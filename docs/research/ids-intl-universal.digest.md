# ids-intl-universal

### Key takeaways
- Universal recognizers with strong validation (IBAN mod 97, Luhn cards with IIN ranges, MRZ 7-3-1, BTC base58check/bech32/bech32m, EIP-55 mixed-case ETH, provider-prefixed secrets, +CC phone numbers via libphonenumber) are safe to run globally in 'auto'. Bare digit strings protected by a single check digit (SIN, TFN, My Number, Aadhaar, IL ID, RNOKPP) pass by chance about 1 time in 10, so they must be gated by locale or context.
- Brazil changed two formats in 2026. CNPJ has been alphanumeric since 31 Jul 2026: positions 1-12 are [0-9A-Z], each character is valued as ASCII minus 48, and the two check digits are still mod 11. The Brazilian IBAN bank code became alphanumeric in IBAN registry release 103 (effective Aug 2026). python-stdnum 2.2 already handles the new CNPJ.
- python-stdnum (v2.2, 4 Jan 2026) covers almost every non-EU ID in scope, but it is LGPL-2.1-or-later. Use it only as an unmodified dependency or as a dev-time test oracle, and reimplement the checksums in our MIT code from public specs. Its bitcoin module also rejects bech32m (Taproot bc1p...) addresses.
- Presidio (MIT) moved to the data-privacy-stack org in 2026. Its recognizers are MIT and can be reused (SSN invalidation, AU Medicare, bech32m). Gaps: CRYPTO covers Bitcoin only, SSN does not reject 9xx, and the phone recognizer runs PhoneNumberMatcher once per region for 8 regions by default (US, GB, DE, FR, IL, IN, CA, BR), which multiplies CPU cost.
- phonenumbers 9.0.41 (8 Oct 2026, Apache-2.0) is pure Python and loads metadata lazily, so call load_all() at startup to avoid latency spikes. PhoneNumberMatcher defaults to leniency VALID with max_tries 65535 and already rejects dates, timestamps and page ranges. Run one pass for numbers written with +CC, then one pass per inferred region only.
- Language-ID licensing: fastText lid.176 is CC-BY-SA-3.0 (caution), NLLB lid218e is CC-BY-NC-4.0 (avoid), OpenLID-v2 is GPL-3.0 (avoid), GlotLID is Apache-2.0 but with unwarranted training-data provenance. The clean defaults are py3langid 0.4.0 (BSD-3, 139 classes including a 'zxx' non-language class) and pycld2 (Apache-2.0, fastest). lingua (Apache-2.0) is the most accurate on short text but ships about 170 MB wheels.
- Secret rules: gitleaks (MIT, about 222 rules, declared feature-complete), its successor Betterleaks (MIT) and Kingfisher (Apache-2.0) can all be ported. TruffleHog is AGPL-3.0 since v3, so avoid it. Many rules have no entropy threshold. The generic api-key rule uses keyword + assignment + entropy >= 3.5.
- In auto mode, language must never decide the country on its own: French points equally to FR, BE, CH, CA, MA, DZ, TN, SN, CI and CM. The strongest signals for an MIT and CPU-only design are: the identifier's own context keywords, the CC of validated IBANs and +CC phones, script detection, and ccTLDs and currencies.
- Excel (the user's question), seen from identifier detection: Excel keeps only 15 significant digits, so a 16-digit card number typed as a number loses its last digit and fails Luhn. Leading zeros (phone numbers, postcodes, Israeli IDs) and dates stored as serial numbers also break text regexes. Spreadsheets therefore need a cell- and column-aware detection path that uses the header as context, rather than flattening to Markdown text first.
- Formats for the Maghreb and francophone Africa (MA CIN, DZ NIN, TN CIN, SN, CI, CM) could not be confirmed from primary sources in this pass (the search budget ran out). None has a known public checksum. Their biometric cards carry an ICAO 9303 MRZ, so MRZ detection combined with context words is the dependable route.

### Recommendations
- Auto mode, tier G0 (always on, every language): e-mail, URL-PII, IBAN (mod 97 + length table), cards (Luhn + IIN + length), MRZ, BTC/ETH-EIP55, provider-prefixed secrets and PEM keys, +CC/00CC phones via phonenumbers with no default region, IPv4/IPv6/MAC with validation. Each needs a checksum or a distinctive structure.
- Auto mode, tier G1 (global but with a score boost or penalty): self-structured national IDs whose false-positive risk stays low without locale: CN RIC (date + MOD 11-2), MX CURP/RFC, IN PAN, formatted BR CPF/CNPJ, formatted US SSN/ITIN with the range rules. Keep VIN, GPS and DOB at a lower score unless context is present.
- Auto mode, tier L (locale-gated): bare digit strings with one check digit or none (CA SIN, AU TFN/Medicare, JP My Number, Aadhaar, IL ID, UA RNOKPP, TR TCKN, US EIN/passport/DL, MA/DZ/TN CIN, national-format phones). Enable them when the country is inferred or the caller names it, or through a context-word unlock (next item).
- Context-word unlock: compile every country pack's context keywords (multilingual, e.g. 'CURP', 'Aadhaar', 'マイナンバー', 'TC Kimlik', 'NAS', 'РНОКПП') into one Aho-Corasick automaton (pyahocorasick, BSD-3). One pass gives both the locale evidence and the windows (±N tokens) where locale-gated recognizers may fire.
- Locale inference score per country = tenant prior + 3×keyword hits + 3×validated IBAN CC + 3×parsed +CC phone region + 2×script (unicodedata: Hebrew→IL, Hiragana/Katakana→JP, Han→CN/JP, Cyrillic→UA, Devanagari→IN, Arabic→Maghreb) + 1×ccTLD + 1×currency (R$, ₹, ₺, ₴, ¥, MAD, DZD, TND, XOF→SN/CI, XAF→CM, C$, A$) + 1×postal pattern (CEP 00000-000, A1A 1A1, 〒) + 0.5×language ID. Activate the top k (e.g. 3) above a threshold, and return the reasons in the response metadata.
- Language ID: run script detection first (stdlib). Then use py3langid restricted to the pack languages with min_confidence (its 'zxx' and 'und' outputs suit tables and code). Skip texts under about 20 characters. pycld2 can serve as a fast pre-filter. Do not bundle fastText lid.176 (CC-BY-SA) in the MIT package; offer it only as an optional download.
- Phones: one PhoneNumberMatcher pass with region=None (finds only +CC/00CC numbers), then one pass per inferred region with leniency VALID. Call PhoneMetadata.load_all() at startup and use phonenumberslite (no geocoder/carrier data). Do not copy Presidio's default of 8 regions.
- Write all checksum validators (Luhn, Verhoeff, ISO 7064 MOD 97-10 and MOD 11-2, 7-3-1, mod-11 variants, bech32/bech32m, base58check, EIP-55) as an in-house MIT module from public specs. Use python-stdnum (LGPL) only as a dev/test oracle in CI, not as a shipped dependency, or document it as an unmodified LGPL dependency.
- Secrets: port the gitleaks/Betterleaks MIT rules (with an attribution NOTICE) to Python re. Keep their keyword prefilter (Aho-Corasick) so that roughly 220 regexes run only when a keyword is present. Treat SECRET as its own non-reversible category: never rehydrate secrets.
- Overlaps (15-digit NIR/IMEI/Amex, 9-digit SSN/SIN/TFN, 12-digit Aadhaar/My Number/cards): resolve by checksum strength, then context, then locale prior. If several validators pass with no context, emit a generic [IDENTIFIANT_n] placeholder. For anonymization recall matters more than the label, but log the ambiguity.
- Excel (the user's question): read cells with types (openpyxl, MIT) rather than flattening to text first. Use header cells as context words. Classify per column: if at least 70-80% of non-empty cells validate as entity X, tag the whole column. Recover lost leading zeros and 15-digit-truncated card numbers heuristically when the header indicates them. Convert serial dates to dates before DOB rules. Run language ID on headers plus text cells only.
- Version the country packs (data + rules) separately from the code, and track format changes: CNPJ alphanumeric (Jul 2026), IBAN registry releases (currently 103), Aadhaar VID, and so on. Build test sets from synthetic valid and invalid numbers, plus a negative corpus (invoices, logs, code, spreadsheets) to measure FP per recognizer before enabling it globally.
- For multi-regex speed on CPU: start with Python re plus keyword or character prefilters. If profiling shows a regex bottleneck, use Vectorscan (BSD-3) through python 'hyperscan' (MIT). Avoid Intel Hyperscan 5.5+, which is proprietary. Guard against catastrophic backtracking with bounded quantifiers.

### Risks
- False-positive explosion in auto mode if single-check-digit recognizers run globally: about 10% of random 9-12 digit strings pass Luhn, Verhoeff or mod 11. Order numbers, invoices and phone numbers get over-redacted, which degrades LLM answers.
- License contamination: python-stdnum (LGPL-2.1+) or pycountry (LGPL-2.1-only) if vendored or modified; fastText lid.176 (CC-BY-SA-3.0) if bundled; lid218e (CC-BY-NC) and OpenLID-v2 (GPL-3.0) are incompatible; TruffleHog (AGPL-3.0); Public Suffix List (MPL-2.0, file-level copyleft; license not re-verified in this pass).
- Formats for the Maghreb and francophone Africa (MA, DZ, TN, SN, CI, CM) are unverified, and none has a known public checksum. Detection there will rely on context and MRZ, with low recall on free text.
- Excel input: 15-significant-digit truncation, lost leading zeros, scientific notation (4.97E+15) and serial dates silently defeat checksum validators, causing false negatives on exactly the data most likely to hold bulk PII.
- phonenumbers is pure Python. Scanning long documents across many regions is CPU-heavy, and lazy metadata loading causes first-call latency spikes.
- Language ID fails on short, tabular, code-mixed or multilingual text, and a shared language (French, Arabic, Spanish, English) does not identify a country. Over-trusting it would turn on the wrong packs.
- Obfuscated-email and handle patterns ('at', 'dot', '@word') produce false positives in English prose and in code (decorators, npm scopes).
- Secret rules written in Go RE2 syntax can behave differently or backtrack catastrophically in Python re. Gitleaks is frozen (security fixes only), and Betterleaks v2 has not shipped a stable release yet.
- Upstream drift: the Presidio repo and docs moved (data-privacy-stack, 2026), and IBAN, CNPJ and Aadhaar formats change. Without versioned packs, detection silently regresses.
- IPv4 regexes match software version numbers, and GPS regexes match decimal pairs in tables. Without context and validation, utility suffers.

### Open questions
- Morocco CIN/CNIE, Algeria NIN, Tunisia CIN, Senegal CNI CEDEAO, Côte d'Ivoire NNI and Cameroon CNI/NIU formats could not be confirmed from primary sources because the shared web-search budget ran out. Check them against EU PRADO and the national sources in a follow-up.
- Does Mexico now issue CURPs with 'X' as the sex marker? python-stdnum accepts only H/M.
- The ICAO Doc 9303 Part 3 (8th ed.) PDF could not be fetched. The 7-3-1 rule is confirmed by secondary sources only.
- What is the exact country count and per-country BBAN table in IBAN Registry release 103 (89 or more)? The table should be built from the SWIFT PDF, keeping SWIFT's terms in mind (extract the facts, do not redistribute the PDF).
- Policy: should legal-entity IDs (EIN, CNPJ, BIC, company RFC) be replaced by default? They are personal data only for sole proprietors.
- Policy for masked forms (last-4 card digits, 'XXXX XXXX 1234' Aadhaar) and for generalizing rather than removing (DOB to year, age to bucket, GPS to 2 decimals)?
- Thresholds and weights for the auto-mode locale score and the column-classification ratio need calibration on a labelled multilingual corpus (including spreadsheets).

### Critical claims
- python-stdnum latest is 2.2 (released 2026-01-04), licensed LGPL-2.1-or-later. It has modules for US SSN/ITIN/EIN, CA SIN, BR CPF/CNPJ, MX CURP/RFC, IN Aadhaar/PAN, CN RIC, JP IN, AU TFN, TR TC Kimlik, IL ID, UA RNTRC, MA ICE, DZ NIF, TN MF, SN NINEA. [https://pypi.org/project/python-stdnum/]
- python-stdnum's bitcoin module validates bech32 only with constant 1, so bech32m (Taproot, witness v1+) addresses fail its checksum. [https://raw.githubusercontent.com/arthurdejong/python-stdnum/master/stdnum/bitcoin.py]
- phonenumbers 9.0.41 was released 2026-10-08 under Apache-2.0. PhoneNumberMatcher defaults to Leniency.VALID and max_tries=65535; the grouping leniencies may give lower coverage outside +1. [https://github.com/daviddrysdale/python-phonenumbers/blob/dev/python/phonenumbers/phonenumbermatcher.py]
- Presidio (MIT) now lives at github.com/data-privacy-stack/presidio. Its CRYPTO entity covers Bitcoin addresses only, and the phone recognizer's default regions are US, GB, DE, FR, IL, IN, CA, BR. [https://presidio.dataprivacystack.org/supported_entities/]
- Brazil's Receita Federal started issuing alphanumeric CNPJs on 31 July 2026 (first: 00.000.000/E08G-12). Existing numeric CNPJs remain valid, and the two check digits stay numeric. [https://agenciagov.ebc.com.br/noticias/202607/receita-federal-gera-o-primeiro-cnpj-em-formato-alfanumerico]
- SWIFT IBAN Registry release 103 changes the Brazilian IBAN so that the bank code becomes alphanumeric (8!c), effective August 2026. [https://github.com/AleksejDix/ibantools/issues/9]
- fastText lid.176.bin (~126MB) and lid.176.ftz (~917kB) cover 176 languages and are distributed under CC-BY-SA 3.0, trained on Wikipedia, Tatoeba and SETimes. [https://fasttext.cc/docs/en/language-identification.html]
- OpenLID-v2 language-ID model weights are licensed GPL-3.0. [https://huggingface.co/laurievb/OpenLID-v2]
- py3langid 0.4.0 (2026-09-02) is BSD-3-Clause, supports 139 classes including a synthetic 'zxx' non-language class, and allows restricting the language set. [https://pypi.org/project/py3langid/]
- lingua-language-detector 2.2.0 (2026-03-09) is Apache-2.0, supports 75 languages, and its wheels are about 170 MB each. [https://pypi.org/project/lingua-language-detector/]
- Gitleaks is MIT-licensed and declared feature-complete (security patches only); the author's focus moved to Betterleaks (MIT). [https://github.com/gitleaks/gitleaks]
- TruffleHog is released under AGPL-3.0 since v3.0. [https://github.com/trufflesecurity/trufflehog]

- Valid ITINs have 4th-5th digits in ranges 50-65, 70-88, 90-92 and 94-99 (first digit 9). [https://www.eitc.irs.gov/pub/irs-pdf/p4757.pdf]
- pycountry 26.2.16 is licensed LGPL-2.1-only. [https://pypi.org/project/pycountry/]

### Verifier notes
- The web search budget for this run was exhausted, so all verification used WebFetch on primary pages. Not reachable: swift.com (403), the ICAO 9303 and IRS PDFs (binary, not parseable), and eCFR (redirect). Claims relying on those were checked against reference implementations instead.
- Key takeaway (Brazil): 'The Brazilian IBAN bank code became alphanumeric in IBAN registry release 103' is UNVERIFIED. The only source is a 0-star rewrite repo (AleksejDix/ibantools, now 'ibanita'). python-stdnum master still embeds iban-registry-v101 with BR 8!n bank code. The recommendation 'IBAN registry releases (currently 103)' should be downgraded until SWIFT's registry PDF is checked by hand. If the change is real, stdnum's IBAN validator, used as a test oracle, would wrongly reject new BR IBANs.
- python-stdnum as a dev/test oracle has known gaps that would produce false test failures or passes: us.itin rejects the IRS 50-65 ITIN range; br.cpf accepts repeated-digit CPFs; mx.rfc skips the check digit by default (about 1.5% of real RFCs have invalid check digits); bitcoin rejects bech32m; iban.dat is registry v101. Treat stdnum as one oracle among several, not ground truth.
- Cards: 'Luhn + IIN + length' will miss part of UnionPay. braintree/card-validator skips Luhn for UnionPay by default, and UnionPay also uses 81xx prefixes and 14-19 digit lengths. For anonymization recall, accept 62/81 PANs with context even when Luhn fails. Maestro and the Brazilian networks (Elo, Hipercard) are missing from the IIN table.
- py3langid class count is inconsistent across sources: the PyPI 0.4.0 README says 139 languages + zxx (140 classes), the GitHub master README says 138 + zxx. Neither states the license or provenance of the retrained model's training corpus. Check TRAINING.md before calling it the 'clean default', because data provenance is exactly the concern raised against GlotLID.
- GlotLID's exact license tag is 'apache-2.0-plus-notices'. Its LICENSE adds notices that the training data may include copyrighted material and that 'no representation or warranty is made regarding the licensing status of the underlying training data'. GlotLID V3 has 2102 labels.
- fast-langdetect 1.1.0 (MIT, 2026-10-17) bundles lid.176.ftz in its package, so adding it as a dependency distributes CC-BY-SA-3.0 weights transitively. The recommendation to make fastText an optional download only holds if fast-langdetect is also optional.
- pycld2 0.42 (2025-03-28) has wheels only up to CPython 3.13. On Python 3.14 it needs a C++ toolchain, which is a packaging risk for an MCP server. CLD2 itself is unmaintained upstream.
- Secrets: Betterleaks is now v2 and moves logic into Expr (filter, validate, analyze), so porting is no longer regex-only. Kingfisher (Apache-2.0, Rust) now uses Betterleaks as its main rule source plus Google 'Veles' detectors, so porting it adds little beyond Betterleaks, and its Apache-2.0 NOTICE terms would apply. gitleaks currently has about 222 [[rules]].
- MRZ: for an FR-first tool, note that the pre-2021 French CNI (still widely in circulation) uses a non-ICAO 2x36 MRZ layout with French-specific fields and check digits. A generic TD1/TD2/TD3 parser will mis-parse it. The 2021+ CNIe uses TD1.
- EXCEL (the user's actual question), points missing from the takeaways: (1) Format coverage: openpyxl reads only .xlsx/.xlsm. Legacy .xls needs xlrd 2.0.2 (BSD), which reads .xls only. .xlsb via pyxlsb is LGPLv3+ (avoid). python-calamine 0.9.0 (MIT, Rust) reads xls/xlsx/xlsb/ods fast, is a good read path, and pandas supports engine='calamine'. openpyxl's last release was 3.1.5 in June 2024.
- EXCEL (2): personal data lives outside cell values, and the takeaways omit it. Cell comments and threaded comments (with author names in persons.xml), docProps creator/lastModifiedBy, headers and footers, sheet and table names, defined names, hyperlinks (mailto:), external-link paths (C:\Users\<name>\...), hidden sheets, rows and columns, formulas containing literal PII (and their cached values), and pivot caches. Pivot cache records keep a full copy of the source data even when the source sheet is anonymized. Embedded images and objects need handling too. A GDPR anonymizer must scan and rewrite or strip all of these, or refuse the file.
- EXCEL (3): round-tripping with openpyxl drops unsupported parts (shapes, some charts and images; VBA unless keep_vba=True). Decide whether the output should be a rewritten .xlsx (format-preserving but lossy) or a clean export (CSV or a new xlsx). Untrusted workbooks are zip and XML: install defusedxml (openpyxl uses it when present) and cap the uncompressed size to guard against zip and XML bombs. Always save through a full rewrite, which regenerates sharedStrings, rather than patching XML in place, which can leave original strings behind in sharedStrings.xml.
- EXCEL (4): 'recover 15-digit-truncated card numbers heuristically' can be made exact for 16-digit PANs: only the last (Luhn check) digit is zeroed, so it can be recomputed from the first 15 digits. 17-19 digit PANs are not recoverable. For anonymization, recovery is unnecessary anyway: mask the cell. French specifics matter here: mobile numbers typed as numbers lose their leading 0 (0612345678 becomes 612345678, 9 digits). A 15-digit NIR fits exactly in Excel's precision, but Corsican 2A/2B NIRs are stored as text. openpyxl already converts date-formatted serials to datetime, so only unformatted serials need conversion.
- pycountry is LGPL-2.1-only, not 'or later'. If it is used for country tables, it carries the same constraints as stdnum. Babel/CLDR (BSD-3 + Unicode License v3) is the cleaner source for territory and currency data.
