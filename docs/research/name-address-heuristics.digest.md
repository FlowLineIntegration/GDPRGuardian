# name-address-heuristics

### Key takeaways
- Scope note: the relayed user request is about Excel (handle it or not, and how). This research covers only rule-based detection of names, addresses, organisations and special categories. Where it bears on Excel, see the takeaway and recommendation marked Excel.
- Name detection without ML is realistic in FR if built in two tiers. Unambiguous names (in the INSEE prénoms/noms lists but not common words) are masked on capitalisation alone. Ambiguous names (Pierre, Rose, Blanc, Martin, Marine, France, Florence, Nancy, Avril, Petit, Fontaine, Boulanger...) need a trigger: an honorific, a greeting, a signature block, an email local part, an adjacent name token, or propagation from a confirmed mention.
- France has the best open gazetteers. Both are Licence Ouverte 2.0 (insee.fr default) and fine under MIT with attribution. INSEE Fichier des prénoms covers 1900-2025 (published 16/07/2026, counts rounded to 5, by sex). INSEE Fichier des noms has 218,982 surnames born 1891-2000 with at least 30 bearers (2018 edition, stale for recent immigrant surnames).
- Other countries are patchy. US SSA names are CC0. Italy (ISTAT) is CC BY 4.0, but only top lists and a calculator exist, no full bulk list. Spain (INE) publishes top-N tables under CC BY 4.0, though its site footer says BY-SA. Germany has no national list, only city files (Bonn CC0, Berlin CC BY 3.0 DE). Wikidata (CC0, Lexemes included) is the realistic multi-country backbone.
- Address gazetteers: BAN has been Licence Ouverte 2.0 since 01/01/2020. INSEE COG 2026 and the La Poste Base officielle des codes postaux are also Licence Ouverte 2.0. GeoNames is CC BY 4.0, and its countryInfo.txt gives a postal-code regex per country. OSM and BANO are ODbL (share-alike on derivative databases), so avoid them for any bundled gazetteer.
- libpostal is the wrong tool. It parses a string already known to be an address; it does not find addresses in free text. Its model is about 1.8 GB (Senzing variant about 2.2 GB) and is trained on OSM and OpenAddresses, so the weights' provenance is ODbL-ambiguous. The C code is MIT and maintained (1.1.4, Oct 2025; Senzing data 1.2.0, Dec 2025). deepparse is LGPL-3.0. For detection, use an anchor-based regex plus gazetteer validation instead.
- French addresses can be found reliably by anchoring on a postal code followed by a commune name, then checking that pair against La Poste/COG. Then extend leftwards to: house number, optional bis/ter/quater or letter, a street-type word (rue, av., bd, chemin, impasse, allée, quai, lieu-dit...) and the street name. Also catch BP/CS/TSA and CEDEX. Patterns elsewhere: DE has the street-suffix compound (-straße/-str./-weg/-platz) + PLZ(5); ES uses C/, Avda. + CP(5); IT uses Via + CAP(5) + (XX) province code; NL uses \d{4} ?[A-Z]{2}.
- Precedent in French court decisions: the Cour de cassation runs a Flair BiLSTM-CRF model followed by 8 deterministic post-rules. Those rules propagate a name to all its occurrences once it is detected more than twice, use regex for standardised numbers, and flag surnames of 1-2 letters and near-duplicate first names for human review. Its tool LABEL (MIT) links annotations so case variants get the same replacement. Etalab/Conseil d'État replaced names with X/Y/Z and first names with A/B/C.
- Coreference of name variants can be done deterministically. Key each person cluster on the normalised surname (casefold, no accents, hyphen-aware). Merge mentions whose first names are compatible: the same name, a matching initial, or none given. Gender from the honorific (M./Mme, Herr/Frau, Sr./Sra.) is checked against the INSEE first-name sex ratio. When two people share a surname, a surname-only mention stays ambiguous and should go to a surname-level placeholder or be decided by the honorific's gender.
- Special categories (GDPR Art. 9/10): the CJEU reads them broadly by inference. C-184/20 held that data indirectly revealing sexual orientation counts; C-21/23 held that orders of pharmacy-only medicines are health data even without a prescription. Lexicons can only flag explicit mentions (medicines, diseases, religions, parties, unions, criminal-law terms). Treat this as risk flagging or sentence-level masking, never as a completeness guarantee.
- Health vocabularies come with licensing traps. BDPM is ok: Licence Ouverte, but data must not be altered and the source and update date must be cited. WHO ICD-10/11 and the ATIH CIM-10 FR are CC BY-ND 3.0 IGO (no adaptations), so do not bundle extracted label lists. The Inserm French MeSH is CC BY-NC 4.0, so avoid it. The German MeSH is CC BY 4.0 (ok). English MeSH is under NLM terms (free with attribution). Wikidata disease labels (CC0) are the safe alternative.
- Matching engine: pyahocorasick 2.3.1 (BSD-3 + public domain, Python >=3.10) or ahocorasick_rs 1.0.3 (Apache-2.0, 1.5-7x faster per its author, releases the GIL for str) can handle hundreds of thousands of name patterns. Word boundaries and accent/case folding must be handled with offset-preserving normalisation. For large regex sets, Vectorscan (BSD-3) through python-hyperscan (MIT, manylinux wheels only) is fast. Intel Hyperscan from 5.5 is proprietary, so avoid it.
- Excel: per-cell detection fails because cells have no surrounding context. Column-level classification is the strong rule-based approach. Combine a header lexicon (nom, prénom, adresse, CP, ville, NIR, IBAN, date de naissance...) with the share of a column's cells that hit a validator or gazetteer. Above a threshold, mask the whole column, giving equal values the same placeholder across the workbook. Hidden sheets, comments and document properties also hold PII.

### Recommendations
- Country-pack gazetteers. FR: INSEE prénoms (with sex ratio) + INSEE noms + optional frequencies derived from the décès file. EN: SSA. IT/ES/DE: Wikidata names (CC0) + ISTAT/INE/city lists. Compile each pack offline into an Aho-Corasick automaton carrying per-entry frequency, sex and an ambiguity flag. Record every attribution (Insee, GeoNames, BDPM, ISTAT) in a NOTICE file.
- Mark a name as ambiguous when it is also a common word (Wikidata Lexemes, CC0), a commune (COG) or a GeoNames place. Ambiguous names (Pierre, Rose, Blanc, Martin, Marine, France, Nancy, Avril) are masked only with a trigger or by propagation. Unambiguous names are masked when capitalised and not sentence-initial, or anywhere in ALL CAPS next to another name token.
- Triggers per language. FR: M., MM., Mme, Mlle, Me, Dr, Pr, Mgr, Monsieur/Madame/Maître, née/épouse/veuve. DE: Herr, Frau, Dr., Prof., geb. ES: Sr., Sra., D./Dña., Dr./Dra. IT: Sig./Sig.ra, Dott./Dott.ssa, Avv. EN: Mr, Mrs, Ms, Dr. Greetings: Bonjour/Cher/Chère X, Liebe/Sehr geehrte X, Hola/Estimado X, Gentile/Ciao X, Dear/Hi X. Treat the 1-3 lines after a closing formula (Cordialement, Mit freundlichen Grüßen, Saludos, Cordiali saluti, Best regards) as a name zone.
- Derive names from email addresses and display names. Split local parts on [._-] (prenom.nom, p.nom, nom.prenom, prenom_nom), check the pieces against the gazetteers, and feed confirmed names into document-level propagation. Always mask the whole address.
- Propagation and coreference. After span detection, build person clusters keyed on the normalised surname; first names must be compatible (same, initial, or absent) and the honorific's gender consistent. Each cluster gets one placeholder [PERSONNE_n]. Propagate a cluster's name forms to every capitalised occurrence in the document or session. For ambiguous common-word forms, propagate only in capitalised, non-sentence-initial position. Like the Cour de cassation, raise the review/confidence flag for 1-2 letter surnames.
- FR address detector. Anchor: postal code ((0[1-9]|[1-8]\d|9[0-8])\d{3}) followed by a commune, with the pair validated against La Poste/COG. Optional CEDEX n. Extend left: number \d{1,4}, optional bis/ter/quater/quinquies or [A-Z], then a street-type word from a lexicon derived from BAN (rue, av., bd, pl., chemin, imp., allée, quai, cours, rte, sq., fg, lieu-dit, résidence, lotissement, ZA/ZI). Also catch BP/CS/TSA \d+. Without an anchor, match number + street-type + capitalised name. For other countries use GeoNames postal regexes plus street-type/suffix lexicons.
- Organisation detector. A capitalised token sequence followed or preceded by a legal form (SA, SAS, SASU, SARL, EURL, SCI, SNC, GmbH, AG, KG, UG, S.L., S.A., S.p.A., S.r.l., B.V., N.V., Ltd, LLC, plc), or introduced by société/entreprise/association/cabinet. Boost when a SIREN/SIRET is within N tokens. GLEIF names (CC0) are an optional extra. If an organisation name contains a detected surname, mask it as personal data (the Cour de cassation 'physicomorale' rule).
- Special categories: present them as a risk flag with optional sentence-level masking, not a guarantee. Lexicons: BDPM medicines, Wikidata diseases/religions/parties/unions (CC0), FR unions (CGT, CFDT, FO, CFE-CGC, CFTC, UNSA, Solidaires), Art. 10 terms (condamné, casier judiciaire, garde à vue, mis en examen, 'article \d+-\d+ du code pénal'). Raise severity only when a person mention occurs in the same sentence. Evaluate GLiNER zero-shot labels on a FR test set before enabling them.
- Matching engine: casefold and strip accents with an offset map so spans map back to the original text exactly, then run the Aho-Corasick match and filter by word boundaries. Use ahocorasick_rs (threads, GIL released) or pyahocorasick with automata pickled per pack. For hundreds of regexes on Linux, use Vectorscan via python-hyperscan; never Intel Hyperscan >=5.5.
- Excel (for the user's question). Rule-based detection for spreadsheets should run per column, not per cell. Score each column by header lexicon plus the share of its cells that hit validators or gazetteers, and mask the whole column above a threshold. Equal cell values get equal placeholders across sheets. Before converting to Markdown, also extract or strip hidden sheets, comments, named ranges and docProps author fields.
- Do not bundle: OSM/BANO extracts, Inserm MeSH FR, extracted ICD/CIM-10 label lists, Lexique, name-dataset (Facebook leak), Intel Hyperscan. Keep libpostal and deepparse out of the default path.

### Risks
- False positives from first names that are also common words (Pierre, Rose, Blanc, Martin, Marine, Prudence, Constance, Clément), places (France, Florence, Nancy, Lourdes, Valence) or months (Avril). Title Case in Markdown headings and table cells (Excel) is a further false-positive trap.
- Over-propagation: masking every 'pierre' or 'blanc' after one confirmed name damages the text. Propagation must stay case- and position-sensitive.
- Surname-only mentions ('M. Martin') when two people share a surname: merging them wrongly links two data subjects under one placeholder.
- Low recall on foreign and recent-immigrant names. The INSEE noms file stops at births in 2000 and keeps only names with 30+ bearers; ES/IT/DE lack official bulk lists.
- Special-category detection by lexicon misses inferred data. The CJEU treats indirect revelation (C-184/20) and OTC medicine orders (C-21/23) as Art. 9 data, so 'sensitive data masked' claims must not be marketed.
- Licence traps: ODbL (OSM/BANO, possibly libpostal weights), CC BY-ND (ICD), CC BY-NC (Inserm MeSH, possibly Lexique), the INE BY vs BY-SA inconsistency, and Licence Ouverte attribution plus BDPM no-alteration duties.
- Bundling raw décès or SIRENE records would redistribute personal data and ignore opposition and diffusion-status obligations. Ship only aggregated frequency lists.
- Aho-Corasick over hundreds of thousands of patterns: memory per worker, and offset drift when normalisation changes string length (e.g. ß -> ss under casefold).
- Organisation names that embed a person's surname (individual entrepreneurs, 'Cabinet Dupont') leak identity if organisations are left unmasked.

### Open questions
- The web search budget ran out partway through, so several points were checked only by direct page fetches or remain unchecked: the Grammalecte French dictionary licence, Wikidata name item counts, the Berlin Vornamen current licence, and the Conseil d'État's current pseudonymisation tool.
- INE Spain: its legal notice says CC BY 4.0 but the site footer says CC BY-SA 4.0. Which applies to the nombres/apellidos files?
- Does bundling a list of disease labels extracted from ICD-10/11 count as an 'adaptation' under CC BY-ND 3.0 IGO? Ask WHO (licensing@who.int) or rely on Wikidata only.
- HeTOP lists the 2025 French MeSH as public domain, unlike Inserm's CC BY-NC. Who owns the DéSaN translations, and under what terms?
- Are libpostal's trained weights an ODbL derivative database or a produced work? No OSMF statement was found.
- GLiNER accuracy on FR special-category labels (religion, political opinion, union membership, sexual orientation) is unmeasured, and the provenance of its Mistral-generated synthetic training data needs checking.
- Excel: should GDPR Guardian mask spreadsheets column by column natively (keeping the sheet structure), or flatten them to Markdown tables, given that a whole-column decision needs the table structure?
- The Etalab pseudonymisation guide (guides.etalab.gouv.fr) did not resolve during research, and the licence of the pseudonymisation_decisions_ce repo remains unconfirmed.

A normalised, lower-cased medicine lexicon derived from BDPM should be documented as an extraction that does not alter meaning, with the BDPM update date stored in NOTICE and a refresh process.

- Cour de cassation precision: moteurNER's README announces 8 post-processing methods but describes only 5. F1 0.9744 is for personnephysiquenom; micro-average F1 is 0.9408. The repository shows no licence, so cite its rules as prior art but do not copy code. LABEL is MIT.
- Legal precision for the special-categories takeaway: the C-21/23 operative part names the customer's 'name, the delivery address and the details required for individualising the medicinal products' as health data. In that context, the identity and address fields are Art. 9 data in themselves, not only the medicine name. This supports document-level or context-level risk flags (e.g. a pharmacy order spreadsheet), not just sentence-level lexicon hits.
- OMISSION (legal framing): placeholder replacement ([PERSONNE_n]) is pseudonymisation, not anonymisation, under GDPR recital 26. The output stays personal data for whoever holds the mapping. The EDPB Guidelines 01/2025 on pseudonymisation and the CJEU judgment C-413/23 P EDPS v SRB (2025, on whether pseudonymised data is personal data from the recipient's perspective) should be cited before calling the tool 'anonymization'. Their dates and holdings were not verified in this pass.
- OMISSION (Excel, relevant to the user's actual question): the column-level approach is sound, but the takeaway misses Excel-specific traps. (1) Typed cells: postal codes such as 01000 are often stored as the number 1000, which breaks the FR postal regex. Phone numbers lose leading zeros. Dates of birth are serial numbers whose meaning depends on the number format. NIR/IBAN-like numbers longer than 15 digits lose precision as doubles. Detection must read cell type and number format, not only the displayed text. (2) Pivot caches (pivotCacheRecords) keep full copies of source rows even after the source sheet is deleted. Add them to hidden sheets, comments, named ranges and docProps, as well as: threaded comments and notes, headers/footers, very-hidden sheets, hidden rows/columns, data-validation lists, external links, chart caches, customXml, and sharedStrings, which can retain strings no longer shown. (3) Formulas that reference masked cells, or that embed literals, must be rewritten or replaced by values. (4) The recommendation to mask a whole column above a threshold should also mask the matching header-identified columns on other sheets joined by the same key.
- Minor: ISTAT note-legali text says CC BY 4.0, but the badge links to CC BY 3.0 IT. Cite 4.0. ISTAT Contanomi covers births from 1999 only. The GeoNames GB_full attribution must reproduce 'Contains Royal Mail data © Royal Mail copyright and database right 2022' (plus OS) in NOTICE. The La Poste base also covers Monaco (98000) and the COM, which the 9[0-8] regex branch correctly admits. Whether it lists CEDEX codes is not stated, so validating 'CP + CEDEX' pairs against it may fail.
