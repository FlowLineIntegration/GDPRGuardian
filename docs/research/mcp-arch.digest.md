# mcp-arch

### Key takeaways
- Core finding: an MCP tool that takes raw text as an argument cannot protect data from the LLM provider. The model writes the tool arguments, so it has already read the personal data. Also, claude.ai custom connectors call remote MCP servers from Anthropic's cloud, so even tool traffic passes through the provider. MCP only protects data when the raw content reaches the server by a route the model never sees: a local file path, a URI or connector, or an out-of-band upload.
- Only interception before the provider covers all LLM traffic: (1) a REST API/SDK called by the application, (2) an OpenAI/Anthropic-compatible LLM proxy that anonymizes requests, including tool results and tool-call arguments, and rehydrates responses, and (3) client hooks. Claude Code can be routed through a proxy with ANTHROPIC_BASE_URL. Its UserPromptSubmit hook can only block a prompt, not rewrite it. PostToolUse.updatedToolOutput and PreToolUse.updatedInput can redact tool results and rehydrate tool inputs.
- The MCP spec is now 2026-07-28. It removes protocol sessions, Mcp-Session-Id and the initialize handshake, and deprecates Roots, Sampling, Logging and Dynamic Client Registration (replaced by CIMD). Tasks moved to the io.modelcontextprotocol/tasks extension. State must use server-minted handles passed as tool arguments, so the placeholder vault becomes an opaque handle bound to the authenticated user ('<sub>:<handle>'), never treated as authentication.
- FastMCP 4.1.3 (Apache-2.0, released 2026-10-20) fits our needs: it speaks the 2026-07-28 protocol and negotiates legacy versions, and provides UserSession/SessionId state isolated per user, background tasks (fastmcp-tasks, Docket/Redis), Progress, elicitation through InputRequiredResult, middleware that can rewrite tool arguments and results, ProxyProvider gateways, many OAuth/OIDC providers (Keycloak included), and MCP Apps (FastMCPApp, app-only backend tools).
- Ways to keep the re-identification mapping away from the model: a server-side vault (AES-GCM with an ephemeral per-session key and the handle as associated data, TTL, crypto-shredding). Rehydration happens only in the application, the proxy, or an MCP App View that fetches directly from the EU server (connectDomains). Caveats: MCP Apps says structuredContent is 'not added to model context', but that is UI-extension guidance only; FastMCP warns that 'App tool visibility is not a security boundary'.
- Prompt-injection rule: never expose a model-callable deanonymize/rehydrate tool. A document returned by our tool could tell the agent to rehydrate the data and send it out. Returned Markdown should also be cleaned of invisible Unicode, bidi and tag characters and of remote image/link exfiltration channels, and wrapped as untrusted data. The MCP spec says servers MUST sanitize tool outputs, and OWASP LLM01/LLM02 and MCP10 apply.
- The pattern is already proven by open-source projects (PII-Shield: file path in, path plus session id out; pii-redaction-gateway: AES-GCM vault and buffering of placeholders split across stream chunks; PrivAiTe: JSON-aware scrubbing of tool-call arguments; Kiji by Dataiku). None focuses on EU country packs or a hosted EU service, which is GDPR Guardian's niche. PrivAiTe still measured 2 of 24 planted values leaking, so recall stays the limit.
- Excel (the user's question): yes, handle it, but through a dedicated tabular pipeline and by reference only (path, upload or URI; a binary file cannot travel as an LLM argument). Classify each column from its header, a sample of values and validators; run NER only on free-text columns; return Markdown tables one sheet at a time, with pages through a handle. Explicitly decide what to do with hidden sheets, comments, pivot caches and metadata, and with quasi-identifiers (dates of birth, postcodes).

### Recommendations
- Layer 0, gdprguardian-core: a pure Python library with no network access. It handles conversion to Markdown, detection (country packs), the replacement plan and placeholders, a Vault interface (in-memory by default; Valkey optional with AES-256-GCM, an ephemeral per-session key, the handle as associated data, TTL and crypto-shredding), and a separate tabular pipeline for xlsx/csv. Every other surface is a thin adapter over this library.
- Layer 1, REST API/SDK, the primary surface for companies. POST /v1/anonymize takes text or a file (multipart) and returns {markdown, handle, stats}. POST /v1/rehydrate is callable only by the caller's backend with a scoped token, never by an LLM. Hosted in the EU and also self-hostable with Docker. Pros: no LLM in the loop, simplest compliance story. Cons: requires application integration.
- Layer 2, an LLM proxy compatible with OpenAI Chat/Responses and Anthropic Messages. It anonymizes messages, tool results and tool-call arguments; rehydrates responses with streaming-safe buffering of split placeholders; and rehydrates tool-call arguments so local tools receive real values. Before detection, a pass replaces values already in the vault so placeholders stay consistent across turns; deterministic output keeps provider prompt caching working. Also ship adapters as a LiteLLM Generic Guardrail endpoint and a Docker MCP Gateway after:http interceptor. Pros: covers all traffic, including Claude Code through ANTHROPIC_BASE_URL. Cons: must track provider APIs; system prompts and CLAUDE.md need explicit scrubbing.
- Layer 3, an MCP server on FastMCP 4, in two modes. (i) Local stdio (uvx gdprguardian-mcp): tools take file paths limited to directories allowlisted in server config (Roots is deprecated) and return anonymized Markdown plus an opaque handle. (ii) Hosted streamable HTTP with OAuth 2.1 (Keycloak or another EU IdP, audience validation, CIMD): tools take a document_ref from an upload, an https URL behind an SSRF guard, or a connector, never raw text. If an anonymize_text tool exists, its description must say the model has already seen the input.
- For hosted MCP intake, use out-of-band upload: URL-mode elicitation pointing to an EU upload page (the spec says data other than the URL is not exposed to the client), or an MCP App View with connectDomains set to the EU API and a direct browser-to-server fetch. Use background tasks for large files and Progress for feedback.
- Rehydration for the end user without involving the model: do not expose a model-callable deanonymize tool. Use (a) the proxy or the application backend; (b) an MCP App View that receives only placeholder text and fetches originals directly from the EU server with a short-lived, single-use, user-bound token, never through a host-proxied tool when the host is a cloud provider; or (c) local stdio, writing the restored file to disk and returning only its path, as PII-Shield does.
- Gateway mode: a FastMCP ProxyProvider in front of the company's other MCP servers, with on_call_tool middleware that anonymizes their results. Test first that server middleware applies to proxied tools, because the proxy docs say results pass through untouched. Track SEP-2624 interceptors and offer GDPR Guardian as a PII mutator.
- Client integration: a Claude Code plugin with PostToolUse redacting Read, Bash, WebFetch and MCP outputs through updatedToolOutput; PreToolUse rehydrating Write and Edit arguments; and UserPromptSubmit blocking prompts that contain detected PII and telling the user to pass a file reference instead. Document that telemetry and transcripts still hold originals locally.
- Vault security rules: handle of at least 128 random bits, stored as '<oauth sub>:<handle>'; reject handles presented by another principal; FastMCP UserSession/SessionId with authentication always on for the hosted service; short TTL stated in the tool description; end_session deletes immediately; logs contain counts only; never put the mapping in content, structuredContent or _meta.
- Prompt-injection hygiene for returned documents: remove zero-width, bidi and Unicode tag characters; neutralize Markdown images and links to external hosts (exfiltration channel) and HTML comments; wrap output in clear untrusted-content delimiters with provenance; optionally flag instruction-like patterns with regex; keep document text out of tool descriptions; enforce size limits.
- Excel decision: support .xlsx/.xlsm/.ods/.csv in v1.x, by reference only. Read cell values with calamine (never execute macros) and use openpyxl plus defusedxml for comments, hidden-state and metadata checks. Classify columns from the header, a sample of values and checksum validators, applying the column label to every cell; run NER only on free-text columns, in batches. Output one Markdown table per sheet, with a row cap and handle-based paging, plus a report of dropped items (hidden sheets, comments, pivot caches, external links, document properties). Offer generalization of quasi-identifiers (birth year only, département) as an option. Anonymized .xlsx output can wait for a later version.
- Build order: core, then REST, then local stdio MCP (file paths), then the LLM proxy, then hosted MCP with OAuth plus upload elicitation, then MCP App rehydration and gateway/interceptor adapters. Track client support of the 2026-07-28 spec; FastMCP negotiates legacy 2025-11-25 per connection.

### Risks
- False sense of security: an anonymize_text MCP tool, or any remote connector used from claude.ai or ChatGPT, means the provider has already received the raw PII. This must be documented prominently or the product can mislead users about GDPR compliance.
- Hosted MCP behind cloud LLM hosts: app-only tool calls and results transit the host provider's infrastructure even when kept out of the model context. Only direct browser-to-EU-server fetches (connectDomains) or a local stdio deployment avoid that.
- Host behaviour varies: MCP Apps visibility and the structuredContent exclusion are extension guidance that some hosts may ignore, and FastMCP states that app visibility is not a security boundary.
- Spec churn: 2026-07-28 removed sessions, the handshake and SSE resumability, and moved Tasks into an extension. Client support lags, so expect dual support for legacy and new protocol versions for 12 months or more.
- Placeholder fragility: LLMs may translate, reformat or merge placeholders (for example [PERSONNE_1] becoming 'Personne 1'), and streaming can split them across chunks. Rehydration then fails silently unless buffering and fuzzy matching are used.
- Recall limits: every open-source proxy reports residual leaks (PrivAiTe 2 of 24 on a large session). Missed entities reach the provider; there is no guarantee.
- Prompt injection through returned documents: an exposed rehydrate tool, or remote images and links in the Markdown output, could be used to exfiltrate the mapping or the data.
- Vault as a high-value target: handle hijacking, plaintext task snapshots in Redis (encryption off by default in fastmcp-tasks), and backup copies would all defeat 'ephemeral'.
- Supply chain: LiteLLM was compromised on PyPI on 2026-03-24, and FastMCP pulls in many auth and HTTP dependencies (4.1.3 was itself a CA/certifi incident response). Pin with hashes and maintain an SBOM.
- Licensing: Redis 8 is RSAL/SSPL/AGPL; do not bundle it. Kiji's model weights and the OpenAI Privacy Filter training data have unverified provenance.
- Excel-specific: hidden sheets, rows and columns; comments; pivot caches (which duplicate source data); defined names; headers and footers; document properties; formulas containing literal PII; sheet names; billion-laughs and zip-bomb files; token blow-up from large sheets; re-identification from quasi-identifiers in structured records that placeholders do not cover.
- GDPR: placeholder-pseudonymized data remains personal data for whoever holds the mapping (GDPR Art. 4(5) and Recital 26, https://eur-lex.europa.eu/eli/reg/2016/679/oj). Whether it is personal data for the LLM provider depends on the provider's means of re-identification. That legal analysis was not verified in this run.

### Open questions
- Does FastMCP server middleware (on_call_tool) apply to tools served by ProxyProvider, so that it can rewrite their results? The proxy docs say results pass through untouched. This needs a quick test before choosing gateway mode.
- Which hosts (Claude Desktop and web, ChatGPT, VS Code) actually honour MCP Apps visibility and keep structuredContent out of model context? Do they allow file input and authenticated fetches to connectDomains from the sandboxed iframe, given third-party cookie blocking? See the client matrix at https://modelcontextprotocol.io/extensions/client-matrix.md
- How should a View or browser channel authenticate to the EU vault without passing a bearer capability through the host (the spec discourages pre-authenticated URLs)? Options: OAuth popup, short-lived single-use token, or a user re-login page.
- Excel output: Markdown only (constraint 5), or also an anonymized .xlsx or CSV? What row and cell caps per tool call? Are quasi-identifier generalization (k-anonymity style) and hidden-sheet policy in scope for v1?
- Should the hosted MCP server accept an anonymize_text tool at all, given the model has already seen the input? Possibly only for agent-generated or already-shared text, with an explicit warning.
- When will SEP-2624 (interceptors) be accepted, and will Python SDK support arrive? Is OWASP MCP Top 10's planned October 2026 release out yet (the project page still showed beta v0.1)?
- Legal: whether placeholder output sent to an LLM provider is personal data from the provider's perspective (CJEU C-413/23 P EDPS v SRB; EDPB Guidelines 01/2025 on pseudonymisation). The curia and EUR-Lex fetches failed in this run and need a legal-scope check.
- Research gap: the web search budget ran out, so Envoy/Kong AI gateway PII plugins, the Lasso gateway's latest commit dates, and xls/xlsb support in python-calamine were not verified.

### Critical claims
- The latest MCP specification revision is 2026-07-28. It removes protocol-level sessions (the Mcp-Session-Id header) and the initialize handshake. Servers needing cross-call state must use explicit server-minted handles passed as ordinary tool arguments. [https://modelcontextprotocol.io/specification/2026-07-28/changelog]
- MCP 2026-07-28 deprecates Roots, Sampling and Logging (SEP-2577) and Dynamic Client Registration in favour of Client ID Metadata Documents. It also moves Tasks into the io.modelcontextprotocol/tasks extension (SEP-2663), with polling through tasks/get. [https://modelcontextprotocol.io/specification/2026-07-28/changelog]
- FastMCP latest is 4.1.3 (2026-10-20), license Apache-2.0. FastMCP 4.0.0 (2026-08-31) supports the 2026-07-28 protocol and legacy clients through per-connection negotiation, and removed server-initiated sampling and roots. [https://gofastmcp.com/updates]
- MCP security best practices: servers MUST NOT treat possession of a state handle as authentication. They SHOULD bind handles server-side to the authenticated user (for example '<user_id>:<handle>'). MCP servers MUST NOT accept tokens not explicitly issued for them (no token passthrough). [https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices]
- URL-mode elicitation directs users to an external URL for out-of-band interactions; data other than the URL is not exposed to the MCP client, so the information never passes through the LLM context. [https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation]
- MCP Apps: the host MUST NOT include tools in the agent's tool list when their visibility lacks 'model'. structuredContent is described as 'not added to model context'. If ui.csp is omitted the default CSP sets connect-src 'none', and external fetches require declared connectDomains. [https://raw.githubusercontent.com/modelcontextprotocol/ext-apps/main/specification/2026-01-26/apps.mdx]
- FastMCPApp backend tools declare visibility=['app'], but the FastMCP docs warn that 'App tool visibility is not a security boundary': clients that know the names can call them directly. [https://gofastmcp.com/apps/fastmcp-app.md]
- FastMCP 4 session state is keyed to the authenticated user (UserSession, SessionId). Without authentication, 'whoever holds the id can read and write it'. [https://gofastmcp.com/servers/sessions.md]
- Claude Code's UserPromptSubmit hook cannot replace the prompt; it can only block it or add context. PostToolUse.updatedToolOutput replaces a tool's output before it is sent to Claude, and PreToolUse.updatedInput replaces tool arguments. [https://code.claude.com/docs/en/hooks]
- Claude custom connectors connect to remote MCP servers from Anthropic's cloud infrastructure, not from the user's device. [https://support.claude.com/en/articles/11175166-about-custom-connectors-using-remote-mcp]
- Docker MCP Gateway supports before and after interceptors of type exec, docker or http that receive tool call requests and responses as JSON and can return a custom response. [https://github.com/docker/mcp-gateway/tree/main/examples/interceptors]
- LiteLLM's Generic Guardrail API (beta) sends texts and tool_calls to a custom endpoint, which can return GUARDRAIL_INTERVENED with modified texts. [https://docs.litellm.ai/docs/adding_provider/generic_guardrail_api]
- Malicious LiteLLM versions 1.82.7 and 1.82.8 were published to PyPI on 2026-03-24 (TeamPCP) and later yanked. [https://bleepingcomputer.com/news/security/popular-litellm-pypi-package-compromised-in-teampcp-supply-chain-attack]
- Starting with Redis 8, Redis is tri-licensed RSALv2 / SSPLv1 / AGPLv3, while Valkey is BSD-3-Clause. [https://raw.githubusercontent.com/redis/redis/unstable/LICENSE.txt]
- openpyxl by default does not guard against quadratic blowup or billion-laughs XML attacks; the docs say to install defusedxml. [https://openpyxl.readthedocs.io/en/stable/]

### Verifier notes
- Tool limits: the web-search budget was used up at the start, so everything was checked by fetching primary sources directly. Not verified: PII-Shield, pii-redaction-gateway, PrivAiTe, Kiji/Dataiku and their '2 of 24 leaked' figure, and the CJEU case text (curia and EUR-Lex returned empty pages).
- LEGAL OMISSION (high): with a vault and rehydration, GDPR Guardian does pseudonymisation (GDPR Art. 4(5), Recital 26), not anonymisation. For the customer and for GDPR Guardian as key holder, the output remains personal data. The recommendations should say this and cite the EDPB Guidelines 01/2025 on pseudonymisation (v1 consultation Jan-Mar 2025; adoption of a final version not confirmed in this session). Also cite CJEU C-413/23 P EDPS v SRB (from memory, not verified here: judgment of 4 Sept 2025, relative approach). It bears on whether placeholder-only text sent to the LLM provider is personal data for that provider. Calling the product 'anonymization' could mislead buyers.
- LiteLLM correction: the malicious 1.82.7/1.82.8 releases were deleted from PyPI (404), not yanked. The latest is 1.106.3. If the LiteLLM Generic Guardrail adapter ships, pin dependencies with hashes; the guardrail endpoint itself does not need LiteLLM as a dependency.
- URL-mode elicitation recommendation is incomplete. The spec says: servers MUST NOT put PII in the URL; MUST NOT send a pre-authenticated URL (so no upload token in the URL); MUST verify that the user opening the URL is the one who started the elicitation (e.g. compare the session-cookie sub with the token sub); notifications/elicitation/complete and elicitationId were removed; and completion is found by retrying with requestState. URL mode is flagged as 'may change'.
- OAuth/Keycloak mismatch: FastMCP's KeycloakAuthProvider uses Dynamic Client Registration (deprecated in 2026-07-28) and needs Keycloak 26.6.0 or later. In FastMCP, CIMD comes from OAuthProxy/OIDCProxy (enable_cimd is on by default). To get CIMD, put OIDCProxy in front of Keycloak, or use pre-registration. The new MCP extensions OAuth Client Credentials (M2M) and Enterprise-Managed Authorization also suit company deployments and are not mentioned.
- structuredContent caveat is stronger than the takeaways say. The core spec says a tool returning structuredContent SHOULD also return the serialized JSON in a TextContent block, so in practice anything in structuredContent reaches the model. MCP Apps Views can also push data into model context through ui/update-model-context and ui/message. The rehydration View must never call these, and hosts can proxy the View's tools/call through their own infrastructure.
- Claude Code plugin caveat: built-in tools (Read, Bash, etc.) silently ignore an updatedToolOutput that does not match their output shape. A badly shaped redaction then leaks the original. Shape-conformance tests are needed. Also worth using: suppressOriginalPrompt on blocked prompts, and the managed setting allowedProviders=["customEndpoint"] (Claude Code v2.1.285 or later) to force all traffic through the GDPR Guardian gateway. Anthropic now also offers a self-hosted 'Claude apps gateway', and third-party gateways must forward anthropic-beta headers.
- OWASP mapping: MCP10 is 'Context Injection & Over-Sharing'. For prompt injection in returned documents, the more direct item is MCP06 'Prompt Injection via Contextual Payloads'. MCP04 'Software Supply Chain' is relevant given the LiteLLM incident.
- Core MCP tools spec: servers MUST validate inputs, implement access controls, rate-limit tool invocations and sanitize outputs. Rate limiting is missing from the hosted-MCP recommendations. Never mark document_ref or handle parameters with x-mcp-header, since header values are visible to intermediaries.
- Tasks/state: the Tasks extension requires client opt-in, and it does not appear in the official client matrix, so client support is likely thin. FastMCP TasksExtension defaults to an in-memory single-process backend. pydocket serializes with cloudpickle over Redis/Valkey, so the Redis instance must be private, authenticated and TLS-protected; task results stored there must not contain the mapping. FastMCP session state has no TTL by default; wrap the store (missing_ttl) to enforce the 'short TTL' promise.
- Redis: avoid Redis 7.4-7.8 (RSALv2/SSPLv1 only, from memory) and Redis 8 (RSALv2/SSPLv1/AGPLv3) as bundled components. Valkey (BSD-3) is the right default, and redis-py (MIT) is the client pydocket uses.
- Excel omissions: (a) calamine also reads .xls and .xlsb, but openpyxl cannot read .xls, .xlsb or .ods, so hidden-state, comment and metadata checks for those formats need other parsers (e.g. defusedxml over the ODS content.xml). (b) Add limits on decompressed size and ZIP entry count (zip bombs), which defusedxml does not cover. (c) Other places PII hides: formulas vs cached values, named ranges, headers and footers, data-validation lists, threaded comments, chart titles, custom XML, docProps/app.xml, and external-link targets. (d) Even after a column is classified, validate each cell, because columns are often mixed. (e) openpyxl has not been released since 3.1.5 (June 2024), and defusedxml 0.7.1 (2021, PSF license, compatible). (f) MarkItDown's xlsx path (pandas plus openpyxl) reads every sheet, likely including hidden ones (my inference, not tested), which supports the dedicated tabular pipeline.
- Gateway mode: FastMCP proxy docs say 'A proxy passes a backend's tool results through untouched', and the middleware docs do not cover ProxyProvider. Parent middleware is documented only for mounted servers. The 'test first' recommendation is therefore warranted. SEP-2624 (Interceptors) is still an open PR (formerly SEP-1763), with a reference implementation in the experimental-ext-interceptors repo.
- OpenAI Privacy Filter: Apache-2.0 weights, but it is a transformer converted from an LLM checkpoint (1.5B total parameters), 'primarily English', with 8 coarse categories. It arguably conflicts with the LLM-free, EU-country-pack positioning; at most it would be an optional detector, and training-data provenance is undisclosed.
