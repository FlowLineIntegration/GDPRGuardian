# gap-competitor-landscape-spreadsheets

Topic: Commercial and EU competitors: what they offer for spreadsheets and LLM traffic
Why: Only open-source projects were surveyed. Commercial LLM-privacy and DLP products, and EU or French vendors, set what customers expect. For spreadsheets the open questions are whether competitors return format-preserving redacted xlsx or something else, how they handle hidden content, whether they offer reversibility and EU hosting, and at what price. That decides whether Markdown-only spreadsheet output is acceptable or a competitive handicap, and where GDPR Guardian's niche (MIT, no LLM, EU country packs) really lies.

### Key takeaways
- Method note: the shared WebSearch budget was already used up when this agent started, so every finding comes from fetching vendor and cloud documentation directly (pages dated up to 2026-10-23). The survey of EU, French and German vendors is therefore partial.
- Only three of the surveyed de-identification APIs accept xlsx and return a de-identified spreadsheet. Limina (formerly Private AI) returns a base64 redacted XLS/XLSX. Tonic Textual returns a file in the same format, or JSON. Skyflow Detect accepts CSV/XLS/XLSX and returns a base64 processed file. Google SDP only inspects Excel; it de-identifies CSV/TSV. Azure document PII accepts .pdf/.docx/.txt only. AWS works on text only.
- LLM gateways and firewalls do not process files at all. Cloudflare AI Gateway DLP can only flag or block, and does not inspect binary multipart data. Cloudflare's AI firewall (now 'AI Security for Apps') handles JSON only. Bedrock Guardrails, Kong, Traefik and Dataiku work on text only. Purview DSPM for AI, Harmonic, Strac and Prompt Security mostly discover, coach or block rather than pseudonymize.
- Tonic Textual already sends Markdown to LLM pipelines: its JSON output holds Markdown for the whole file plus one table per worksheet, with per-cell entities and hashes. So Markdown for LLMs plus a structured JSON table form is a proven pattern, not a weakness.
- Column awareness is table stakes. Limina needs headers on the first row and sends cells as 'key: value' pairs; it also has a CSV sampling mode that redacts whole columns. Tonic classifies each CSV column as Sensitive, Not sensitive or Unstructured. Google SDP can transform a column by name without inspecting it, with conditions on other columns.
- None of the surveyed vendors documents how it handles hidden sheets. Limina passes review comments through unredacted (it plans to remove them later), warns that formulas may not survive, removes hyperlinks and redacts core document properties. Rewriting the workbook in its original format is therefore incomplete even at the market leader.
- French identifiers: none of the surveyed products detects SIREN or SIRET. The NIR is covered by Azure (France Social Security Number), Google (FRANCE_NIR), Nightfall (FRANCE_INSEE), Purview (INSEE, with checksum and French keywords within 300 characters), Cloudflare (regex) and Strac (FR_NATIONAL_ID / FR_HEALTH_INSURANCE_NUMBER). Limina, Tonic, Protecto, AWS Comprehend, Bedrock and Lakera do not name it.
- Reversible pseudonymization is common among the vendors who mask data. Limina's reidentify endpoint is stateless (the client sends the mapping back). Kong restores original values in responses. SAP unmasks the LLM output. Strac can reverse its Google Sheets anonymization. Protecto unmasks under authorization, Skyflow uses vault tokens and Google uses reversible encryption (AES-SIV / FPE). Azure, AWS, Bedrock, Cloudflare, Traefik and Dataiku masking is one-way.
- No surveyed product combines an open-source licence, deterministic detection without any LLM, EU hosting and an MCP server. Every competitor is proprietary; only client SDKs such as Skyflow's are MIT. Check Point AI Guardrails (Lakera) says it uses 'machine learning and language models'. Tonic lets admins plug in LLM providers for some features.
- Ownership changes: Private AI now redirects to Limina (getlimina.ai). Check Point announced it would acquire Lakera on 16 Sep 2025, and lakera.ai now carries Check Point branding. SentinelOne announced it would acquire Prompt Security on 5 Aug 2025, and the site reads 'Prompt Security from SentinelOne'. Cloudflare renamed Firewall for AI to 'AI Security for Apps'.
- Harmonic's figures on demand: xlsx made up 4.90% and csv 3.17% of 8,226 file uploads to ChatGPT that it observed (May 2025). That is about 8% of uploads, so spreadsheets matter but are not the main load.
- Verdict: Markdown-only output is fine for the core use (prompts to an LLM, the MCP server, the proxy), where competitors offer no file handling at all. It is a gap only against de-identification buyers who want a sanitized file back (Limina, Tonic, Skyflow). That justifies an opt-in CSV or JSON tables output, and an opt-in xlsx rebuilt from cleaned cell values, but not in-place editing that preserves formatting.

### Recommendations
- Keep Markdown as the default output for spreadsheets on the MCP server and the LLM proxy. No gateway competitor handles files, and Tonic itself sends Markdown to LLMs.
- Add an opt-in structured output alongside Markdown: JSON with one table per sheet (header, rows, and placeholders per cell), in the style of Tonic. This makes reinsertion easy for callers and costs little.
- Add an opt-in CSV export, one file per sheet, values only (cached values, never formulas). It is cheap, carries little leakage risk and matches Google SDP and Limina for CSV.
- Ship any rebuilt xlsx as a separate opt-in 'sanitized rebuild': a new workbook built from cleaned cell values, with no formulas, comments, hidden sheets, defined names, pivot caches, external links, embedded objects or document properties. State plainly that formatting is not preserved, and do not attempt in-place editing (Limina's own constraints show how hard that is).
- Default safety policy: list hidden and very-hidden sheets, comments and notes, headers and footers, defined names, data validations, hyperlinks and document properties. Either pseudonymize them as text or drop them, and report what was done in the response. No competitor documents this, so it can be a selling point.
- Use headers as context words in each country pack. A column named 'NIR', 'N° SS', 'SIRET' or 'IBAN' should switch on the matching validator for the whole column, and a column of names should go through NER. Add column-level policies without inspection, like Google's fieldTransformations, and keep placeholders consistent across cells and sheets.
- Highlight SIREN/SIRET (with Luhn) and the NIR (mod-97 key plus French context words) in marketing, since no surveyed vendor detects SIREN/SIRET and several do not detect the NIR.
- Make reversible re-identification stateless, as Limina and Kong do: the caller holds the mapping, or it is encrypted with an ephemeral key. Make sure a rebuilt xlsx or CSV can also be filled back in from a rehydrated LLM answer.
- Publish size and row limits for spreadsheets (competitors cap at roughly 10 MB per request) and offer truncation or sampling modes, because Markdown for large sheets uses a lot of tokens.

### Risks
- A format-preserving xlsx rewrite can leak data through shared strings, pivot caches, cached formula values, comments, hidden sheets, defined names, chart caches, embedded objects and docProps. Limina's documentation shows partial coverage even at the leader.
- Replacing cell values breaks formulas and data validations. Keeping cached values can leave originals behind.
- Header-based column classification can produce false positives (Limina warns about column names) and misses unlabelled columns.
- A rebuilt-xlsx feature may be read as document editing, which conflicts with project constraint 5; it must stay a data export, not visual redaction.
- Large spreadsheets turned into Markdown can exceed LLM context and inflate cost and latency on CPU-only servers.
- Big cloud vendors could close the gap quickly, for example if Azure adds xlsx to document PII or Google adds Excel de-identification.
- The competitor survey is incomplete because the search budget ran out. French and German vendors on SecNumCloud or HDS beyond SafeBrain and Octopize could not be enumerated.
- Several vendor claims (SafeBrain's SecNumCloud, Octopize's CNIL evaluation, Harmonic's statistics) come from the vendors' own sites and were not checked independently.

### Open questions
- Does Skyflow's processed XLSX keep the original formatting, and what happens to formulas and hidden sheets? Its API docs returned HTTP 403.
- Exact prices for Azure Language PII, Google SDP and AWS: the pricing pages render prices dynamically and the fetch did not return figures.
- Which other French and German vendors offer pseudonymization for generative AI on SecNumCloud or HDS hosting? The search budget ran out, so this needs a follow-up search.
- Do Bedrock Guardrails sensitive-information filters follow the Classic-tier language list (English, French, Spanish), or are they language-independent?
- Have the Check Point-Lakera and SentinelOne-Prompt Security deals formally closed? The branding suggests so, but no closing notice was fetched.
- Do GDPR Guardian's target customers want a sanitized file back, or only text ready for an LLM? Customer research should confirm demand before building an xlsx rebuild.
- Does Limina's SaaS run in an EU region? The site lists Germany among deployment locations without saying which deployment type.

### Verification ({'confirmed': 17})
### Verifier notes
- Method: the shared WebSearch budget was used up for this turn as well, so every check above comes from fetching primary pages directly. Claims that needed a search to settle are marked uncertain or flagged below.
- Harmonic demand figure is misread: 'about 8% of uploads, so spreadsheets are not the main load' ignores that images are 68.3% of uploads. Of non-image document uploads (about 28.6%), xlsx+csv (8.07%) are about 28%. That is second only to PDF (13.4%) and larger than docx (5.46%). For a text-only anonymizer, spreadsheets are the number-two document type, so the takeaway understates them. The data is also one vendor, one unnamed quarter and ChatGPT only, and it measures volume, not sensitivity.
- 'None of the surveyed products detects SIREN or SIRET' is too strong. Limina has a generic ORGANIZATION_ID entity (company codes such as EINs and VAT numbers; full support for English only). Azure ('France Value Added Tax Number') and Google (global VAT_NUMBER) detect the French VAT number, whose structure is 2 key digits + SIREN (python-stdnum fr/tva.py). Safer wording: 'no vendor documents a named, checksum-validated SIREN/SIRET detector'.
- Legal nuance missing from the SIREN/SIRET marketing recommendation (from memory, not re-fetched from EUR-Lex this turn): GDPR Recital 14 says the Regulation does not cover data concerning legal persons, including their name, form and contact details. SIREN/SIRET of companies are also public in INSEE's Sirene open data. They are personal data only when they identify a natural person, such as an entrepreneur individuel or micro-entrepreneur. Recommendation: present SIREN/SIRET detection as a configurable policy (keep company IDs for usefulness, or pseudonymize sole-trader IDs), not as a core GDPR differentiator.
- Checksum details the recommendations miss: (a) SIRET is Luhn EXCEPT La Poste. For SIREN 356000000, every SIRET other than the head office 35600000000048 must instead have a digit sum that is a multiple of 5 (python-stdnum fr/siret.py), so a plain Luhn check rejects valid La Poste SIRETs. (b) SIREN is Luhn on 9 digits. (c) NIR key = 97 - (first 13 digits mod 97), after replacing Corsica department 2A with 19 and 2B with 18 (python-stdnum fr/nir.py).
- License caution: python-stdnum, the obvious reference implementation, is LGPL-2.1, not MIT. Use it only as a reference, or reimplement the algorithms; do not ship it as a dependency of an MIT package without a deliberate LGPL decision. pyxlsb (for .xlsb) is LGPLv3+, so avoid it. MIT-compatible readers: openpyxl (MIT, latest 3.1.5, June 2024, ageing) and python-calamine (MIT, 0.9.0, a Rust calamine binding for Excel and ODF). xlsxwriter is BSD for writing (from memory, not re-verified).
- Omitted open-source competitor: Microsoft Presidio (MIT) has moved to a 'Data Privacy Stack' organisation (presidio.dataprivacystack.org; the GitHub README says 'Presidio has moved to a new home!'). Its presidio-structured package does column-level PII detection for pandas DataFrames and JSON (most-common, highest-confidence and mixed strategies), which is open-source, non-LLM prior art for 'column awareness'. Presidio has no France recognizers (it has DE_HANDELSREGISTER and SE_ORGANISATIONSNUMMER business IDs), which supports GDPR Guardian's France angle. It weakens the framing that 'every competitor is proprietary'.
- Spreadsheet handling the takeaways missed: Nightfall's file scanning accepts xlsx and csv as tabular data and can redact CSV files (enableFileRedaction), though not xlsx. Strac has POST /anonymize-gsheets, which pseudonymizes Google Sheets in place and can be reversed through /anonymize-gsheets/reverse, with a 10 MB document cap. So 'only three vendors return a de-identified spreadsheet' holds only for xlsx.
- Limina details to correct or add. The CSV page says 'headers must be on the first row'; the Excel page says 'first non-empty row'. 'key: value' comes from the Structured Data guide (multi-level headers as 'key1a: key1b: value'), not from the Excel processing path. CSV sampling mode (csv_options) is confirmed: it 'redacts the entirety of the column'. The Community API caps CSV at 250 KiB and Excel at 10 MiB, and the Professional API does not support Excel at all. Headers and footers, text boxes and embedded external objects pass through unredacted, so 'no competitor documents this' should read 'Limina documents a partial property table; nobody documents hidden sheets'.
- Limina's reidentify endpoint takes processed_text plus the entities list from the client, which is stateless by design. The docs never say 'stateless' and make no retention statement. Kong's restoration is optional and relies on a server-side anonymizer service, so 'stateless, as Limina and Kong do' is accurate only for Limina.
- Microsoft Purview France SSN (INSEE): confirmed 300-character proximity, checksum, and French keyword list. Its pattern only accepts 15 consecutive digits or '13 digits + space + 2 digits', so the common grouped format '1 85 05 78 006 084 36' is not matched. That is a concrete gap GDPR Guardian can beat with normalised matching.
- Takeaways on ownership changes are confirmed: Check Point announced the Lakera acquisition on 16 Sep 2025 (expected to close in Q4 2025), and SentinelOne announced the Prompt Security acquisition on 5 Aug 2025. Cloudflare 'AI Security for Apps (formerly Firewall for AI)' handles only application/json requests and works through custom or rate-limiting rules (block or challenge), with no redaction.
- xlsx leakage vectors missing from the 'sanitized rebuild' and 'default safety policy' recommendations: chart XML caches (c:numCache and c:strCache keep copies of cell data); sheet, table and defined names that contain personal names; VBA projects in .xlsm (vbaProject.bin); custom XML parts and docProps/custom.xml; threaded comments as distinct from legacy notes; conditional-formatting and data-validation formulas; externalLink cached values; print titles; .xlsb, .xls (BIFF) and .ods inputs.
- Implementation risks to add: (1) CSV/formula injection. When writing CSV or a rebuilt xlsx, escape values starting with =, +, -, @, tab or CR, because pseudonymized LLM output could otherwise inject formulas. (2) 'Cached values, never formulas': files written by non-Excel tools often lack cached values (openpyxl data_only=True then returns None), so define a fallback and report it. (3) xlsx is a zip of XML: guard against zip bombs and XXE (openpyxl recommends defusedxml) and enforce the published size and row limits.
- Size-limit benchmark: Azure document PII allows 10 MB and 40 docs per request, Limina Excel 10 MiB (Community API) and CSV 250 KiB, Strac 10 MB per document, and Google SDP 30 MB per Excel file before falling back to binary scanning. 'Roughly 10 MB' is fair, but Google is higher.
