# gap-spreadsheet-structure-column-typing

Topic: Table and header detection on messy real-world sheets, semantic column-type detection prior art, and a spreadsheet evaluation corpus
Why: Every dimension rests its Excel answer on column-level classification: header lexicon plus the hit rate of validators or gazetteers on sampled values, with thresholds that disagree (0.5, 0.6, 0.7-0.8, 0.8). Some dimensions then mask the whole column, others only use the column as a prior. All of this assumes tidy tables with one header row in row 1. Nobody checked how often real business sheets have multiple tables, multi-row or merged headers, key-value 'form' layouts or cross-tabs. Nobody surveyed column-type detection research or found a spreadsheet test corpus. If tidy tables are rare, the core detection design changes.

### Key takeaways
- Messy layouts are the norm, not the edge case. In TableSense's random test set (WebSheet400), 400 web-crawled sheets held 795 tables (about 2 per sheet). Auto-Tables estimates that 30-50% of sampled real spreadsheet and web tables are non-relational (transposed, stacked, wide). So 'one table per sheet, header in row 1' (MarkItDown's behaviour) will often be wrong.
- Excel's own region-growth detection (Ctrl+*, 8-connectivity) gets only 52.2% precision and 58.5% recall at EoB-2 on WebSheet400. Plain connected components is a weak baseline on its own; it needs row-type rules on top.
- No released ML table detector is permissive and CPU-friendly. TableSense publishes only annotations (O-UDA) with no model. SpreadsheetLLM detects tables with an LLM (excluded) and has no official code. Mondrian is GPL-3.0 and Pytheas has no license. The usable open baselines are deterministic: Docling (MIT, BFS flood fill), Unstructured (Apache-2.0, connected components plus single-cell title/note rows) and Strudel (Apache-2.0, random-forest line classifier with 14 features).
- python-calamine 0.9.0 (MIT, released 2026-10-16) exposes merged cell ranges, Excel ListObject tables with their header names (load_tables=True, xlsx only) and sheet visibility (Hidden/VeryHidden). It exposes no styles and no formulas, so cues such as bold headers or borders (used by TableSense and SpreadsheetLLM) are not available. Header detection must rely on value-type and lexicon heuristics, or on a separate styles.xml parse.
- Commercial classifiers combine the column name with sampled values. Purview: top 128 rows or 1 MB, system match threshold fixed at 60%, a column-name regex as an optional extra. Macie: a keyword in an Excel/CSV/TSV column name puts every value in that column 'in proximity'. Google SDP: a header hotword (windowBefore=1) changes the likelihood. AWS Glue: a sample % plus a detection-threshold %. Purview treats XLSX as a document (asset-level only).
- The ML column typers (Sherlock, Sato, DoDuo, TURL) are English-only, use DBpedia types and cover no national identifiers. Their training data (VizNet; WikiTables, which is CC BY-SA) has no clear license, and TURL's checkpoints are no longer downloadable. Reuse their feature ideas; do not ship their weights.
- Header lexicon: Wikidata property labels and aliases are CC0. FR/DE/ES/IT/EN labels and aliases were checked for date of birth (P569), given name (P735), family name (P734), phone (P1329) and email (P968). They make a good seed for a multilingual header lexicon but need curation ('nom' is ambiguous, abbreviations such as DDN or N° SS are missing).
- Evaluation data: the Enron spreadsheet set is labelled CC BY 4.0 on figshare (16,189 unique files) but contains real people's data, so use it privately and do not bundle it. data.gouv.fr lists 2,450 datasets with xlsx resources, of which 1,308 (53%) are under a Licence Ouverte; use them as a structural corpus. The Répertoire national des élus (LO 2.0) gives real French name and birth-date columns. Faker (MIT) fr_FR generates NIRs with valid keys.
- Recommendation: treat the column type as a prior that tunes per-cell detection, never as a substitute for it. Mask a whole column only for high-confidence direct-identifier columns. Set column thresholds with a binomial test against each validator's chance pass rate (about 10% for Luhn, about 1/97 for mod-97).
- Limit on this research: the shared WebSearch budget (200 per turn) was used up before this agent's first search. Every fact here was checked by fetching the primary URLs directly. FUSE and VEnron could not be reached, and the Nuix/EDRM findings on PII in Enron were not retrieved.

### Recommendations
- Pipeline: load with calamine. Process every sheet, including Hidden and VeryHidden ones. If ListObject tables exist (load_tables=True), use their ranges and header names directly.
- Find regions deterministically. Run connected components on non-empty cells, treating merged ranges as filled (as Docling and Unstructured do). Use a gap tolerance of 1 for columns and 0 for rows, then merge components that overlap in rows. Emit single-cell rows above or below a region as title/note text, which still gets per-cell NER.
- Classify rows inside each region with cheap features (Strudel's 14: empty, numeric and string ratios, position, type change against neighbours, total keywords). Begin with hand rules and train a small random forest later on data.gouv and Enron annotations. Header candidates are the leading rows that are mostly unique short strings above type-consistent rows (the csv.Sniffer logic). Join multi-row and merged headers as 'Parent / Child'.
- Detect totals and notes by keyword (Total, Sous-total, Summe, Totale, TOTAL) and by single-cell or sparse rows. Exclude them from column statistics but still scan them per cell.
- Check orientation: compare type homogeneity per column with per row. If rows are more homogeneous, transpose before typing (Auto-Tables lists 28 transpose cases among 244).
- Key-value form sheets: detect 2-column (or label/value alternating) regions where the label column is mostly short text matching the header lexicon or ending in ':', and the value column has mixed types. Bind each label as the 'header' of the cell to its right (or below). Render them in Markdown as '**Label :** [PLACEHOLDER]' lines, not as a table.
- Give NER context in the cell itself: serialize short cells as 'header: value' (for example 'Nom : Dupont') before GLiNER. This is the deterministic equivalent of Macie's column-name proximity and Google's header hotwords.
- Use the column type as a prior, never as the only detector. Always run per-cell regex, validators and NER over every cell (regex and validators are cheap; run NER on all free-text cells). Use the column prior to lower the NER threshold and to accept checksum-less formats (phone, date) in that column.
- Mask a whole column only for high-confidence direct-identifier columns: names, email, phone, NIR, IBAN, address. Mask every non-empty cell there, including misspellings and partial values. Never mask a whole column on the header alone if the values contradict it (for example 'Nom du produit').
- Thresholds with confidence: run validators on all shape-matching cells, which is cheap, so no sampling is needed. Accept type T when k of n shape-matching cells pass and the binomial tail P(X>=k | n, p0) < 1e-3, where p0 is the validator's chance pass rate (Luhn 0.10, mod-97 about 0.0103). Examples: 8/20 for Luhn (p of about 4e-4) or 3/10 for mod-97 (p of about 1.3e-4). Also require the Wilson 95% lower bound >= 0.5 (24/30 gives about 0.63).
- For types without a checksum (names via NER, dates, phones), require header evidence plus a value rate whose Wilson lower bound is >= 0.3. Run NER on a stratified sample of up to 64-128 distinct values (Purview uses 128 rows), taken from the top, middle and bottom to avoid sorted or total artefacts. Rule of three: 0 failures in n means at most 3/n invalid at 95%, so n=60 bounds it at 5%.
- Header lexicon: generate FR/DE/ES/IT/EN labels and aliases from Wikidata (CC0) for about 30 PII properties. Normalize (casefold, strip accents and punctuation, expand abbreviations such as 'tél', 'n°', 'ddn', 'nss', 'dob'). Add a hand-curated alias list per country pack, and use the SEMIC CPV terms as the type taxonomy.
- Evaluation: (a) data.gouv.fr xlsx under lov2/fr-lo, annotated for regions and headers; (b) Enron spreadsheets used privately for messy layouts, with PII cells replaced by Faker values and only annotations or re-skinned files committed; (c) RNE and GitTables/SOTAB for header and value typing; (d) TableSense O-UDA ranges for boundary EoB-0/EoB-2 scoring.
- Measure per-cell PII recall as the primary metric and column-type F1 as secondary. Track three error classes separately: missed regions, wrong header row, and PII in notes, comments or hidden sheets.

### Risks
- Leaks outside the cell grid: calamine's stub exposes no comments, formulas, styles or document properties. Author names, comments, sheet names and defined names can carry PII and may reach the LLM unless they are parsed separately (for example through docProps and comments XML).
- If the column prior is used as a mask, recall drops on mixed columns (free-text 'Observations', 'Contact' holding a name or a phone) and precision drops on false headers ('Nom du produit'). Per-cell scanning must stay on.
- A Luhn chance pass rate of 10% means internal 9-digit IDs often pass SIREN validation. Without a header prior and a binomial test, false SIREN/SIRET columns will appear.
- The Enron corpus contains real people's data. Processing it in the EU falls under GDPR, and the CNIL developer guide advises fictitious data for tests. Bundling it, even under the CC BY 4.0 label, could republish personal data. The Nuix/EDRM PII findings were not verified here.
- Copying Purview or Macie keyword lists, or the CNIL guide (GPL-3.0), into the MIT repo would create licence problems. Build lexicons from CC0/CC-BY sources only.
- GitTables per-table licences and SOTAB's missing licence make them unsafe as bundled fixtures. Keep them as downloadable eval-only sets.
- Region detection with gap tolerance can merge adjacent tables, which mis-assigns headers and can pseudonymize one column with another column's type. Evaluate with exact boundaries (EoB-0).
- Search budget: the turn's WebSearch quota was exhausted. The following stay unverified: FUSE/VEnron availability and terms, the DECO/FUSTE licences, Strudel's label set and data licences, and whether any 2025-2026 permissive small-encoder table detector exists.

### Critical claims
- TableSense's random test set WebSheet400 has 400 sheets containing 795 tables. Excel's region-growth baseline scores 52.2% precision and 58.5% recall at EoB-2; TableSense scores 86.5% and 91.3%. [https://ar5iv.labs.arxiv.org/html/2106.13500]
- The microsoft/TableSense repo publishes only table-range annotations (2,615 tables in 1,645 spreadsheets from VEnron2, VEUSES and VFUSE) under the Open Use of Data Agreement v1.0. The WebSheet dataset is unpublished for compliance reasons, and no model or code is released. [https://github.com/microsoft/TableSense]
- SpreadsheetLLM detects tables with a fine-tuned LLM (best F1 0.759 against TableSense-CNN 0.666 at EoB-0). Its structural-anchor step is heuristic, and k=4 keeps over 97% of boundary rows and columns. [https://arxiv.org/html/2407.09025]
- Auto-Tables reports that over 30% (30-50% in its introduction) of sampled real spreadsheet and web tables are non-relational, and uses a CNN rather than an LLM. [https://ar5iv.labs.arxiv.org/html/2307.14565]
- Docling's MIT Excel backend detects tables by BFS flood fill over non-empty and merged cells, with gap_tolerance defaulting to 0, and flags the first row of each region as the column header. It uses no ML. [https://raw.githubusercontent.com/docling-project/docling/main/docling/datamodel/backend_options.py]
- python-calamine v0.9.0 (MIT, published 2026-10-16) exposes merged_cell_ranges, Excel tables via load_tables, and sheet visibility, but its stub has no style or formula API. [https://raw.githubusercontent.com/dimastbk/python-calamine/master/python/python_calamine/_python_calamine.pyi]
- For structured files, Microsoft Purview samples the top 128 rows or the first 1 MB. Its system classifications use a fixed 60% minimum match threshold. XLSX is a document format that gets only asset-level classification. [https://learn.microsoft.com/en-us/purview/data-map-data-sources]
- Amazon Macie treats a keyword in a column name of Excel, CSV or TSV data as being in proximity of every value in that column. For unstructured data, the keyword must be within 30 characters. [https://docs.aws.amazon.com/macie/latest/user/managed-data-identifiers-keywords.html]
- AWS Glue Detect PII offers a column-level mode with a configurable sample portion (% of rows) and a detection threshold (% of rows, example 10%). [https://docs.aws.amazon.com/glue/latest/dg/detect-PII.html]
- presidio-structured (MIT, v0.0.8) types columns from cell values only, not column names. Its strategies are most_common (default), highest_confidence and mixed, with a 0.5 threshold. [https://raw.githubusercontent.com/microsoft/presidio/main/presidio-structured/presidio_structured/analysis_builder.py]
- The Enron Spreadsheets and Emails figshare record is labelled CC BY 4.0 and was published 2014-10-30. Its spreadsheets.7z is 992,635,888 bytes, and the author reports 16,189 unique spreadsheets. [https://api.figshare.com/v2/articles/1221767]
- Wikidata structured data (main and Property namespaces) is released under CC0, so property labels and aliases such as P569 'date de naissance / Geburtsdatum / fecha de nacimiento / data di nascita' can be bundled. [https://www.wikidata.org/wiki/Wikidata:Licensing]
- On 2026-10-24, data.gouv.fr listed 2,450 datasets with xlsx resources. By licence: 838 lov2, 470 fr-lo, 227 ODbL and 785 notspecified. [https://www.data.gouv.fr/api/1/datasets/?format=xlsx&license=lov2&page_size=1]
- piicatcher was archived on 2026-01-26. Mondrian is GPL-3.0, and Pytheas has no licence file. [https://github.com/tokern/piicatcher]
- Sherlock (MIT) covers 78 DBpedia types and was trained on 686,765 VizNet columns with 1,588 features, reaching a support-weighted F1 of 0.89. [https://arxiv.org/abs/1905.10688]

### Verifier notes
- The SpreadsheetLLM figure is wrong in the claims: the paper's headline best F1 is 0.789 (ablation without aggregation), and 0.759 is the full pipeline. TableSense intro vs table mismatch: cite 52.2% precision (Table 3), not the 55.2% in the paper's introduction.
- The recommendation to treat merged ranges as filled '(as Docling and Unstructured do)' is half wrong. Unstructured's xlsx partitioner has no merged-cell logic. Its connected components use 4-connectivity (no diagonals), unlike Excel's 8-connectivity. It merges components that overlap by column span (min_x/max_x), not 'in rows'. It does not infer headers (include_header defaults to False). Docling does handle merged cells.
- Docling has newer features the takeaways omit: treat_singleton_as_text, which emits 1x1 tables as text, and _split_leading_section_label, which strips a merged title row above a table. Both partly answer the title/note-row problem.
- Omission: openpyxl (MIT, 3.1.5) exposes styles (bold, borders, fills), formulas, merged cells, cell comments, hidden rows and columns, and data validation. It is a permissive way to get the header cues calamine lacks (slower, but no separate styles.xml parse needed). Docling's Excel backend is itself built on openpyxl.
- Omission (important for GDPR completeness): calamine cannot read cell comments or threaded comments. The recommendations track 'PII in notes, comments or hidden sheets', so comments need openpyxl or a raw XML parse. Other xlsx PII places are not mentioned at all: docProps/core.xml (creator, lastModifiedBy), pivot cache records (a full copy of the source data), chart caches, defined names, headers and footers, external links, embedded objects and images, and hidden rows and columns. If GDPR Guardian writes an anonymized xlsx rather than Markdown, pivot caches and document properties must be purged or rewritten.
- python-calamine 0.9.0 dropped Python 3.10 (requires_python >=3.11) and its release notes list no new features. Check GDPR Guardian's minimum Python version before pinning >=0.9.
- Purview nuance: system classifications on structured data also require a minimum number of distinct values (the docs say unstructured formats have 'no requirement to meet a condition of eight distinct values'). The column-name regex ('Column Pattern') exists only for custom classifications, and custom classifications are never applied to XLSX.
- Google SDP: the docs' header-hotword example uses windowBefore=1 (the Go sample uses 5). The docs also recommend an ExcludeByHotword exclusion rule to drop a whole column. That is a useful pattern for the 'Nom du produit' false-positive case.
- SEMIC Core Person Vocabulary 2.1.1 is outdated: v2.1.2 was released 2026-06-09.
- ML column typers: Sato, DoDuo and TURL code is Apache-2.0 and Sherlock is MIT, so the code licences are not the blocker; the data and weights are. TURL's README (update 11/22/2025) confirms the checkpoints and data link no longer works.
- Strudel is confirmed: 14 line features (line_position, has_derived_keyword, discounted_cumulative_gain, empty/numeric/string cell ratios, average word count, empty-line ratio before/after, histogram diff before/after, data type before/after, derived_cell_coverage) and a scikit-learn RandomForestClassifier with default hyperparameters, Apache-2.0. It was designed for verbose CSV files, not xlsx, and ships no pretrained model.
- Faker caveat for evaluation: fr_FR NIRs always use birth months 01-12, so they never exercise special month codes (20-42, 50-99). Add hand-made NIR cases for those, and for 2A/2B Corsica keys, which Faker does handle. Faker vat_id() FR keys are not checksum-valid.
- Legal caution: RNE (lov2) and Enron (CC BY 4.0) contain real people's personal data. Open licences do not remove GDPR obligations, so use them only privately for evaluation, as the takeaways already say for Enron, and apply the same rule to RNE.
- Binomial and Wilson figures check out: P(X>=8 | 20, 0.1) is about 4.1e-4; P(X>=3 | 10, 1/97) is about 1.2e-4 (the claim says 1.3e-4); the Wilson 95% lower bound for 24/30 is about 0.627. For NIR the chance key-match rate is closer to 1/100 than 1/97, a negligible difference.
- The WebSearch budget was used up for this turn, so this check relied on direct fetches. Not verified: SpreadsheetLLM having no official code, the VEnron2/FUSE/EUSES licences, other Wikidata properties (P734, P735, P1329, P968), and whether newer permissive table detectors exist.
