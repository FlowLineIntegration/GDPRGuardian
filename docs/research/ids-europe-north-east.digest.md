# ids-europe-north-east

### Key takeaways
- Library coverage is thin. The MIT Presidio (now at github.com/data-privacy-stack/presidio, 2.2.364 of 2026-07-22) covers only 4 identifiers in this scope: PL_PESEL, FI_PERSONAL_IDENTITY_CODE, SE_PERSONNUMMER and SE_ORGANISATIONSNUMMER. GDPR Guardian has to build its own Nordic and Eastern European country packs.
- A checksum can no longer be a hard gate everywhere. Danish CPR numbers have not been guaranteed to pass modulus 11 since 2007. Iceland has issued kennitala without a valid check digit since 18 Feb 2026. From 1 Jan 2032 the first Norwegian check digit (k1) can take 4 values. Lithuanian codes starting with 9 have no check digit. Use the checksum to raise the score, and keep date and structure checks plus context as the floor.
- Recent format changes that test data must cover: Finnish century signs Y/X/W/V/U and B-F since 2023; Latvian '32' codes without a birth date since July 2017; Dutch VAT numbers using mod-97 since 2020; Norway's 2032 rule. Faker (no new Finnish signs, no Latvian 32-codes, no Danish CPR, no Icelandic locale) and django-localflavor (rejects Latvian 32-codes; checks Icelandic kennitala, Norwegian numbers without D/H support) lag behind.
- Licences: python-stdnum 2.2 (2026-01-04) is LGPL-2.1+, so it is caution, not ok. django-localflavor 5.1 is BSD-3, but its requires_dist includes python-stdnum>=2.2 and Django>=4.2, so it brings in LGPL code too. Faker (MIT) and Presidio (MIT) are ok. Write the algorithms from public specs in MIT code, and use stdnum at most as an optional extra or a test oracle.
- Many identifiers are bare 8-11 digit strings with weak checksums (mod 10 or mod 11 lets about 9-10% of random strings through): Hungarian TAJ, Czech and Slovak IČO, Polish REGON, Croatian OIB, Bulgarian LNCh, Romanian CUI, Estonian registrikood. The same 11-digit string can pass the rules of several countries (PL PESEL, NO fnr, EE/LT isikukood, HR OIB, LV reg. no.). Local-language context words and country-pack scoping are required.
- EU VAT: one recognizer keyed on the 2-letter prefix (EL for Greece, XI for Northern Ireland, EU for OSS) covers all 27 member states. Every member state has a deterministic check rule. EORI, the EHIC card number and the driving licence number (field 5) have no EU-level checksum, so detect them through context only.
- Answer to the Excel question (the user's request): xlsx cells hold many of these identifiers as numbers. Leading zeros are lost (CPR for days 01-09, PESEL and rodné číslo for births in 2000-2009, OIB), digits beyond 15 are truncated (the 20-digit EHIC number), and values show in scientific notation. If xlsx is supported, read the cell's text or format (not the float), try zero-padding candidates one digit too short and confirm with the checksum, and treat the column header (e.g. 'PESEL', 'CPR-nr', 'Personnummer') as context for the whole column.
- Not verified in this run: the EHIC field structure (EUR-Lex returned empty pages) and several national primary specs (LV, LT, HU, BG, RO, HR, SI). Those rely on python-stdnum source, Wikipedia or django-localflavor. The shared WebSearch budget ran out partway through, so later checks used direct fetches only.

### Recommendations
- Write every validator in-house under MIT from the public specs listed (algorithms are not copyrightable). Run python-stdnum only in CI as a differential test oracle, or as an optional extra, never vendored.
- Use three validation levels per recognizer: STRICT (structure + date + checksum), LENIENT (structure + date, checksum only adds score) and CONTEXT-ONLY. Put DK_CPR, IS_KENNITALA, LT codes starting with 9, NO numbers after 2032 and 9-digit CZ/SK rodné číslo in LENIENT; put EORI, EHIC and driving licence in CONTEXT-ONLY.
- Make country packs versioned, with effective dates: FI separators 2023 and gender-neutral 2027; LV '32' codes from 2017-07-01; IS check digit dropped 2026-02-18; NO new k1 rule 2032-01-01; NL VAT mod-97 from 2020. Add regression tests built from Faker and hand-made edge cases.
- For an 11- or 10-digit match that fits several countries, keep every country interpretation whose checksum passes. With country='auto', break ties using context words in the local language and document language detection; never drop a match only because of ambiguity, because anonymizing is the safe default.
- Base scores: a structured separator (HETU sign, '/' in rodné číslo, '-' in personnummer, a VAT prefix) plus a passing checksum is high confidence. A bare digit string passing a mod-10/11 check is medium with context and low or discarded without it. Use a context window of ±40 characters plus table and column headers.
- Normalize before matching: remove spaces, non-breaking spaces (U+00A0, U+202F), dots, hyphens and slashes inside candidates; uppercase letters for HETU, CY and IE. Match context words case-insensitively with Unicode NFC (Cyrillic for BG; diacritics for CZ/SK/HU/PL/LT/LV).
- Excel handling (user question): if xlsx input is accepted, convert with a reader that keeps the displayed text (e.g. openpyxl with number_format) and not the float. For numeric cells whose length is one short of an expected ID length (CPR 10, PESEL 11, rodné číslo 10, OIB 11), try left-padding with a zero and accept only if the checksum passes. Flag cells in scientific notation or above 15 digits (EHIC) as possibly truncated. Use the header cell as context for the whole column ('PESEL', 'CPR', 'Personnummer', 'TAJ', 'OIB', 'EGN/ЕГН').
- Use a single EU_VAT recognizer keyed on the prefix, with per-country checksums from the table, and report the sub-type (company vs embedded personal ID). VAT numbers of sole traders are personal data, so anonymize by default.
- Prefer granular placeholders that still hide the country, e.g. [ID_NATIONAL_1] or [ID_TAX_1], rather than [PL_PESEL_1]. The label alone can reveal nationality, a quasi-identifier. Make this a per-tenant option.

### Risks
- Hard checksum gates cause false negatives (leaks): DK CPR since 2007, IS kennitala since 2026-02-18, NO from 2032 (only 1 of the 4 valid k1 values matches the old rule), LT codes starting with 9, SI EMŠO when the computed check would be 10 (localflavor rejects, stdnum maps to 0), the CZ/SK pre-1985 mod-11 exception, and NL VAT for sole traders since 2020.
- False positives on bare numbers: mod-10 checks (HU TAJ, PL REGON-9 via mod 11 then mod 10, HR OIB, BG LNCh, EE KMKR) let about 10% of random strings through, and mod-11 checks about 9%. Invoice, order and phone numbers in business documents will be over-anonymized without context. That is tolerable for privacy but hurts LLM usefulness.
- Licence: python-stdnum is LGPL-2.1+, and django-localflavor pulls it in transitively. Copying stdnum source into the MIT repo would breach the LGPL terms; keep it an unmodified dependency or reimplement.
- Rules keep changing in countries in scope: FI 2027, NO 2032, IS 2026, and LT/SK/CZ replacement proposals. Without versioned packs and monitoring, detection accuracy will drift.
- Spec provenance: python-stdnum itself flags the LV personal-code and RO CNP check algorithms as 'not confirmed by an independent source'. The EHIC number structure could not be verified (EUR-Lex inaccessible), so its regex and checksum are provisional.
- Online validation (VIES, EORI, Skatteetaten) would leak identifiers to third parties and break the no-external-call promise; it must not be added as a convenience feature.
- Excel and CSV ingestion can silently corrupt identifiers (leading zeros, 15-digit precision, scientific notation, auto-dates). Corrupted IDs then evade detection and leak in the Markdown output.

### Open questions
- EHIC: the exact format of field 8 (card identification number: length, '80' + ISO numeric country prefix, Luhn?) and field 7 (institution ID) under Decision S2. EUR-Lex returned empty pages in this run; fetch the PDF manually.
- Iceland: when do real (non-test) kennitölur without a valid check digit start? Are system IDs (kerfiskennitala) for foreigners structurally different (e.g. first digit)?
- Finland: was the 2027 gender-neutral issuance of new HETU numbers enacted, and does it change the format or only how the individual-number parity is allocated?
- Latvia: is the check-digit algorithm for '32' personal codes officially published (PMLP or Cabinet regulation)?
- Lithuania (opaque personal codes), Slovakia (BIFO replacing rodné číslo) and Czechia (rodné číslo phase-out): current legal status in 2026?
- EORI: does Greece use 'GR' (ISO) or 'EL' (VAT) as its prefix? Do national EORI suffix conventions (e.g. PL NIP + 00000, FR SIRET) deserve sub-recognizers?
- Romania: did the 2024-2025 trade register (ONRC) reform change the 'J40/123/2005' number format?
- Excel scope (user's actual question): will GDPR Guardian accept xlsx/csv as input? If so, should identifiers be detected per cell with header-as-context and zero-padding repair, and how should formulas, comments and hidden sheets be handled? That is outside this identifier research but changes the recall of every recognizer above.
- The shared WebSearch budget ran out partway through this run, so primary national sources for LV, LT, HU personal ID, BG, RO, HR and SI were not retrieved. Those rows rely on python-stdnum source, django-localflavor, Faker and Wikipedia.

### Critical claims
- Iceland (Þjóðskrá): from 18 Feb 2026 all kennitölur, both system IDs and individuals' numbers, are issued without a calculated check digit and so fail the check-digit test. Systems are told to remove that test. [https://www.skra.is/folk/eg-i-thjodskra/um-kennitolur/kennitolur-an-vartolu]
- Norway: Norwegian ID numbers issued from 1 Jan 2032 use k1 = {11,12,13,14} - (weighted sum mod 11), so k1 can take 4 values. k2 is computed as before. The individual number no longer indicates century or gender. [https://skatteetaten.github.io/folkeregisteret-api-dokumentasjon/nytt-fodselsnummer-fra-2032/]
- Sweden: personnummer check digit uses modulus 10 with alternating weights 2 and 1 over YYMMDDNNN. The '-' becomes '+' in the year the person turns 100. Samordningsnummer adds 60 to the birth day (since 2000). [https://docs.swedenconnect.se/technical-framework/mirror/skv/skv704-8.pdf]
- Sweden: the organisationsnummer has 10 digits; its third digit is always at least 2 to avoid confusion with personnummer; the last digit is a check digit. [https://docs.swedenconnect.se/technical-framework/mirror/skv/skv709-8.pdf]
- Denmark: CPR numbers are no longer guaranteed to satisfy modulus 11. Under the newer allocation method a number that happens to pass modulus 11 cannot be used, because it may already be assigned; python-stdnum dk.cpr does not enforce the checksum. [https://www.dst.dk/da/Statistik/dokumentation/Times/cpr-oplysninger/bef-personnummer/pnr]
- python-stdnum latest release is 2.2 (2026-01-04), licensed LGPL (classifier LGPLv2+; headers say LGPL 2.1 or later). [https://pypi.org/pypi/python-stdnum/json]
- django-localflavor 5.1 (2026-08-01) is BSD-3-Clause, but its requires_dist is ['django>=4.2','python-stdnum>=2.2']. [https://pypi.org/pypi/django-localflavor/5.1/json]
- Presidio (presidio-analyzer 2.2.364, MIT, homepage github.com/data-privacy-stack/presidio) covers only PL_PESEL, FI_PERSONAL_IDENTITY_CODE, SE_PERSONNUMMER and SE_ORGANISATIONSNUMMER among DK/NO/IS/EE/LV/LT/PL/CZ/SK/HU/RO/BG/HR/SI/SE/FI, and has no EU-wide VAT entity. [https://presidio.dataprivacystack.org/supported_entities/]
- Finland: python-stdnum fi.hetu (and Presidio's FI recognizer) accept the century signs '+', '-', Y, X, W, V, U (1900s) and A-F (2000s). Faker fi_FI ssn uses only '+', '-' and 'A'. [https://raw.githubusercontent.com/arthurdejong/python-stdnum/master/stdnum/fi/hetu.py]
- Latvia: personal codes issued from July 2017 start with '32' and contain no birth date. python-stdnum validates them with the same check digit and notes the algorithm 'has not been confirmed by an independent source'. [https://raw.githubusercontent.com/arthurdejong/python-stdnum/master/stdnum/lv/pvn.py]
- Hungary: the TAJ number is 9 digits with check digit k9 = (3k1+7k2+3k3+7k4+3k5+7k6+3k7+7k8) mod 10. [https://hu.wikipedia.org/wiki/T%C3%A1rsadalombiztos%C3%ADt%C3%A1si_azonos%C3%ADt%C3%B3_jel]
- Hungary: the adóazonosító jel is 10 digits: first digit 8, digits 2-6 = days since 1867-01-01, check digit = sum(d_i·i) mod 11, and a remainder of 10 is never issued. [https://hu.wikipedia.org/wiki/Ad%C3%B3azonos%C3%ADt%C3%B3_jel]
- EORI number = 2-letter code of the issuing EU country + a nationally unique identifier of up to 15 alphanumeric characters. [https://taxation-customs.ec.europa.eu/customs-4/customs-procedures-import-and-export-0/customs-procedures/economic-operators-registration-and-identification-number-eori_en]
- Netherlands: VAT numbers that fail the BSN 11-test can be valid under ISO 7064 mod 97-10 computed over 'NL' + the number (the sole-proprietor btw-id, valid since 2020-01-01). [https://raw.githubusercontent.com/arthurdejong/python-stdnum/master/stdnum/nl/btw.py]
- The revised EU driving licence Directive (EU) 2025/2205 was published 5 Nov 2025, entered into force 25 Nov 2025 and applies from 26 Nov 2029, repealing Directive 2006/126/EC. [https://en.wikipedia.org/wiki/European_driving_licence]

### Verifier notes
- Using python-stdnum as a CI oracle will give false failures in at least three places. (1) is_/kennitala.py on master still raises InvalidChecksum, although Þjóðskrá dropped the check digit on 18 Feb 2026. (2) no/fodselsnummer.py has no 2032 k1 rule (only one exact k1 is accepted) and rejects FH-numbers. (3) lt/asmens.py still enforces the check digit for codes starting with 9, which lt.wikipedia says have none. The oracle needs per-rule allowlists.
- django-localflavor is also outdated in places. is_ enforces mod 11 on kennitala. no rejects D- and H-numbers (they fail datetime.date) and has no 2032 rule. lv rejects '32' codes. si rejects EMŠO when r=1. Its 5.1 release now requires python-stdnum>=2.2, so it pulls in LGPL code.
- Faker is a weak source for regression data. The dk_DK provider has only vat_id (no CPR), and both dk_DK and fi_FI vat_id use bothify, so the 'DK########' and 'FI########' values are random digits that usually fail the checksum. no_NO has no D/H/FH numbers and no 2032 rule. lv_LV never produces '32' codes. Every Faker value must be filtered through the in-house validator.
- Missed MIT tool: stdnum-js (npm 'stdnum' 1.12.6, MIT, github.com/koblas/stdnum-js) covers all 16 countries in scope, for example DK VAT, NO fodsels/orgnr, IS kennitala, SE personnummer/orgnr, FI hetu/ytunnus, EE ik/registrikood, LV pvn, LT asmens/pvm, PL pesel/nip/regon, CZ/SK rc, HU anum, RO cnp/cui, BG egn/pnf/vat, HR oib, SI ddv/jmbg. It could serve as an MIT oracle, but check its provenance first: it mirrors python-stdnum's module layout.
- Missed MIT tool for the Excel question: presidio-structured 0.0.8 (MIT, released 2026-07-22, same org as Presidio) analyzes tabular data (pandas) or JSON at column level and maps whole columns to entity types. It is a ready precedent for the 'header as context for the whole column' recommendation.
- Excel recommendation, correction 1: openpyxl (3.1.5, MIT, last release 2024-06-28) does not return the displayed text. It returns the raw value plus the number_format string, so GDPR Guardian must apply the format itself. A custom format such as '0000000000' or '000000-0000', common on CPR or PESEL columns, gives the exact zero padding deterministically. Prefer that over guessing a pad and confirming with the checksum.
- Excel recommendation, correction 2: the zero-padding list (CPR, PESEL, rodné číslo, OIB) is incomplete. These IDs can also start with 0: NO fødselsnummer and D-numbers (DD), SE 10-digit personnummer (YY 00-09), SI EMŠO (DD, 13 digits), BG EGN (YY 00-09), IS kennitala (DD), old LV personas kods (DD) and HU TAJ. Digits past the 15th significant digit are zeroed by Excel when the number is entered and cannot be recovered: flag them, do not try to rebuild them.
- Excel omission with direct GDPR impact: an xlsx file holds personal data outside cell values. Examples: comments and threaded comments, headers and footers, sheet names, defined names, docProps/core.xml (creator, lastModifiedBy), pivotCacheRecords (a full copy of the source data), chart caches (strCache/numCache), cached results of formula cells, external-link caches, data-validation lists, hyperlinks, hidden sheets, rows and columns, and embedded images or objects. Anonymizing only cells leaks data. openpyxl also drops shapes, images and charts when it re-saves an existing file. Either edit the XML parts directly (sharedStrings, sheets, caches) or document those losses.
- RO CNP county codes: valid values are 01-48 (47 and 48 are the abolished Bucharest sectors 7 and 8), 51, 52, 70 and 80-83. 49 and 50 are invalid, so '01-52' is too broad.
- EU VAT recognizer: add the 'IM' prefix (IOSS numbers; stdnum routes 'eu' and 'im' to its OSS module), and fix the XI/GB rule to 'mod 97 remainder 0 or 42 (the +55 method)'. stdnum also accepts 55 for numbers >= 100.
- FI: 'used since 1 Jan 2023' should read 'legally valid since 1 Jan 2023'. fi.wikipedia says issuance with the new signs began later. The 'gender-neutral 2027' item is a plan ('tarkoitus muuttua sukupuolineutraaliksi 2027 mennessä'), not a statute in force. dvv.fi returned 403, so it is unverified at the primary source.
- NO 2032: k1 = 10 is rejected, so for some prefixes only 3 of the 4 candidate k1 values are valid digits. The test should be '(S1 + k1) mod 11 in {0,1,2,3}' with k1 a digit 0-9. The rule also covers D-numbers issued after 1 Jan 2032.
- LT codes starting with 9: put them in LENIENT as recommended, but note that python-stdnum disagrees (it still checks the digit). Document the source chosen (lt.wikipedia; the Lithuanian population-register spec was not checked).
- Sweden: SKV 704 is the 2007 edition. The samordningsnummer reform of 2022 (5-year validity, 'vilande' status) was not checked against Skatteverket here.
- Unverified in this run as well: the Directive (EU) 2025/2205 dates (EUR-Lex returned empty pages; only Wikipedia agrees), EHIC fields 6-8 and the card-number structure, and the BG 13-digit EIK rule. The shared WebSearch budget was already exhausted at the start of this check, so all checks used direct fetches of primary sources (GitHub raw source, PyPI JSON, skra.is, skatteetaten, the SKV PDFs, the EC customs page) plus Wikipedia.
