# licenses

### Key takeaways
- EXCEL (the user's question): no licence reason to exclude Excel. The useful readers are all permissive: python-calamine (MIT, built on the Rust calamine crate, reads xls/xlsx/xlsm/xlsb/ods), openpyxl (MIT), pandas (BSD-3-Clause), xlrd (BSD, .xls only), fastexcel (MIT), XlsxWriter (BSD-2-Clause), msoffcrypto-tool (MIT), defusedxml (PSF). The traps are the formula engines: pycel is GPL-3.0 and has CVE-2024-53924 (crafted formula can run code); formulas is EUPL-1.1+. So deciding whether to handle Excel is a technical and privacy question, not a legal one.
- EXCEL leak surface depends on the converter. MarkItDown reads every sheet, hidden ones included, with pandas+openpyxl (.xls via xlrd), then to_html, then Markdown. It does not handle comments or merged cells. Docling uses openpyxl with data_only=True (stored formula results, no formulas), handles merged cells and several tables per sheet, reads comments, and puts hidden sheets in an INVISIBLE layer. Docling converts .xls through LibreOffice (MPL-2.0).
- Biggest licence traps in the candidate list: spaCy fr_core_news_* (LGPLLR), es_core_news_* (GPL-3.0), it_core_news_* (CC-BY-NC-SA-3.0); PyMuPDF and pymupdf4llm (AGPL-3.0 or commercial; pymupdf4llm 2.0 is now an empty placeholder); html2text (GPL-3.0-or-later); extract-msg (GPL); the Flair 'classic' models (non-commercial only); piiranha (CC-BY-NC-ND-4.0); libpostal model data and OSM extracts (ODbL); and the NVIDIA Open Model License (custom terms).
- Weights licensed Apache-2.0 can still sit on restricted data. OpenMed's French PII models are Apache-2.0 but trained on ai4privacy/pii-masking-400k, which is academic/non-commercial only and needs a written licence for derivatives. GLiNER2 training data (paper) and knowledgator gliner-bi v2.0 pre-training data were annotated by GPT-4o. knowledgator gliner-stream-pii-v1.0 runs on a Qwen3-0.6B causal backbone, which breaks the no-LLM rule.
- Cleanest NER weights found: urchade/gliner_multi-v2.1 and gliner_multi_pii-v1 (Apache-2.0; base mdeberta-v3-base, MIT; training data urchade/pile-mistral-v0.1 and synthetic-pii-ner-mistral-v1, both tagged Apache-2.0, generator not documented). The v0/v1 GLiNER models were CC-BY-NC-4.0. For French: cmarkea/distilcamembert-base-ner and Jean-Baptiste/camembert-ner (MIT, trained on WikiNER, which is CC-BY-4.0 on figshare).
- LGPL components are python-stdnum (LGPL-2.1-or-later) and pycountry (LGPL-2.1-only, also pulled in by schwifty). (a) As a pip dependency nothing is distributed, so there is in practice no obligation. (b) In a Docker image: ship the licence and notices, keep the .py source (or a written offer), let users swap the library, and publish any changes to it under LGPL. (c) SaaS: LGPL-2.1 has no network clause (Section 0: running is not restricted). Checksum algorithms are ideas, which copyright does not protect (Directive 2009/24/EC Art. 1(2)), so re-implement them from official specs without copying code.
- CPU-only: the default PyPI torch wheels on Linux pull nvidia-* packages (LicenseRef-NVIDIA-Proprietary). Use the CPU wheel index, or better, ONNX Runtime (MIT) alone at runtime. Intel Hyperscan 5.5 and later is proprietary; the python 'hyperscan' wheels statically link Vectorscan (BSD-3-Clause), which is fine.
- Gazetteers: INSEE Fichier des prénoms (1900–2025, July 2026 edition), INSEE COG and the BAN are Licence Ouverte 2.0: free, attribution means naming the source and the last-update date. GeoNames is CC-BY-4.0 and Wikidata is CC0. OSM is ODbL (share-alike on derived databases), so do not bundle it. No dedicated INSEE surname dataset was found. The Fichier des personnes décédées is Licence Ouverte 2.0 but holds personal data and carries an opposition-list condition.
- Crypto: cryptography 50.0.2 (Apache-2.0 OR BSD-3-Clause) covers HMAC and AES for the reversible vault. Avoid ff3: the package itself reports that NIST withdrew FF3 (SP 800-38G Rev.1 draft 2, Feb 2025). Use HMAC-SHA256 with an ephemeral key, or AES-SIV/FF1 if format-preserving output is needed.
- Apache-2.0 §4 and CC-BY-4.0 §3(a) obligations only start when you distribute (pip sdist/wheel that vendors code, Docker image, bundled weights or data). SaaS-only use creates no notice obligations, except under AGPL, which is excluded anyway.

### Recommendations
- Excel: handle it. Reader stack: python-calamine (MIT) for values from xls/xlsx/xlsm/xlsb/ods, plus openpyxl (MIT, read_only, with defusedxml) only for xlsx extras: comments/notes, hidden or very hidden sheets, docProps author/lastModifiedBy, named ranges, headers/footers, hyperlinks, data-validation lists. Output Markdown, one table per sheet. Anonymize hidden sheets, comments and metadata, or drop them explicitly with a warning; never pass them through silently.
- Excel detection: classify each column (header keywords per country pack plus checksum hit rate over sample cells), then apply the label to the whole column. This is faster and more consistent than running NER on every cell. Run NER only on free-text columns. Never evaluate formulas (no pycel or formulas); use stored formula results. Reject or ignore VBA. Cap cell count and archive size against zip bombs.
- Re-implement every national ID validator in-house under MIT from official specs (NIR key = 97 − (n mod 97), Luhn for SIREN/SIRET, ISO 7064/13616 mod-97 for IBAN). Cite the spec URL in each module and write test vectors from spec examples, not from python-stdnum's tests. Keep python-stdnum out of runtime deps (or only as an opt-in extra for cross-checking).
- Replace pycountry with iso3166 (MIT) plus Babel (BSD-3-Clause). Drop schwifty or isolate it in an extra, since it pulls pycountry (LGPL-2.1-only). Ban PyMuPDF/pymupdf4llm, html2text, extract-msg, pycel, flair classic models, and the spaCy fr/es/it models.
- Keep a MODEL_LICENSES registry (YAML) per weight: SPDX licence, base model, training datasets with their licences, generator LLM if any, HF revision SHA. CI fails if any field is missing. Do not put weights in the pip wheel; download on first use with a pinned revision. The Docker image bundles only models rated 'ok'.
- Default NER set: urchade/gliner_multi_pii-v1 (multilingual, Apache-2.0) and cmarkea/distilcamembert-base-ner (FR, MIT), exported to ONNX int8 and run with onnxruntime. For a cleaner-provenance custom model, fine-tune mdeberta-v3-base or CamemBERT on WikiNER (CC-BY-4.0), Nemotron-PII (CC-BY-4.0, EN) and Faker-templated synthetic data with INSEE names. No LLM is involved at any stage.
- CI licence policy: pip-licenses --allow-only 'MIT;BSD;Apache;ISC;PSF;Python Software Foundation;MPL-2.0 (reviewed)' plus a reviewed exceptions file; reuse lint for our sources; ScanCode on the final Docker image; generate THIRD_PARTY_NOTICES (licence and NOTICE texts) and DATA_ATTRIBUTION (Insee + date, GeoNames CC-BY, WikiNER CC-BY) into the image and docs.
- Install torch (if at all) from the PyTorch CPU index so no nvidia-* proprietary wheels enter the image; prefer onnxruntime-only runtime images. Use Vectorscan-based wheels only, never Intel Hyperscan 5.5 or later.
- Pseudonymization: HMAC-SHA256 with a per-session ephemeral key (cryptography) for consistent [PERSONNE_n] indices; keep the reversible map in memory with a TTL. Do not use ff3 (FF3 withdrawn).

### Risks
- Training-data provenance behind permissive weights: GPT-4o-annotated data (GLiNER2, knowledgator bi v2.0) may breach OpenAI terms that bind the trainer. Downstream users are not parties to those terms, so the legal risk to us is low but non-zero, and enterprise procurement may flag it. Undisclosed datasets (knowledgator gliner-pii, E3-JSI generator) cannot be assessed at all.
- Licence metadata drifts and contradicts itself: ai4privacy open-pii-masking-500k shows CC-BY-4.0 on its card but 'other' in the API; docling-models carries two licences with no per-model mapping; flair models have no licence tag. CI that reads only metadata will miss these, so ScanCode and the manual MODEL_LICENSES registry are needed.
- A transitive LGPL dependency (schwifty → pycountry) can enter silently. The opencv-python-headless wheels (via RapidOCR) bundle FFmpeg under LGPL-2.1, which needs notices in Docker images.
- Maintenance risk in Excel and parsing deps: openpyxl last released 2024-06-28; defusedxml 2021; xlrd .xls-only; odfpy 2020; flashtext 2018; liccheck 2023. LLM Guard and anjana pin exact versions that clash (presidio-anonymizer needs cryptography<49 while latest is 50.0.2).
- Excel-specific leak paths if not handled: hidden or very hidden sheets, cell comments and threaded comments, docProps author fields, pivot caches (keep a full copy of the source data), formulas that contain literal strings, chart caches, named ranges, external links, embedded OLE objects. MarkItDown ignores comments; Docling keeps hidden sheets in a separate layer.
- Markdown output for big spreadsheets is token-heavy and loses types; a large sheet could exceed the downstream LLM context and push users to bypass the service.
- Gazetteers built from INSEE death records contain personal data and carry an opposition-list obligation; shipping raw records would itself be a GDPR and compliance problem for a privacy product.
- NVIDIA Open Model License can be updated unilaterally and rights terminate if guardrails are bypassed; unsuitable as a default dependency.

### Open questions

- Will GDPR Guardian ship a Docker image or on-prem bundle to customers (distribution, so LGPL, Apache NOTICE and CC-BY obligations apply), or only run as SaaS plus a pip package (almost no obligations)?
- Does 'no LLM anywhere' also exclude LLMs used at training time to generate synthetic data? The answer changes whether GLiNER2, knowledgator bi v2 and our own synthetic data generation are acceptable.
- Not verified (WebSearch quota ran out, and gnu.org, EUR-Lex and curia were rate-limited or returned no readable text): the GNU GPL FAQ wording on LGPL with Python and on server use; the CJEU C-406/10 SAS Institute operative part; TIGER corpus and OntoNotes terms behind the MIT spaCy de/en models; OSCAR licence; DocLayNet/PubTabNet licences; schwifty bank-registry data licence; CLDR notice inside Babel.

### Verification ({'confirmed': 96, 'refuted': 2})
- [refuted] 66. xlrd is BSD-3-Clause
  - correction: The xlrd LICENSE has two parts: a 3-clause BSD licence (Machin/Lingfo) and a 4-clause BSD-style licence (David Giffin, 2001) with an advertising-acknowledgement clause. It is still MIT-compatible but is not plain BSD-3-Clause, and the acknowledgement must be carried. PyPI says only 'BSD'. xlrd 2.0.2 is .xls only.
  - src: https://github.com/python-excel/xlrd/blob/master/LICENSE
- [refuted] Recommendation: openpyxl read_only mode for comments/notes and other xlsx extras
  - correction: openpyxl docs: 'Comments are not currently supported if read_only=True is used.' openpyxl also does not parse threadedComments (Docling reads that XML itself). Use normal mode behind size and cell caps, or parse xl/comments*.xml and xl/threadedComments/*.xml directly with a hardened XML parser.
  - src: https://openpyxl.readthedocs.io/en/stable/comments.html
### Verifier notes
- Web search budget for this turn was exhausted after my first query, so all checks were done with direct WebFetch of primary sources (PyPI JSON API, GitHub raw files, HF cards, insee.fr, data.gouv API). Some omissions (an INSEE surname dataset, WikiNER's figshare licence, which returned 403) could not be verified.
- EXCEL recommendation error: openpyxl read_only=True does not load comments (official docs), so the proposed 'openpyxl read_only for comments/notes' stack would silently miss comments, which is the leak the recommendation is meant to prevent. Threaded comments (modern Excel) are not parsed by openpyxl in any mode. Either open in normal mode with strict size and cell caps, or read xl/comments*.xml, xl/threadedComments/*.xml, xl/persons/person.xml, docProps/core.xml and docProps/app.xml directly from the zip with a hardened parser. Also add pivot caches, external links, chart caches, embedded objects, sheet names and custom XML parts to the leak checklist.
- Docling's Excel backend does not extract docProps (author, lastModifiedBy), headers/footers, defined names, data validation or hyperlink targets, and does not check for VBA. It uses a hardened lxml parser, not defusedxml. Very hidden sheets are converted into the INVISIBLE layer. MarkItDown passes hidden sheets through as ordinary tables.
- xlrd licence is not plain BSD-3-Clause: it also includes a 4-clause BSD-style David Giffin licence with an advertising clause. Since python-calamine reads .xls natively, xlrd (and LibreOffice for .xls) can be dropped entirely.
- CI policy recommendation is broken as written. pip-licenses --allow-only matches full names only by default, so 'MIT' will not match 'MIT License', 'BSD' will not match 'BSD License' or 'BSD-3-Clause', and 'MPL-2.0 (reviewed)' matches nothing. Add --partial-match or list exact strings, and use --from=all or --from=expression: 5.5.0 added PEP 639 License-Expression support, and many packages now ship only License-Expression (pandas, pypdf, iso3166, docling, torch) or only classifiers. Packages with no licence metadata at all (e.g. nvidia-cudnn-cu13) appear as UNKNOWN and must fail the check.
- Checksum recommendation omits two real-world exceptions: Corsican NIRs (2A becomes 19, 2B becomes 18 before 97 - n mod 97) and La Poste SIRETs (SIREN 356000000: digit sum divisible by 5, except head office 35600000000048). A clean-room implementation that misses these will reject valid identifiers.
- 'No LLM is involved at any stage' is inaccurate for training data. Nemotron-PII was synthesized with NVIDIA NeMo Data Designer (LLM-based). E3-JSI/synthetic-multi-pii-ner-v1 was prompt-generated. The recommended default urchade/gliner_multi_pii-v1 was fine-tuned on synthetic-pii-ner-mistral-v1, and gliner_multi-v2.1 on pile-mistral-v0.1 (both cards are empty, but the names imply Mistral-LLM generation or annotation). Runtime is LLM-free, but provenance statements should say 'LLM-generated or annotated training data' where applicable.
- knowledgator gliner-pii-base-v1.0: the config shows backbone microsoft/deberta-v3-small (MIT), but training data are undocumented. gliner-bi-base-v2.0 base is BAAI/bge-base-en-v1.5 plus ModernBERT/Ettin, with GPT-4o-annotated FineFineWeb pre-training.
- INSEE data: the data.gouv 'fichier-des-prenoms-depuis-1900' dataset is stale (points to the 2023 edition, 1900–2022). The correct 1900–2025 file (published 16/07/2026) is insee.fr/fr/statistiques/8595130, so download from INSEE directly. The COG on data.gouv is tagged fr-lo (Licence Ouverte v1.0), while INSEE's mentions légales apply LO 2.0. Attribution should read 'Source : Insee' plus the last-update date.
- Fichier des personnes décédées: the data.gouv page states the records are not personal data (consistent with GDPR recital 27), so the takeaway that it 'holds personal data' is contestable. The binding condition is removing records listed in INSEE's opposition file, which makes bundling a snapshot operationally awkward (it must be refreshed).
- torch 2.14.1 now depends on cu13 packages (nvidia-cudnn-cu13, nvidia-nccl-cu13, nvidia-nvshmem-cu13, nvidia-cusparselt-cu13) on Linux. gliner 0.2.29 lists torch as a core (non-optional) dependency, so even an ONNX-only runtime pulls torch unless gliner is replaced with a thin ONNX inference wrapper or installed with --no-deps against the CPU index.
- Notices omissions: Babel bundles CLDR data (Unicode licence). python-calamine, fastexcel and pypdfium2 wheels statically bundle Rust or C dependencies with their own notices. The Vectorscan LICENSE also includes a BSD-2-style Intel CRC32 notice and Google Test BSD-3. All belong in THIRD_PARTY_NOTICES.
- cryptography provides AES-SIV (AESSIV) but not FF1. 'AES-SIV/FF1' therefore needs a separate FF1 library with its own licence check, or FF1 should be dropped. NIST's SP 800-38G Rev.1 2nd draft keeps only FF1.
- CC-BY-4.0 'Share' covers making material available to the public, not just distribution. A SaaS that returns GeoNames or WikiNER-derived data verbatim may still trigger attribution, so 'SaaS creates no notice obligations' is too absolute for CC-BY data.
- PyMuPDF 2.0 and the pymupdf4llm 2.0 placeholder were both released 2026-10-19. pymupdf4llm functionality now lives inside AGPL PyMuPDF, and the placeholder carries no licence metadata, so scanners may not flag it. Ban both by name.
- Legal citation: the Directive 2009/24/EC source used is the UK-retained copy on legislation.gov.uk. Cite EUR-Lex 32009L0024 and CJEU C-406/10 SAS Institute (functionality, programming language and data-file formats are not protected) as the EU primary sources for re-implementing checksum algorithms.
