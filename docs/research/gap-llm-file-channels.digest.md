# gap-llm-file-channels

Topic: How spreadsheets actually reach LLM providers, and which channels GDPR Guardian can intercept
Why: The proxy design covers only text messages, tool results and tool-call arguments, and MCP covers only file references. In practice spreadsheets mostly reach LLMs in three ways. One is API file uploads: Files APIs, code-execution containers, base64 document blocks. Another is web-UI uploads on chatgpt.com, claude.ai and Le Chat. The third is Office add-ins: Copilot in Excel, Claude for Excel, Gemini in Sheets. Neither the proxy nor MCP sees the last two, and nobody researched the first. This decides whether Excel support is reachable at all in proxy mode, and whether a browser-extension or add-in surface is needed.

### Key takeaways
- Verdict on Excel: support it in v1. Spreadsheets reach LLMs mostly through channels GDPR Guardian can intercept (API file inputs, Files APIs, code-execution containers, and the Claude for Excel gateway mode). The in-suite assistants (M365 Copilot in Excel, Gemini in Sheets) cannot be intercepted, so do not promise coverage for them.
- OpenAI Responses input_file accepts xlsx/xls/csv/tsv by file_data (base64), file_id or file_url, up to 50 MB per request. The API parses only the first 1,000 rows per sheet and adds a model-generated summary. Chat Completions accepts only PDF. file_search does not list xlsx or csv.
- Anthropic: the document block accepts only PDF and text/plain. Excel must be converted to text first, or uploaded through the Files API (multipart POST /v1/files) and referenced with container_upload for code execution. The Files API and code execution are both marked as not ZDR-eligible, which strengthens the case for anonymizing before upload.
- Gemini: only PDF gets document vision; other types are extracted as text. File API uploads use a resumable two-step protocol (the upload URL comes back in x-goog-upload-url), and files are stored for 48 hours. Code execution 'works best with text and CSV', so swapping an xlsx for an anonymized CSV is natural.
- Mistral: OCR and document_url accept PDF, PPTX, DOCX and images. xlsx is not listed. The Files API purposes are fine-tune, batch, ocr and agentic_safety. A public document_url is fetched by Mistral itself, which bypasses a proxy unless the proxy fetches the file and inlines it.
- Azure OpenAI Responses: input_file is documented for PDF only, and purpose=user_data is not supported (use 'assistants'). The code interpreter container accepts xlsx and csv. Regions include swedencentral and westeurope.
- Proxy feasibility: inline base64 files are easy to handle (decode, anonymize, re-encode). Uploads made with file_id need multipart parsing, buffering of chunked OpenAI /v1/uploads (up to 8 GB), rewriting of the Gemini upload URL, and a mapping from file_id to anonymization session. Proxy-minted IDs work, as LiteLLM's encoded file IDs do. file_url and GCS URIs bypass the proxy unless it fetches and inlines them.
- Swapping files: an anonymized rebuilt xlsx, or a CSV per sheet, keeps code interpreter and code execution working (pandas and openpyxl are preinstalled). Keeping the pseudonymization consistent preserves joins and lookups. Generated outputs are only partly reversible: CSV/xlsx downloads can be rehydrated through the files/containers content endpoints, but rendered PNG charts cannot.
- Claude for Excel (GA for Pro/Max/Team/Enterprise) officially supports an 'LLM gateway' mode. The gateway must expose POST /v1/messages and GET /v1/models in Anthropic format, forward anthropic-version, and return CORS for https://pivot.claude.ai. In that mode file uploads are disabled, so workbook data arrives as JSON text, which GDPR Guardian can anonymize and rehydrate.
- M365 Copilot in Excel is reachable only through Purview. Purview can exclude labelled files, and blocking prompts that contain sensitive info types is in preview. Microsoft states that Purview DLP 'can't scan the contents of files that you upload directly into prompts'. GDPR Guardian can at best produce an anonymized copy beforehand.
- Enterprise GenAI-DLP products mostly block, warn or audit; few redact. Purview Edge, network and endpoint DLP allow or block only, and inline evaluation is capped at 4 MB of text and 3 MB per file. Zscaler documents blocking and browser isolation. Akamai Workforce Protector (formerly LayerX) is a browser extension that can 'warn, redact, block'. Nightfall documents block/notify for browser uploads and paste, and redaction only in its API.
- MV3 browser extension: request bodies cannot be modified. declarativeNetRequest offers block, redirect, allow, upgradeScheme and modifyHeaders only, and webRequestBlocking is limited to policy-installed extensions and cannot change bodies anyway. The workable route is capture-phase content scripts (paste, drop, input change; File swapped through DataTransfer) plus fetch/XHR patching in the MAIN world. This is feasible but fragile against UI changes.
- Office.js add-in: it can read cell values through the Excel API. Excel on the web caps payloads at 5 MB, and one read is limited to 5,000,000 cells. getFileAsync returns only a PDF on the web (Compressed works on desktop only). The add-in can open an anonymized copy with Excel.createWorkbook(base64). It can be deployed through the Integrated apps portal without a Marketplace listing, and can take 24-72 hours to appear.
- MIP/IRM-encrypted Office files cannot be read without the tenant's Rights Management service: the client sends the policy to Azure RMS to obtain a use license holding the AES content key. Password-encrypted files can be decrypted with msoffcrypto-tool (MIT) when the password is supplied.
- Label metadata leaks tenant identity. In custom properties, MSIP_Label_<labelGUID>_SiteId holds the Microsoft Entra tenant ID, and _Name holds the label name. With co-authoring enabled, the same data moves to a LabelInfo part with a siteId attribute. Any rebuilt xlsx must strip both. Markdown or CSV output drops them naturally.
- Interception matrix, part 1 (Y=yes, P=partial or fragile, N=no, M=manual pre-anonymization by the user). (1) API inline file: REST M, Proxy Y, localMCP N, hostedMCP N, Ext N, Office N. (2) API upload + file_id: Proxy Y, others M/N. (3) API file by URL: Proxy P (fetch and inline). (4) Code-interpreter containers: Proxy Y for inputs, P for outputs. (5) Agent reading a local xlsx: localMCP Y, hostedMCP P, Proxy Y if the base URL can be set.
- Interception matrix, part 2. (6) Claude for Excel in gateway mode: Proxy Y. (7) Claude for Excel with a Claude account, and the desktop chat apps: N (M only). (8) Web-chat file uploads: Ext P, REST/MCP M, Proxy N (would need TLS interception). (9) Pasting copied cells into web chat: Ext Y, Office add-in Y. (10) M365 Copilot in Excel: N. (11) Gemini in Sheets: N.

### Recommendations
- Decision: handle Excel in v1 (.xlsx, .xlsm with VBA dropped, .xls, .ods, .csv/.tsv). Default output is Markdown tables per sheet, consistent with constraint 5. Add an optional anonymized CSV per sheet for code-interpreter use. Defer rebuilt xlsx output until the hidden-content stripping described below is implemented.
- v1 surfaces for Excel: (a) REST, where the file goes in and Markdown or CSV comes back; (b) an OpenAI/Anthropic/Azure-compatible proxy handling inline file inputs and Files API multipart uploads; (c) Claude for Excel gateway compatibility; (d) a local MCP tool anonymize_file(path) returning Markdown. Hosted-MCP file ingestion, the browser extension and the Office add-in come in v2.
- Make the proxy a valid 'LLM gateway' for Claude for Excel: Anthropic Messages format, GET /v1/models, anthropic-version forwarding, CORS for https://pivot.claude.ai on every response including errors, and x-api-key or Bearer auth. Anonymize tool_result cell payloads, and rehydrate tool_use inputs (including streamed input_json_delta) so real values are written back into cells.
- In the proxy, rewrite every file reference into content the proxy controls. Decode and re-encode base64 inputs (input_file.file_data, document base64/text, inline_data). Fetch file_url and document_url targets and inline them. Parse multipart /v1/files and container-file uploads, and buffer chunked OpenAI /v1/uploads before anonymizing. Rewrite Gemini's x-goog-upload-url so the bytes come back through the proxy.
- Keep the file_id mapping consistent: issue proxy-side file IDs (LiteLLM-style encoded IDs) bound to the ephemeral session key. Set provider expiry no longer than the mapping TTL (OpenAI expires_after; Anthropic expires_in_seconds, minimum 1 h). Delete provider files at session end. Never accept raw provider file_ids from end users, as Anthropic itself warns.
- Swapping formats: for OpenAI input_file and Anthropic code execution, send an anonymized CSV per sheet in v1, since both accept CSV. For Gemini, prefer CSV. For OpenAI file_search, send Markdown, because xlsx/csv are unsupported there. Keep numeric non-identifying columns untouched so pandas data types survive.
- Use column-level detection for CPU throughput. Classify each column from header context words and a value sample, using checksum validators (IBAN, NIR, SIREN/SIRET) on the sample. Apply one deterministic operator per column, and run GLiNER/NER only on free-text columns and comments. Keep pseudonyms consistent across sheets, files and prompts within a session so joins and VLOOKUP-style keys still work.
- Before emitting anything, scrub or anonymize hidden spreadsheet content: hidden sheets, rows and columns; comments, notes and threaded comments; headers and footers; defined names; data-validation lists; pivot caches; external-link caches; chart titles and caches; docProps (creator, lastModifiedBy); MSIP_Label_* custom properties; the LabelInfo part (tenant siteId). Markdown or CSV output avoids most of this; a rebuilt xlsx does not.
- Encryption policy: decrypt password-protected files only when the caller supplies the password (msoffcrypto-tool, MIT). Reject IRM/MIP-encrypted files with an explicit error ('decrypt in Office first or export values'). Never attempt MIP SDK integration in the hosted multi-tenant service.
- Set expectations in docs: GDPR Guardian cannot cover M365 Copilot in Excel, Gemini in Sheets, Claude for Excel with a Claude account, or desktop chat apps. Recommend Purview label-based Copilot exclusion, or the Claude for Excel gateway mode, for those organizations.
- For v2 browser coverage, start with paste interception (TSV/HTML clipboard from Excel, the highest-volume path), then file swapping on chatgpt.com, claude.ai, chat.mistral.ai and gemini.google.com. Call the EU-hosted or localhost GDPR Guardian REST API. Study PasteGuard (Apache-2.0) and AI-Safe-Plugin (MIT) before writing code; force-install through enterprise policy.
- Cap work per file. OpenAI parses only the first 1,000 rows per sheet anyway, Purview inline DLP evaluates only up to 3 MB per file, and Markdown tables explode token counts. Expose max_rows and max_cells per sheet, and report truncation in the response.

### Risks
- Rehydration gaps: rendered charts and images from code interpreter or code execution contain placeholders in their pixels and cannot be restored. Only text formats (CSV, xlsx, md, json) can be rehydrated on download.
- Writing placeholders back into a live workbook. With Claude for Excel in gateway mode, a missed rehydration in tool_use inputs writes [PERSONNE_1] into real cells. Streaming JSON deltas make token-level rehydration harder.
- Session lifetime mismatch: Anthropic containers live up to 30 days and Files persist until deleted, while GDPR Guardian mappings are ephemeral. Follow-up requests may reference provider-side anonymized files after the mapping is gone, leaving answers that cannot be rehydrated.
- Anthropic Files API and code execution are not ZDR-eligible, and Claude for Excel keeps backend data up to 30 days. Any detection miss is therefore retained at the provider.
- Browser-extension brittleness: chat UIs change often, and uploads may go through encoded payloads or dynamic endpoints (as Microsoft notes for ChatGPT). MAIN-world patching can be broken or detected by the page. Maintenance cost is high for an OSS project.
- Spreadsheet leakage through hidden structures (pivot caches, comments, defined names, hidden sheets, chart caches, document properties, MSIP SiteId tenant GUID) if an xlsx is rebuilt rather than converted.
- Analytical utility loss: replacing values in key columns, dates or amounts can break formulas, type inference and aggregations. Over-anonymizing numeric columns makes code interpreter results meaningless.
- Rule-based column classification on CPU can mislabel columns with ambiguous headers or mixed content; NER on free text adds latency on very large sheets.
- Commercial and OSS competition: PasteGuard (Apache-2.0) already pairs a proxy with an extension and uses GLiNER plus checksums; Akamai Workforce Protector claims redaction. GDPR Guardian needs EU hosting, country packs and Markdown file handling to stand apart.
- openpyxl has not released since 2024-06-28; relying on it to rebuild xlsx carries maintenance risk.
- The proxy cannot see provider-side fetches of public URLs or GCS URIs (OpenAI file_url, Mistral document_url, Vertex gs://) unless it fetches and inlines them. Private GCS URIs cannot be fetched at all.

### Open questions
- No published figures were found on the share of enterprise files that are MIP/IRM-encrypted. The web-search budget was exhausted mid-task, so this needs a follow-up search (Microsoft Data Security Index, Netskope Cloud and Threat reports).
- The OpenAI help center and openai.com returned HTTP 403. Still unverified: ChatGPT web upload limits for spreadsheets, whether an official 'ChatGPT for Excel' add-in exists, and whether it supports a custom gateway.
- The interception mechanisms of Netskope and Prompt Security (SentinelOne), and whether they redact or only block, were not confirmed from primary docs.
- The exact payload shape Claude for Excel sends through a gateway (cell data in tool_result blocks, tool names and schemas) should be captured with a test gateway before designing rehydration.
- Does Mistral Le Chat (or Le Chat Enterprise self-hosted) accept xlsx uploads, and can it be pointed at a customer gateway?
- Does the MIP SDK NuGet 'MIT' license also cover its bundled native binaries, and what are the separate service terms? This only matters if on-prem IRM decryption is ever considered.
- Does Excel.createWorkbook(base64) work in Excel on the web for anonymized copies, and with what size limits?
- Should GDPR Guardian's Markdown-only output rule be relaxed for spreadsheets so CSV can be returned for code-interpreter workflows? This is a product decision.

### Critical claims
- OpenAI Responses API input_file supports Excel (.xlsx/.xls), CSV, TSV and others via file_data, file_id or file_url. For spreadsheets it parses up to the first 1,000 rows per sheet and adds model-generated summary and header metadata. Chat Completions supports only PDF. The limit is 50 MB per file and per request. [https://developers.openai.com/api/docs/guides/file-inputs]
- OpenAI POST /v1/files is multipart/form-data with purposes including user_data and assistants, individual files up to 512 MB, and an optional expires_after. The Uploads API accepts up to 8 GB in total and an Upload expires one hour after creation. [https://developers.openai.com/api/reference/resources/files/methods/create]
- OpenAI file_search's supported file types do not include .xlsx or .csv. [https://developers.openai.com/api/docs/guides/tools-file-search]
- Anthropic's Files API maps only PDF and text/plain to document blocks. Anthropic advises converting .xlsx to text, or uploading it for the code execution tool with a container_upload block. The Files API is GA with ZDR 'not-eligible', and files are scoped to the workspace. [https://platform.claude.com/docs/en/build-with-claude/files]
- Anthropic's code execution tool processes CSV and Excel (.xlsx, .xls) uploaded through the Files API. openpyxl, xlrd and xlsxwriter are preinstalled, and containers expire 30 days after creation. [https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool]
- Gemini document vision only meaningfully understands PDFs; other types are extracted as text. Files API uploads are stored for 48 hours, up to 2 GB per file and 20 GB per project. [https://ai.google.dev/gemini-api/docs/files]
- Azure OpenAI Responses documents input_file for PDF only and does not support purpose user_data. Code Interpreter containers accept .csv and .xlsx and expire after 20 minutes of inactivity. [https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/responses]
- Claude for Excel can route through an organization's LLM gateway. In Anthropic format the gateway must expose POST /v1/messages and GET /v1/models and return Access-Control-Allow-Origin: https://pivot.claude.ai. File uploads are not available in third-party-platform mode. [https://claude.com/docs/office-agents/third-party-platforms]
- Purview DLP for Microsoft 365 Copilot cannot scan the contents of files uploaded directly into prompts; it checks only the typed prompt text. It can prevent Copilot in Excel from processing files that carry chosen sensitivity labels. [https://learn.microsoft.com/en-us/purview/dlp-microsoft365-copilot-location-learn-about]
- Purview inline DLP in Edge for Business evaluates up to 4 MB of text for uploadText and files up to 3 MB for uploadFile. Microsoft notes that ChatGPT may send content in encoded form or through dynamically generated endpoints. [https://learn.microsoft.com/en-us/purview/dlp-browser-dlp-learn]
- In Manifest V3, webRequestBlocking is available only to policy-installed extensions, and declarativeNetRequest actions are limited to block, redirect, allow, upgradeScheme, modifyHeaders and allowAllRequests. No body modification is possible. [https://developer.chrome.com/docs/extensions/reference/api/webRequest]
- Excel on the web has a 5 MB payload limit for add-in requests and responses, and a range read is limited to 5,000,000 cells. [https://learn.microsoft.com/en-us/office/dev/add-ins/concepts/resource-limits-and-performance-optimization]
- In Office on the web, Document.getFileAsync in Excel supports only FileType.Pdf; Compressed is available only on Windows and Mac. [https://learn.microsoft.com/en-us/javascript/api/office/office.document]
- The MIP label metadata attribute SiteId holds the Microsoft Entra tenant ID, written as MSIP_Label_<GUID>_SiteId. With protected co-authoring enabled, metadata moves to the LabelInfo stream, whose label element has a required siteId attribute. [https://learn.microsoft.com/en-us/information-protection/develop/concept-mip-metadata]
- To open an RMS-encrypted document, the client sends the document policy to the Azure Rights Management service, which returns a use license containing the AES content key re-encrypted for the user. Decryption therefore needs the tenant's service. [https://learn.microsoft.com/en-us/azure/information-protection/how-does-it-work]

### Verifier notes
- Web search budget ran out partway through; the later checks used WebFetch on known URLs only. These were not checked: Zscaler and Nightfall behaviour, Excel.createWorkbook(base64), 'Hosted Shell', and the AI-Safe-Plugin LICENSE file (only the GitHub sidebar was seen).
- Claude for Excel in gateway mode, oversimplification: the takeaway says workbook data arrives only as JSON text because file uploads are disabled. Two things on claude.com/docs/office-agents point the other way. First, there is a 'file.upload' kill switch under disabled_features. Second, data-storage.md says the add-in keeps 'every file that a user attaches to the chat in Outlook or in a third-party platform deployment', and that attachments go to the configured gateway endpoint. Plan for base64 image/document blocks at the gateway, and treat inline attachments as possible until a test shows otherwise.
- Claude for M365 omissions. (1) The same gateway also serves Word, PowerPoint and Outlook, not only Excel. (2) Besides the Anthropic format, the gateway can speak bedrock (/model/{id}/invoke...) or vertex (:rawPredict) format, and Foundry or Vertex direct can be pointed at a custom gateway through azure_base_url or gcp_base_url. Handling only the Anthropic format leaves those deployments uncovered. (3) CORS: '*' is accepted, the header must appear on errors too, and Access-Control-Allow-Headers must list 'authorization' explicitly. (4) Admins can add their own MCP servers (mcp_servers key) and set label-scoped access_policies. This could be a second integration point for GDPR Guardian. (5) A gateway token placed in the manifest URL query string is logged by pivot.claude.ai. Advise putting it in the URL fragment (#gateway_token).
- Anthropic omissions. A CSV can go through the Files API as text/plain and be used in a document block (with citations), not only through container_upload. Anthropic says to create one workspace per tenant for multi-tenant Files API use; this matters for a hosted multi-tenant GDPR Guardian that holds provider keys. Expiry and deletion are not a guaranteed erasure: content 'may be retained for a limited period ... for safety review', and deleted files may persist in active calls. Docs should not present 'delete provider files at session end' as GDPR erasure.
- Gemini figures are out of date. Inline data is now 100 MB per request (50 MB for PDF). External HTTP or signed URLs (15 MB) are fetched by Google itself. GCS URI registration lasts up to 30 days. Code execution has a 30 s runtime cap and includes openpyxl and pandas.
- OpenAI details. input_file also accepts .xla/.xlb/.xlc/.xlm/.xlt/.xlw/.iif and Google Sheets, but not .ods or .xlsb, so these must be converted. Files sent as model input are auto-uploaded into the code_interpreter container. The Uploads API lists purposes assistants, batch, fine-tune and vision; user_data is not listed.
- Purview Edge for Business: the list of supported unmanaged AI apps (page updated 2026-10-06) includes ChatGPT, Gemini, DeepSeek, Copilot and others, but not claude.ai or Mistral Le Chat. That strengthens the case for the v2 extension on those two sites. Supported actions are allow or block (audited). Enforcement needs Edge 144 or later and Intune-managed devices.
- The claim 'Markdown or CSV output avoids most hidden content' is wrong for hidden sheets, rows and columns. markitdown's XlsxConverter calls pd.read_excel(sheet_name=None, engine='openpyxl') with no visibility filter, so hidden sheets and rows are emitted into the Markdown. Comments, docProps and MSIP labels are dropped, but hidden-cell values are not. GDPR Guardian must filter or anonymize hidden sheets, rows and columns on the Markdown and CSV path too.
- openpyxl (MIT) has had no release since 3.1.5 (2024-06-28). It also drops shapes, images and charts when a workbook is re-saved, which adds risk to the deferred 'rebuilt xlsx' output. python-calamine (0.9.0, MIT) is a faster read-only option and also reads .xlsb and .ods. Add .xlsb to the v1 format list.
- MIP metadata nuances. Under protected co-authoring, extended or custom label attributes are still written to docProps/custom.xml, and LabelInfo lives in the Sensitivity Label Information part (docMetadata/LabelInfo.xml). Strip both, as the recommendation says. For IRM-encrypted files, the LabelInfo stream sits in cleartext in the OLE \x06DataSpaces\TransformInfo storage. A rejected encrypted file therefore still exposes the tenant siteId, so error logs and messages must not echo it.
- The RMS source URL now redirects to learn.microsoft.com/en-us/purview/rights-management-how-does-it-work. DKE/HYOK-protected content also needs a key held by the customer, which supports the 'never attempt MIP SDK in hosted service' recommendation.
- Competitor and prior art missed: PasteGuard (github.com/sgasser/pasteguard, Apache-2.0) is a near-direct competitor. It is a local-first privacy proxy for OpenAI Chat and Responses, Anthropic and Codex. It uses checksum validation, python-stdnum and GLiNER, restores placeholders in responses, and has an experimental browser extension for ChatGPT, Claude and Gemini. Its README does not mention file or xlsx handling, so spreadsheet support is a real differentiator. AI-Safe-Plugin (MAYA-DATA-PRIVACY, MIT per the GitHub sidebar) runs GLiNER2 ONNX on localhost plus regex, on text inputs only.
- LiteLLM managed files, used as the model for proxy-minted IDs: documented as a 'Free Enterprise feature' with no licence needed. It requires Postgres and stores a mapping from LiteLLM file IDs to provider IDs. Its ID format is not clearly documented as base64.
- Confirmed side claims: LayerX is now Akamai Workforce Protector and claims to 'warn, redact, block'. Office add-ins deployed centrally 'can take 24-72 hours to appear on the ribbon'. Add-in-only manifests can be uploaded in the add-ins portal; unified manifests need the Integrated apps portal. Claude for Excel is GA for Pro, Max, Team and Enterprise.
