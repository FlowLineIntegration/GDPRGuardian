# gap-excel-roundtrip-rehydration-formulas

Topic: Reversible pseudonymization for tabular outputs, operators that keep column types, and formula handling
Why: Rehydration was designed only for streamed text. Excel use cases with LLMs produce tables or files: code-interpreter xlsx or CSV, aggregated Markdown tables, rewritten formulas. Placeholders in those outputs get sorted, concatenated or split, and their types get coerced. Placeholders in numeric or date columns can also break the LLM's own pandas code. On formulas, the dimensions contradict each other: one says evaluate or remove them, one says never evaluate (pycel is GPL with a code-execution CVE), one says use cached values only. Formula-help and data-cleaning requests are among the most common Excel+LLM tasks, so this decides which Excel use cases v1 can support.

### Key takeaways
- Verdict on Excel ('traiter ou non'): yes, support it, but read values first. Take cached values from python-calamine, apply a typed operator per column, and return Markdown or CSV. Formula text is optional context: it is tokenized (never evaluated) and its literals are scrubbed. No formula engine belongs in the pipeline.
- python-calamine (MIT, 0.9.0) cannot read formulas. Its type stubs offer only values, merged ranges and tables. The Rust calamine crate (MIT, 0.37.0) does read them: worksheet_formula, defined_names, hyperlinks_by_sheet_name, has_1904_epoch and shared-formula expansion. Options: a thin PyO3 binding, a pull request upstream, or openpyxl read_only with data_only=False as a slower fallback.
- Formula parsers. Default: the openpyxl Tokenizer (MIT, pure Python, no evaluation). Optional: formualizer (MIT/Apache-2.0, Rust with Python bindings, 0.12.0 of 2026-10-19, tokenize/parse/render, TableRef). 'formulas' (EUPL-1.1+) can parse alone, but it pulls in schedula (also EUPL) plus scipy and numpy. xlcalculator has a mixed license and was last released in 2023. pycel is GPL-3.0 with CVE-2024-53924 (CVSS 9.8).
- Where PII hides in a formula: OPERAND/TEXT tokens (strings in HYPERLINK and mailto, VLOOKUP keys, IF tests), OPERAND/NUMBER tokens (IDs typed as numbers), and identifiers inside RANGE tokens (sheet names, defined names, table and column names in structured references). Renamed identifiers must use identifier-safe placeholders: sheet names cannot contain [ ] and are limited to 31 characters.
- Derived PII leaks through cached values: =A2&" "&B2 holds a full name, LEFT(nom;1) holds initials. Run detection on every cached value. Also propagate taint statically from referenced PII cells or columns through text functions, without evaluating anything.
- Rebuilt files: pandas.read_excel (openpyxl engine) loads with data_only=True, so formula cells without cached values read as empty. Write anonymized cached values (XlsxWriter write_formula with value=) or values only. XlsxWriter write() turns strings that start with '=' into formulas by default, so use write_string or strings_to_formulas=False.
- No tool I checked rehydrates tables structurally. LLM Guard Deanonymize and LiteLLM output_parse_pii do plain str.replace on text; LiteLLM also replaces inside tool-call JSON as raw strings, which can break JSON escaping. Limina (formerly Private AI) reidentify is text-only, and its own Excel redaction says formulas may not be preserved. Protecto unmask is text-only. Presidio reverses only decrypt, and presidio-structured has no reversal.
- Rehydration must parse first and restore at the value level (JSON, CSV, xlsx cells), never by replacing bytes. Matching must tolerate escaped Markdown (\[PERSONNE\_1\]), changed case, missing brackets and translated labels. Never rehydrate inside URLs or network formulas: Markdown-image and WEBSERVICE() exfiltration would send the real values to a third party.
- Keeping column types: placeholders turn numeric ID columns into object dtype. Per-session integer surrogates keep int dtype, joins and distinct counts. FF1 is an opt-in only for internal numeric IDs of at least 6 digits (NIST 2PD dropped FF3; the minimum domain has been one million since the initial draft), with check digits recomputed. The NIR's internal structure makes FF1 a poor fit.
- Date shift should work on decoded datetimes: one offset per session, a multiple of 7 days, applied to every sheet. Raw serials differ by 1,462 days between the 1900 and 1904 systems, and serial 60 is a fictitious 29/02/1900. Date of birth is better generalized (year or age band) than shifted.
- Evidence: Bordt et al. (COLM 2024) defaced IDs and names in their 'perturbed' format and saw no significant GPT-4 accuracy change on new datasets (ACS Income 0.78 → 0.78). Their 'statistical' format (features renamed X1..Xn, numbers standardized) fell to 0.57. So replace identifiers but keep headers and values that do not identify anyone. I verified no direct 2024–2026 table-QA study comparing placeholders with surrogates.
- Some LLM answers about tables go wrong under placeholders: alphabetical sorts, initials, string lengths, grouping by email domain, lexical order ('PERSONNE_10' < 'PERSONNE_2'), and counts that depend on entity resolution ('J. Dupont' vs 'Jean Dupont'). Normalize mapping keys and warn the caller.
- Coverage limit: the shared WebSearch budget was already used up when this task started, so all evidence comes from direct fetches of primary URLs. PrivAiTe and the wider table-QA literature remain unverified.

### Recommendations
- OPERATOR TABLE (Excel, defaults). Person names (text): [PERSONNE_n], consistent per session on a normalized key (NFKC, casefold, trim). First-name and last-name columns on the same row share n ([PRENOM_n]/[NOM_n]), so free-text 'Jean Dupont' maps to [PERSONNE_n]. Realistic surrogates are opt-in only.
- OPERATOR TABLE: Email → [EMAIL_n] (keep_domain opt-in). Phone → [TELEPHONE_n]. Street address → [ADRESSE_n]. City is kept. Postal code is kept, or generalized to the 2-digit département as an opt-in.
- OPERATOR TABLE: National IDs (NIR, IBAN, passport, SIREN of a sole trader) → text placeholder [NIR_n] / [IBAN_n]. Never FF1 by default: a realistic result can collide with a real person or company, and the NIR's internal fields (sex, year, month, department) break under encryption.
- OPERATOR TABLE: Internal numeric ID columns (int dtype) → per-session integer surrogate (dense rank from a base such as 900001), shared across every sheet so joins and distinct counts keep working. Opt-in: FF1 with an ephemeral key, only when radix^len ≥ 10^6, encrypting the payload digits and recomputing the Luhn or mod-97 check digit. Text IDs with leading zeros → [ID_n]; never coerce them to int.
- OPERATOR TABLE: Date of birth → year (int) by default; age band as an opt-in. Other person-linked dates → kept by default; opt-in date_shift on decoded datetimes with one per-session offset, a multiple of 7 days, applied to all sheets and to date literals in emitted formulas.
- OPERATOR TABLE: Amounts and measures (salary and the like) → kept. Opt-in rounding or bucketing that stays numeric (lower bound or midpoint) so the float dtype survives. Non-identifying categories and booleans → kept. Columns holding Article 9 special-category data → flagged, with a placeholder as opt-in. Free-text cells → the full detection pipeline with inline placeholders.
- OPERATOR TABLE: Hyperlink targets → the same operator as the entity (mailto: → [EMAIL_n]); personal URLs → [URL_n]. Sheet names, defined names, table names and headers that contain PII → identifier-safe PERSONNE_n: no brackets, sheet names at most 31 characters, never letters+digits that parse as a cell reference (for example NOM1). Formula cells → the cached value goes through its column's operator, and the formula text follows the formula policy.
- FORMULA POLICY F1: never evaluate. No pycel, xlcalculator or formulas runtime; the CVE-2024-53924 class of bugs is avoided entirely. Content comes from calamine cached values. Read formula text (calamine Rust worksheet_formula via PyO3, or openpyxl data_only=False) only when include_formulas=true or a formula cell has no cached value.
- FORMULA POLICY F2: tokenize with the openpyxl Tokenizer (formualizer is the fast option). Scrub OPERAND/TEXT tokens with the same detectors and session mapping, re-escaping doubled quotes. Pass OPERAND/NUMBER tokens through the numeric ID recognizers. Inside RANGE tokens, rename only sheet, defined-name, table and column identifiers through the identifier-safe map; keep A1/R1C1 references and function names. Apply the same scrub to defined names, data validation, conditional formatting and chart series formulas, or drop them.
- FORMULA POLICY F3: run static taint analysis without evaluation. A formula whose references reach PII cells or columns through text functions (&, CONCAT, LEFT, MID, UPPER, TEXT, XLOOKUP/INDEX returning a PII column) gets the entity operator on its cached value, or [DERIVE_n]. Numeric aggregates over non-identifying columns pass unchanged.
- FORMULA POLICY F4, output. Markdown: values only by default; with include_formulas, an appendix such as 'Feuil1!D2: =B2*C2' after scrubbing. A cell with no cached value shows its scrubbed formula as code, with a flag. Rebuilt xlsx: values only by default. The opt-in keeps formulas and also writes anonymized cached values (XlsxWriter value=) so pandas, which reads with data_only=True, still gets numbers. Always rebuild from scratch, never patch the package, so pivot caches, comments, document properties and external links are dropped. Strip WEBSERVICE, RTD, DDE, IMAGE, external-workbook references and http(s) HYPERLINKs.
- REHYDRATION R1: only in the proxy or REST client. The session mapping stores placeholder → (original typed value, entity, source sheet and column, number_format), with a TTL, and is destroyed at session end. Placeholders that are not in the session are left as they are and reported. No MCP tool exposes rehydration.
- REHYDRATION R2, text and Markdown: one placeholder grammar tolerant to Markdown escaping (\[ \_), changed case, missing brackets, space, underscore or hyphen variants, and known label translations (PERSONNE/PERSON). Do not rehydrate inside URLs, Markdown image or link targets, or HTML attributes unless allowlisted: this blocks the image-exfiltration path.
- REHYDRATION R3, JSON (tool arguments, structured outputs): parse, walk, rehydrate string values and keys, then re-serialize so escaping is correct. Fall back to text only, with JSON-escaped insertions. CSV: parse with the csv module. A field that is exactly one placeholder gets the original typed value; a partial match gets string substitution. Integer surrogates are restored only in columns whose header maps to a surrogate column. Apply OWASP neutralization to non-numeric strings starting with = + - @ TAB CR LF or full-width variants.
- REHYDRATION R4, xlsx returned by a code interpreter: treat it as untrusted. Reject .xlsm/VBA; open with openpyxl without evaluating. Restore cell values with their type and number format, then sheet, defined and table names, comments, mailto hyperlinks and formula string literals through the tokenizer. Remove or convert to values any network or external formulas. Write strings as typed strings. Return a report: counts, unknown placeholders, skipped URL contexts, ambiguous numeric surrogates.
- REHYDRATION R5, semantic warnings: flag answers whose correctness depends on placeholder text (alphabetical order, initials, string length, email domain, lexical order of indices). Optionally, number placeholders in sorted order of the original values with zero-padded indices within a single request, so a sort by placeholder matches a sort by name. This leaks only the order.
- Build an internal benchmark before choosing defaults: WikiTableQuestions/TableBench-style tables, plus code-interpreter tasks on French HR or CRM sheets. Compare original values, [TYPE_n] placeholders, integer surrogates and realistic surrogates on identifier columns. Measure exact-match accuracy, join and count correctness, and rehydration success.

### Risks
- python-calamine has no formula API, so formula support needs a custom PyO3 binding over Rust calamine, a pull request upstream, or the slower openpyxl path. That is maintenance load.
- Tokenizer edge cases can corrupt formulas or leak PII: structured-reference escapes ('#, '[, '@), array constants {…}, LET/LAMBDA local names, _xlfn. prefixes, sheet names quoted with apostrophes. A round-trip test corpus is needed. formualizer is very young (first release May 2025).
- Derived PII in cached values (concatenations, initials, lookups) can slip past entity detectors unless static taint analysis is implemented.
- Rehydration as an exfiltration path: a prompt-injected LLM can place placeholders in Markdown image URLs or in WEBSERVICE/HYPERLINK formulas. Rehydrating them sends real PII to a third party automatically.
- Plain str.replace rehydration, the pattern LLM Guard and LiteLLM use, corrupts JSON and CSV when original values contain quotes, backslashes, commas or newlines.
- Realistic surrogates and FF1 output can equal a real identifier (for example a real company's SIREN), causing confusion and possible misattribution. FF1 with NIST 2PD's minimum domain excludes short IDs.
- Integer surrogates are ambiguous in free text: '3' could be a count. Restore them only in typed table columns.
- Excel stores numbers to 15 digits and drops leading zeros. ID columns already typed as numbers may be corrupted in the source, and anonymization must not convert IDs stored as text.
- Placeholder-based answers can be silently wrong for value-dependent operations (sorting by name, initials, domains). Entity-resolution gaps (variants of one name, or two people with the same name) distort counts.
- Research coverage risk: the WebSearch budget was used up before this task, so PrivAiTe and the 2024–2026 table-QA literature on masking were not verified, and the exact FF1 minimum domain in the 2PD could not be read from the PDF.

- Should v1 return rebuilt xlsx at all, or only Markdown and CSV, with xlsx rebuild and rehydration deferred?

### Critical claims
- python-calamine's type stubs expose no formula-reading method: sheets offer to_python, iter_rows and merged_cell_ranges, plus tables via load_tables, and nothing for hyperlinks or defined names. [https://raw.githubusercontent.com/dimastbk/python-calamine/master/python/python_calamine/_python_calamine.pyi]
- Rust calamine 0.37.0 (MIT) exposes worksheet_formula, defined_names, hyperlinks_by_sheet_name, merge_cells_by_sheet_name and has_1904_epoch for XLSX. [https://docs.rs/calamine/latest/calamine/struct.Xlsx.html]
- The openpyxl Tokenizer classifies operands as TEXT, NUMBER, LOGICAL, ERROR or RANGE, where RANGE is a named range or a direct reference. Each token's value is the substring of the formula that produced it. [https://openpyxl.readthedocs.io/en/stable/formula.html]
- The 'formulas' package 1.3.4 (2026-03-11) is EUPL 1.1+ and depends at runtime on schedula (EUPL 1.1+), numpy, scipy, numpy-financial, regex, click, python-dateutil and tqdm. [https://pypi.org/pypi/formulas/json]
- CVE-2024-53924: Pycel through 1.0b30 allows code execution via a crafted formula in an untrusted spreadsheet (CVSS 3.1 9.8). The last pycel release, 1.0b30, dates from 2021-10-13 and is GPLv3. [https://cveawg.mitre.org/api/cve/CVE-2024-53924]
- xlcalculator's MIT LICENSE excludes 'tokenizer, parsing and shunting code which are covered by different licences'. Its last PyPI release is 0.5.0, from 2023-02-06. [https://raw.githubusercontent.com/bradbase/xlcalculator/master/LICENSE]
- formualizer 0.12.0 (uploaded 2026-10-19, MIT/Apache-2.0) offers Python tokenize() returning a Tokenizer with .render() and .tokens, and parse() returning an ASTNode with to_formula() and walk_refs(), including typed TableRef and NamedRangeRef. [https://pypi.org/project/formualizer/]
- NIST SP 800-38G Rev.1 second public draft (2025-02-03): FF3 is no longer specified and the FF1 domain size is increased. The initial draft had already made a minimum domain of one million a requirement. [https://csrc.nist.gov/pubs/sp/800/38/g/r1/2pd]
- Excel's 1900 and 1904 date systems differ by 1,462 days (the 1900 serial is always higher). [https://support.microsoft.com/en-us/office/date-systems-in-excel-e7fe7167-48a9-4b96-bb53-5612a800b487]
- The pandas openpyxl Excel reader calls load_workbook with read_only=True, data_only=True and keep_links=False, so it reads cached formula values. [https://raw.githubusercontent.com/pandas-dev/pandas/main/pandas/io/excel/_openpyxl.py]
- XlsxWriter write() writes strings starting with '=' as formulas unless the Workbook option strings_to_formulas is False, and write_formula() accepts an optional precalculated result value. [https://xlsxwriter.readthedocs.io/worksheet.html]
- LLM Guard Deanonymize matches by EXACT str.replace (default), CASE_INSENSITIVE re.sub, FUZZY (fuzzysearch, max_l_dist=3) or COMBINED, with no CSV or JSON structure handling. [https://raw.githubusercontent.com/protectai/llm-guard/main/llm_guard/output_scanners/deanonymize.py]
- LiteLLM's Presidio guardrail masks with numbered <ENTITY_n> tokens and unmasks by str.replace, including tool-call arguments processed as raw strings. In the SSE path, only text_delta events are unmasked, not tool-argument deltas. [https://raw.githubusercontent.com/BerriAI/litellm/main/litellm/proxy/guardrails/guardrail_hooks/presidio.py]
- Limina (formerly Private AI) Excel processing states 'Formulas may not be preserved after redaction', and its reidentify endpoint takes text arrays plus an entity list, with no file input. [https://docs.getlimina.ai/configuration-and-operations/working-with-files/processing-files/excel.md]
- Bordt et al. (Elephants Never Forget, COLM 2024) defaced unique identifiers such as IDs and names in their 'perturbed' format and saw no significant change on novel datasets (GPT-4 ACS Income 0.78 original vs 0.78 perturbed). The 'statistical' format (features renamed X1..Xn, numerics standardized) fell to 0.57. [https://arxiv.org/html/2404.06209v3]

### Verifier notes
- Missed option: open python-calamine PR #137 ('feat: Add Opt-in Formula Reading Support', by PSU3D0, who also wrote formualizer) adds read_formulas=False and CalamineSheet.iter_formulas(). It was opened 2025-07-07 and reviewed by the maintainer in Aug 2025. CodeRabbit flagged a stub gap and a row-count mismatch in Jan 2026, and a user asked on 2026-08-30 whether it would land. Reviving or finishing #137 is cheaper than a new PyO3 binding and should replace the 'thin PyO3 binding' default. https://github.com/dimastbk/python-calamine/pull/137
- Version skew: python-calamine 0.9.0 (2026-10-16) still bundles calamine 0.36.1, not 0.37.0. Calamine 0.37.0 (2026-10-18) fixes three relevant bugs: an XLSX 1904 epoch flag reset by <x15:workbookPr>, which mis-dates every date in affected 1904 workbooks; formula string results not decoding _xHHHH_ escapes; and hyperlink attributes not decoding XML entities. The date-shift and 1904 recommendations should pin python-calamine to a release built on calamine 0.37 or later, or detect date1904 independently. https://raw.githubusercontent.com/tafia/calamine/master/Changelog.md
- Design gap in F1: python-calamine cannot tell 'formula cell with no cached value' from 'empty cell', because it has no formula API. Issue #107 reports formula cells read as empty. 'Read formula text only when a formula cell has no cached value' therefore needs the formula reader, or a cheap XML scan for <c><f> without <v>, on every file anyway.
- NIST FF1: the 2PD says 'The domain size for the FF1 encryption method is increased' compared with the initial draft's one-million minimum. The takeaway that the minimum 'has been one million since the initial draft' and the radix^len >= 10^6 threshold may be out of date. The new value could not be read: the PDF did not render here and WebSearch was exhausted. Check NIST.SP.800-38Gr1.2pd.pdf before hard-coding it. The 2PD also forbids floating-point arithmetic in FF1 implementations and the inverse cipher as CIPH, which matters for any Python FF1 port. Rev.1 is still a draft.
- Rehydration R4 omission: openpyxl, like XlsxWriter, types any string longer than 1 character that starts with '=' as a formula (Cell._bind_value sets data_type='f'). Writing rehydrated originals with openpyxl must force data_type='s' or use explicit string handling, or an original value such as '=HYPERLINK(...)' becomes a live formula. openpyxl check_string also raises on illegal control characters and truncates at 32,767 characters, so rehydration needs to handle both.
- LLM Guard: its CASE_INSENSITIVE matching is broken for bracketed placeholders because re.sub gets the placeholder without re.escape. This is a further argument for the takeaway's 'parse then restore' approach and should be cited as a concrete failure mode.
- Presidio has moved from Microsoft to the 'data-privacy-stack' GitHub org; docs are now at presidio.dataprivacystack.org and the license is still MIT. 'Presidio reverses only decrypt' holds only for built-in operators: DeanonymizeEngine exposes add_deanonymizer/remove_deanonymizer, so custom reversible operators are possible. Update links and wording.
- pycel: a fix for CVE-2024-53924 (restricted builtins, #165) is in the unreleased section of master. The PyPI release is still 1.0b30 from 2021, so the recommendation to avoid it stands. The CVSS 9.8 score comes from CISA ADP.
- formualizer bundles a full evaluation engine (formualizer-eval), and its PyPI license metadata says 'MIT' while the repo is dual-licensed. If adopted, use only tokenize/parse and never call evaluate. The Python methods .render, .tokens and .walk_refs are listed in the PyPI API reference only; no examples were found, so test them before relying on them.
- Excel identifier rules for the identifier-safe map. Sheet names forbid / \ ? * : [ ], cannot start or end with an apostrophe, and cannot be 'History'. Defined names must start with a letter, '_' or '\', contain no spaces, not look like a cell reference (Z$100, R1C1) or be C/c/R/r, are at most 255 characters, and are case-insensitive. Placeholder names therefore need a case-insensitive collision check against existing names.
- Tokenizer omissions in F2: the _xlfn./_xlws./_xlpm. prefixes; LET and LAMBDA variable names, which are user identifiers that can carry PII; external workbook references ([1]Sheet!A1, where the externalLink part also holds a file path or URL); and openpyxl returning ArrayFormula/DataTableFormula objects rather than str for array and dynamic-array formulas.
- OWASP CSV Injection, now at community.owasp.org, confirms = + - @ TAB(0x09) CR(0x0D) LF(0x0A) and full-width ＝＋－＠. It warns that single-quote prefixing is unreliable in Excel after a save and reopen, and suggests a tab prefix for files meant for people to read.
- Evidence caveat (Bordt et al.): the identifiers there were irrelevant features in few-shot classification, and 'perturbed' also changed numeric digits. The study does not measure questions about identifiers themselves (sorting, joins, counts), so it supports 'replacing IDs and names does not hurt prediction on other features' but not table-QA accuracy under placeholders. The 'task' format, which reworded and recoded features, scored 0.77, so natural-language header rewording is harmless. The 0.57 drop comes from X1..Xn names combined with standardization.
- Coverage: WebSearch was already exhausted when this check ran (the per-turn budget is shared), so all checks used direct fetches. Not verified: Protecto unmask, the PrivAiTe and table-QA literature, Excel serial 60 / 29-Feb-1900 (not fetched), and the new FF1 minimum domain in the 2PD.
