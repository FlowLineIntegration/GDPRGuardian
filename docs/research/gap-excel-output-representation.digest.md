# gap-excel-output-representation

Topic: Output contract for anonymized spreadsheets: representation, size limits and a clean-rebuild option
Why: Every dimension assumes 'one Markdown table per sheet' (constraint 5), possibly with a CSV fence, but none checked whether that representation actually serves Excel+LLM tasks. Nobody looked at the hard limits MCP clients put on tool results. Writing an xlsx back was ruled out only for the edit-in-place case, which copies pivot caches and other parts. A from-scratch rebuild was never evaluated. This decides the v1 Excel output contract and whether constraint 5 needs an exception.

### Key takeaways
- Note on method: the web-search quota shared by this workflow ran out on the first query. All findings below come from WebFetch on primary URLs (official docs, arXiv, PyPI, crates.io, GitHub raw source). Limits for ChatGPT, VS Code and Cursor could not be found by search.
- No input format wins everywhere. In one lookup test (GPT-4.1-nano, 1,000 rows x 8 fields), Markdown-KV scored 60.7% at 52k tokens, a Markdown table 51.9% at 25k, and CSV 44.3% at 19.5k. TQA-Bench found Markdown beat CSV for most models. MMTU found frontier reasoning models barely care about format, except that HTML still lags.
- Table size matters more than format. In TQA-Bench, GPT-4o fell from 78.7 to 63.4 between 8K and 64K tokens, and sum and correlation tasks dropped the most. In MMTU's needle test, GPT-4o fell below 0.5 accuracy once a table had more than 25 columns. Big sheets should therefore not be sent inline, and aggregates should be computed by our code, not by the LLM.
- Published token cost per cell (o200k tokenizer, English synthetic data): about 2.4 for CSV, 2.7 for TOON, 3.1 for a Markdown table, 6.5 for Markdown-KV and 8.3 for JSON. No figure for French business data was found, so we need to measure it ourselves.
- Client limits: Claude Code warns at 10k tokens and caps at 25k tokens (MAX_MCP_OUTPUT_TOKENS). It saves any text result over 50,000 characters to a file, unless the tool sets _meta anthropic/maxResultSizeChars (up to 500k). claude.ai and Desktop allow about 150,000 characters and 240 s per call. An HTTP response over 16 MiB fails in Claude Code. OpenAI, VS Code and Cursor document no size limits.
- MCP 2026-07-28 removes protocol sessions. The spec tells servers to keep state across calls with opaque, server-minted handles passed as ordinary tool arguments, with a bounded lifetime and authorization checked on every call. Cursor pagination covers only list operations, so a read_rows(handle, cursor) tool is the portable design. The Tasks extension covers long jobs.
- Sending 'schema + profile + anonymized sample' instead of the full table is an established pattern. PandasAI v2 sends 5 anonymized sample rows by default, or metadata only with enforce_privacy. LangChain's SQLDatabase sends CREATE TABLE plus 3 sample rows, following Rajkumar et al. 2022. Snowflake semantic models feed sample_values to the model. LIDA builds a compact data summary.
- SpreadsheetLLM's SheetCompressor reaches about 25x compression (24.79x) and +25.6% F1 on table detection for GPT-4. No official code is linked, so we can borrow its ideas (inverted index, grouping cells by format) but there is nothing to adopt.
- A clean rebuilt workbook is feasible with XlsxWriter (BSD-2-Clause, 3.3.0, released 2026-10-22). Its defaults are unsafe for us: strings_to_formulas=True and strings_to_urls=True. Its metadata is benign: the creator is empty and Application is 'Microsoft Excel', but created/modified are set to the current UTC time, and sheet names appear in app.xml.
- Speed and memory at about 1M cells, scaled linearly from benchmarks: rust_xlsxwriter about 0.7 s and XlsxWriter about 4.4 s (from 135 ms and 878 ms for 200k cells). XlsxWriter normal mode uses roughly 200 MB per 1M cells. Its constant_memory mode stays near 62 KB but writes temporary files to disk.
- openpyxl is a poor writer for this job. Any string starting with '=' becomes a formula, the default creator is 'openpyxl', and the last release (3.1.5) dates from 2024-06-28.
- CSV formula injection: OWASP now lists =, +, -, @, TAB, CR, LF and their full-width forms as triggers. It also says no sanitization is universally safe, and that Excel may re-activate escaped formulas after a save. Typed xlsx string cells avoid the problem when the file is opened.

### Recommendations
- Default representation (MCP and REST /convert): one Markdown document with (a) a summary block: sheet count, sizes, entity counts by type, and what was dropped (hidden sheets, comments, formulas reduced to cached values, merged cells); (b) one GFM pipe table per sheet with a first '#' column holding the original Excel row number. Escape | as \| and turn newlines into <br>, because GFM silently drops extra cells. Never use HTML or pretty JSON by default.
- Inline threshold: if the whole anonymized response is 40,000 characters or less, measured on the serialized string, return it in full. This stays under Claude Code's 50,000-character save-to-file threshold and roughly its 10k-token warning, and far under claude.ai's ~150k limit. It is about 2,500-3,000 Markdown cells, to be calibrated on French data.
- Above the threshold, each sheet gets 'schema + profile + sample'. The column table gives: header (anonymized), inferred type, fill %, distinct-count bucket, detected entity types and the action taken. Basic statistics appear only for columns not flagged as identifiers or quasi-identifiers, with min/max generalized and categories under 5 occurrences suppressed. Then the first 20 anonymized rows, plus a handle and next_cursor.
- Wide sheets (more than 20 columns): show the sample and pages as records (Markdown-KV: '### Ligne 17' followed by 'colonne: valeur'), or split into column groups that repeat the key column. Evidence: MMTU's accuracy collapse above 25 columns, and Markdown-KV leading on lookups.
- Pagination: read_rows(handle, cursor?, max_chars=32000, layout='table'|'records'|'csv'|'toon'). Pages are cut by character budget, not row count. The handle is a UUIDv4 kept in RAM only, bound to the caller's auth principal, with a TTL of 15 min idle and 60 min maximum. It shares the placeholder mapping, so [PERSONNE_n] stays consistent across pages; release(handle) destroys both. An expired handle returns isError text telling the model to resubmit.
- Caps (configurable): file of 50 MB or less, 2M non-empty cells or less, 100 sheets or less. Synchronous work must finish within 60 s (claude.ai stops at 240 s, Claude Code backgrounds calls after 120 s). Beyond that, use the MCP Tasks extension when the client declares it, otherwise a REST async job. Do not raise anthropic/maxResultSizeChars; keep results small on purpose.
- Optional `format` parameter: markdown (default), csv (cheapest), toon (toon-format, MIT), json (structuredContent with outputSchema, for programmatic callers). Never ask the LLM to aggregate large sheets; the deterministic profile gives counts, sums and ranges.
- Clean rebuild (opt-in, delivered only as a REST download or an MCP resource, never as base64 inline): XlsxWriter with {'strings_to_formulas': False, 'strings_to_urls': False, 'strings_to_numbers': False, 'in_memory': True}. Above about 1M cells, use constant_memory with tmpdir on a per-request tmpfs that is wiped afterwards. Write each cell by its calamine type; placeholders as strings; dates with a fixed format. Set author to '' and a fixed 'created' date. Generic sheet names (Feuille1...). Values only: no formulas, comments, defined names, tables, hyperlinks, hidden sheets or VBA. xlsm/xlsb/xls/ods inputs come out as xlsx, under a generic file name.
- CSV rebuild: stdlib csv, UTF-8 with BOM, QUOTE_ALL, CRLF. Prefix ' to string cells (never typed numbers) starting with = + - @ TAB CR LF or the full-width ＝＋－＠. Document that Excel may re-arm formulas after a save, and recommend xlsx for people who will open the file.
- CI guardrails: unzip each rebuilt xlsx and assert that only allowlisted parts exist, that core.xml has an empty creator and the fixed date, and that app.xml TitlesOfParts lists only generic sheet names. Re-read the file with calamine and re-run detection to check for leaks. Do not adopt openpyxl for writing. Treat rustpy-xlsxwriter as a later speed path, only after checking how it handles strings starting with '='.
- Proxy mode: attachments sent through the proxy follow the same contract (Markdown, profile above the threshold). Tables pasted into prompts are anonymized cell by cell in place, without reformatting.

### Risks
- The profile and sample can still single people out: min/max of salary or dates, rare categories, small row counts. GDPR data minimisation (Art. 5(1)(c)) and recital 26 on singling out apply (https://eur-lex.europa.eu/eli/reg/2016/679/oj). Suppression and generalization rules are needed.
- XlsxWriter writes temporary files by default, and always in constant_memory mode. On the hosted service this conflicts with 'ephemeral, RAM-only' promises unless in_memory or a tmpfs tmpdir is used.
- Leak paths in a rebuild: sheet names (written to workbook.xml and listed in app.xml TitlesOfParts), defined or table names, and custom number formats, which can hold quoted literal text (Microsoft number-format guidelines). Never copy any of these from the source.
- XlsxWriter's defaults strings_to_formulas=True and strings_to_urls=True, and openpyxl's automatic typing of '=' strings, can turn anonymized text into live formulas or hyperlinks.
- CSV injection cannot be fully neutralized for every consumer (OWASP), and Excel may re-activate formulas after a save.
- ChatGPT, VS Code Copilot and Cursor document no tool-result size limits, so the design rests on Claude's limits and must be tested empirically.
- The benchmarks are mostly English and synthetic, use small models (GPT-4.1-nano) or older ones (text-davinci-003), and some are run by format authors (TOON). They may not transfer to French business sheets or to frontier models.
- Placeholders such as [PERSONNE_12] raise token cost per cell. Keeping them consistent across pages ties the handle's lifetime to the re-identification mapping, so a leaked handle exposes the paging session.
- Handles are bearer tokens if the server is unauthenticated, so they need high entropy, a short TTL and authorization checks on every call.
- TQA-Bench code is GPL-3.0, and the MMTU repo has no LICENSE file. Neither may be vendored into the MIT repo.
- rustpy-xlsxwriter has a single maintainer.
- openpyxl has had no release since June 2024.
- The web-search quota was exhausted. Some facts could not be cross-checked: release dates for polars and defusedcsv, LangChain's license, and the units of rust_xlsxwriter's memory figures.

### Open questions
- What size limits and timeouts do ChatGPT apps/connectors, VS Code Copilot and Cursor actually apply to tool results? None is documented, so each needs an empirical test.
- Do claude.ai, Desktop, ChatGPT, VS Code and Cursor let the model read a resource_link or an embedded blob resource returned by a tool? If not, a downloadable rebuilt file must go through REST.
- What is the real token cost per cell for French business sheets with [TYPE_n] placeholders? Measure with o200k (tiktoken) and Anthropic's count_tokens to set the 40,000-character threshold.
- Do rust_xlsxwriter and rustpy-xlsxwriter write a Python str starting with '=' as a string or as a formula? How do they set docProps?
- Does polars write_excel always add an Excel table, and does it leave strings_to_urls=True?
- Should the profile include any statistics on quasi-identifier columns (dates of birth, postcodes, salaries)? What k-threshold should apply?
- Is ODS output needed in v1, given that odfpy's licensing was not checked?
- Should the paging handle and the reversible placeholder mapping share one TTL, or have separate lifetimes?

### Critical claims
- Claude Code warns when MCP output exceeds 10,000 tokens and defaults MAX_MCP_OUTPUT_TOKENS to 25,000. Text results over 50,000 characters are saved to a file unless the tool sets _meta['anthropic/maxResultSizeChars'] (hard ceiling 500,000). HTTP/SSE responses over 16 MiB fail. [https://code.claude.com/docs/en/mcp]
- Claude Code moves an MCP tool call to a background task after two minutes. The idle timeout defaults to 5 minutes for HTTP servers and 30 minutes for stdio servers. [https://code.claude.com/docs/en/mcp]
- Maximum tool result size is about 150,000 characters on claude.ai and Desktop, with a 240-second timeout per tool call. [https://claude.com/docs/connectors/building]
- MCP 2026-07-28 removes protocol-level sessions and the Mcp-Session-Id header. Servers that need state across calls use explicit server-minted handles passed as ordinary tool arguments. [https://modelcontextprotocol.io/specification/2026-07-28/changelog]
- In MCP 2026-07-28, cursor pagination applies only to resources/list, resources/templates/list, prompts/list and tools/list. Tool results may contain resource_link and embedded resource content. [https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/pagination]
- With GPT-4.1-nano on 1,000 records x 8 fields: Markdown-KV 60.7% (52,104 tokens), Markdown table 51.9% (25,140), JSON 52.3% (66,396), CSV 44.3% (19,524). [https://www.improvingagents.com/blog/best-input-data-format-for-llms]
- TQA-Bench: Markdown beat CSV for most models. GPT-4o average accuracy fell from 78.68 at 8K tokens to 63.41 at 64K. The repository is GPL-3.0. [https://arxiv.org/html/2411.19504v1]
- MMTU: in the needle-in-a-haystack test, GPT-4o accuracy falls below 0.5 with more than 25 columns. HTML still lags other formats. [https://arxiv.org/html/2506.05587v4]
- SheetCompressor reaches 24.79x token compression and beats vanilla encoding by 25.6% on table detection with GPT-4 in-context learning. No official code is linked. [https://arxiv.org/abs/2407.09025]
- XlsxWriter 3.3.0 (released 2026-10-22, BSD-2-Clause) defaults to strings_to_formulas=True and strings_to_urls=True. [https://raw.githubusercontent.com/jmcnamara/XlsxWriter/main/xlsxwriter/workbook.py]
- XlsxWriter writes an empty dc:creator, sets dcterms:created and modified to the current UTC time, and writes Application 'Microsoft Excel' with AppVersion 12.0000. [https://raw.githubusercontent.com/jmcnamara/XlsxWriter/main/xlsxwriter/core.py]
- rust_xlsxwriter (MIT OR Apache-2.0, 0.101.0) wrote 200k cells in 135.2 ms vs 878.2 ms for Python XlsxWriter, 6.49x slower. [https://docs.rs/rust_xlsxwriter/latest/rust_xlsxwriter/performance/index.html]
- In openpyxl, a string longer than one character that starts with '=' gets data_type 'f' (formula). The DocumentProperties default creator is 'openpyxl'. [https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/cell/cell.html]
- OWASP lists =, +, -, @, TAB, CR, LF and full-width variants as CSV formula triggers, and states that no universal CSV sanitization strategy is safe. [https://community.owasp.org/attacks/CSV_Injection]
- PandasAI v2 sends 5 anonymized sample rows to the LLM by default. With enforce_privacy=True it sends only metadata. [https://raw.githubusercontent.com/sinaptik-ai/pandas-ai/v2.4.0/docs/library.mdx]

### Verifier notes
- Clean-rebuild recommendation conflicts with XlsxWriter: the official Workbook docs say in_memory 'overrides the constant_memory option'. The proposed base options ({..., 'in_memory': True}) must drop in_memory on the >1M-cell constant_memory path, or constant_memory is silently ignored. Also, when in_memory is off XlsxWriter writes temp files in its normal mode too, not just in constant_memory. So tmpdir must point at the per-request tmpfs in both non-in_memory modes.
- The speed takeaway (XlsxWriter about 4.4 s per 1M cells) comes only from the rust_xlsxwriter benchmark. XlsxWriter's own working_with_memory page (older hardware) shows 27.60 s for 12,800x50 = 640k cells in normal mode (about 43 s per 1M cells) and 23.63 s in constant_memory. Memory there is 128.85 MB, consistent with the 'about 200 MB per 1M cells' claim, and 62,208 bytes in constant_memory. The speed figure needs a local benchmark before setting the 60 s synchronous cap.
- Missing from the timeout reasoning: for HTTP, SSE and claude.ai-connector servers, Claude Code has a per-request timer up to the server's FIRST RESPONSE BYTE, set to the greatest of 60 s, the server tool timeout and MCP_TIMEOUT. A 60 s synchronous budget therefore sits exactly at that edge for a plain JSON (non-streamed) HTTP response. Target a lower synchronous budget (e.g. 45-50 s), or open an SSE stream early and send progress notifications. Progress also resets the 5-minute idle timeout.
- 'Published token cost per cell (o200k tokenizer)': the per-cell figures (2.4 CSV, 2.7 TOON, 3.1 Markdown table, 6.5 Markdown-KV, 8.3 JSON) are the improvingagents totals divided by 8,000 cells. Neither improvingagents article names the tokenizer, so 'o200k' is an inference, not a published fact. tiktoken counts are not Claude tokens either. Character-based thresholds, as recommended, are the right call. A 40,000-char Markdown response in French may exceed Claude Code's 10k-token warning.
- Claim 11 source attribution: Application 'Microsoft Excel' / AppVersion '12.0000' come from xlsxwriter/app.py, not core.py. app.py also writes Company (empty by default) and TitlesOfParts with the sheet names. The generic sheet names in the recommendation are therefore necessary.
- rustpy-xlsxwriter (0.8.0, MIT, on rust_xlsxwriter 0.100.0) was checked for the '=' question the recommendations leave open. src/cell.rs and src/worksheet.rs write Python str values with write_string, with no leading-'=' check. Formulas and URLs happen only for columns explicitly listed in formula_columns / url_columns. The library sets no document properties, so rust_xlsxwriter defaults apply: DocProperties::new() has an empty author and creation_time = ExcelDateTime::utc_now(). A fixed date needs set_creation_datetime. Caveat: a single-maintainer project with about 33 stars and no GitHub releases.
- polars.DataFrame.write_excel sets strings_to_formulas=False but leaves strings_to_urls=True. By default it also writes an Excel Table object with autofilter. It is not a drop-in for the 'values only, no tables, no hyperlinks' rebuild unless those options are overridden.
- CSV rebuild omission for a French product: Excel in fr-FR locale expects ';' as the CSV list separator. A comma-delimited UTF-8-BOM CSV opens as a single column for many French users. Decide the delimiter (';' or configurable), and note that a 'sep=;' first line conflicts with the BOM in some Excel versions. The ' prefix will also be added to legitimate strings such as '+33 6 ...' phone numbers or '-' bullet text. Document it as a fidelity trade-off.
- openpyxl takeaway wording: only strings LONGER THAN ONE character starting with '=' become formulas (`len(value) > 1`). The openpyxl 'stable' docs are for 3.1.3; 3.1.5 (2024-06-28) is the latest non-yanked release. A yanked 3.2.0b1 also exists. The conclusion (do not adopt for writing) stands.
- PandasAI example is dated: the cited v2.4.0 docs correspond to PyPI 2.4.x releases that are yanked. The current major is 3.0.0 (2025-10-07). Cite it as 'PandasAI v2 (2.3.x)' or re-check v3 behaviour. The LangChain claim is confirmed: SQLDatabase sample_rows_in_table_info defaults to 3, appended as a /* ... */ comment after CREATE TABLE, with values truncated to 100 chars.
- TQA-Bench nuance: the largest drops with context length for GPT-4o were Sum (76.00 to 32.63) and Count (80.00 to 46.74), not specifically correlation. Correlation dropped for many models. The 78.68 to 63.41 figures are for the Markdown serialization. TQA-Bench code is GPL-3.0: reuse ideas or data only, never code.
- SpreadsheetLLM: the abstract states '25 times' average compression; 24.79 is the Table 1 data-region ratio with all modules. The paper is CC BY-NC-SA 4.0. Reimplementing its ideas from the description is fine; copying text or figures is not MIT-compatible.
- MCP handle design: the spec's non-normative 'Stateful Tools' guidance asks servers to state the handle retention policy in the creating tool's description, so the model sees it. The recommendation should put the '15 min idle / 60 min max' TTL in the tool description, and not only in the expiry error.
- OWASP CSV Injection page is CC BY-SA 4.0 (not 'n/a'). Do not paste its text into MIT-licensed source or docs without attribution and ShareAlike.
- Environment/dependency notes: python-calamine 0.9.0 declares requires_python >=3.11, so check it against GDPR Guardian's supported Python range. tiktoken (MIT) downloads its BPE files from an OpenAI blob URL on first use, unless they are pre-cached via TIKTOKEN_CACHE_DIR. An offline CPU deployment must vendor or pre-cache them, or measure size with characters only.
