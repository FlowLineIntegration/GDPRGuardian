# tabular-excel

### Key takeaways
- Recommendation: handle spreadsheets in v1, but only as cell values to anonymized Markdown. Never return or forward the original file. Customer and HR exports are among the riskiest inputs, and per-column processing costs far less CPU than NER on prose.
- One Rust reader covers almost every format. python-calamine (MIT, 0.9.0, released 2026-10-16) reads xlsx, xlsm, xlsb, xls and ods. pandas' own notes say it is up to 5x faster than openpyxl, 20x faster than odf and 4x faster than pyxlsb. One 500K-row test measured 3.58 s against 24.79 s for openpyxl read-only. Use polars plus charset-normalizer for csv and tsv.
- Detect per column, not per cell. Combine a prior from the header name (multilingual, from the country pack) with validator hit rates on sampled values. Classify the column, then map only its unique values to tokens. Run NER only on free-text columns, and only on their unique cells. Cost then scales with distinct values, not rows × columns.
- presidio-structured is only a source of ideas. It ignores column names, analyzes every row by default (n=None), runs the full Presidio NER on each sampled cell, keeps one entity and one operator per column, and anonymizes in a per-cell Python loop. It is at 0.0.8, and its JSON processor overwrites list items.
- Keeping joins and aggregations working: use one mapping per session, keyed by (entity_type, normalized value), shared across every sheet and file in the request. The same customer then gets the same token everywhere, so the LLM can still group, count and join. Normalize values before lookup: E.164 phones, lowercase emails, IBANs without spaces, collapsed whitespace and case.
- Hidden content is a question of what the converter outputs. calamine never reads comments, pivot caches, external links, VBA, document properties, chart caches or embedded objects, so these are dropped by design. Inventory them from the ZIP and report them. calamine does give sheet visibility (Visible/Hidden/VeryHidden), but not hidden rows or columns. For xlsx those need a small streaming XML scan.
- Excel's own data quirks break naive validators. Excel keeps only 15 significant digits, so a 16-digit card number stored as a number has its last digit turned to 0 and fails Luhn. Numeric cells drop leading zeros from postal codes and phone numbers. NIR, SIREN and SIRET come back as floats. Rebuild the canonical string before validating, and fall back on the header prior.
- Do not build k-anonymity, l-diversity or t-closeness into v1. Row-level LLM tasks need row fidelity, and global recoding with suppression destroys utility: anjana suppressed 43.7% of the Adult dataset's records to reach k-anonymity. It also needs user-defined hierarchies, and ARX needs a JVM. For v1, offer simple deterministic generalization operators and an optional k-report computed with polars group_by.
- Output format: a Markdown table costs about 29% more tokens than CSV (25,140 vs 19,524 tokens) and is clearly more accurate (51.9% vs 44.3%). JSON costs about 3.4x CSV for similar accuracy. Default to a Markdown table, offer CSV in a fenced block for large tables, and avoid JSON for bulk rows. Very large sheets need caps plus a profile mode (schema, statistics, anonymized sample).
- Library status: ARXaaS (REST) was archived on 2025-11-13, and its Python client pyarxaas has been alpha since 2020, so avoid both. anjana 1.2.3 and pycanon 1.3.6 are Apache-2.0 but pin exact versions (numpy==2.0.2, pandas==2.3.3), so use them only as an offline test oracle. pyxlsb is LGPLv3+ and odfpy is stale (2020); calamine makes both unnecessary.

### Recommendations
- Scope for v1: support xlsx, xlsm, xls, xlsb and ods through python-calamine, and csv and tsv through charset-normalizer, csv.Sniffer and polars. Output is anonymized Markdown only. Out of v1: writing xlsx back out, comments (opt-in later), anonymizing chart or pivot contents, k-anonymity optimization, and decrypting encrypted files without a supplied password.
- Pipeline: (1) a package guard checks file size and decompressed ZIP size and rejects zip bombs, with per-format cell limits. (2) An inventory scans the ZIP parts and records vbaProject.bin, externalLinks, pivotCacheRecords, comments, threadedComments and persons, embeddings, customXml, connections, docProps and the data model. (3) calamine reads the visible worksheets. (4) Tables are detected and the header row found. (5) Columns are profiled and classified. (6) Operators run column-wise. (7) Markdown is rendered with a manifest.
- Column classifier: score = header prior (normalized, accent-stripped header matched against per-language synonym lists in each country pack: nom/prénom/date de naissance/NIR/IBAN; Vorname/Geburtsdatum; DNI/NIE...) plus value evidence on up to about 500 distinct non-null values: regex share, checksum pass share, gazetteer (first-name) share. Weak patterns such as phones and dates require header support.
- Use checksums for statistical confidence. Luhn accepts about 10% of random digit strings, but 50 sampled values all passing length plus Luhn is about 1e-50 likely by chance. Classify as soon as checksum hit rate is at least 0.6. Use hit rate, not presidio's share of results, and log the decision for each column in the manifest.
- Operators work on unique values: build each column's distinct set in polars, map value to token through the session map, then apply with one replace or join. Classify free-text columns (mean length above about 40 chars or above about 6 tokens, high cardinality) for per-cell regex and NER, on deduplicated cells in batches. Always run the cheap regex sweep over all unique strings of 'safe' columns too, as defense in depth.
- Tokens: use indexed placeholders such as [PERSONNE_12] and [CLIENT_ID_3] for LLM readability, with the type taken from the header for generic IDs so an order ID and a customer ID with the same value don't collide. If HMAC tokens are used, keep at least 64 bits: with 40 bits, 1M distinct values collide with probability around 0.45. Destroy the key and the map at the end of the session.
- Generalization operators, deterministic and cheap, for v1: date of birth to year or 5- or 10-year age band; postal code to département (rebuild leading zeros first: 1000 becomes 01000); exact amounts to ranges; categories rarer than k folded into 'Autre'. Optional k-report: min group size over the declared quasi-identifiers, from polars group_by. Warn when below 5.
- Hidden content policy: default to visible sheets, rows and columns only. Hidden and very-hidden sheets (from calamine metadata) and hidden rows and columns (xlsx: stream-parse <row hidden="1"> and <col hidden="1"> with defusedxml) are skipped and counted in the manifest, with an option include_hidden=true that anonymizes them like everything else. Never emit formulas, comments, properties, link paths or VBA in v1. Report their presence only.
- Excel normalization before validators: convert floats with integral value to integer strings without exponent; pad known fixed-width codes (postal code 5, SIREN 9, SIRET 14); treat 16-digit numeric values ending in 0 in 'card' columns as truncated PANs and redact them by header prior; respect the 1904 date system.
- Output: by default, one '## Sheet' section per table rendered as a Markdown table, with pipes and newlines escaped. Offer table_format=csv (fenced) for large tables (about 22% fewer tokens), and markdown-kv for small, accuracy-critical tables. Avoid JSON for bulk data (about 3.4x CSV). Configurable caps, e.g. max cells per request; above them return profile mode: schema, per-column type and PII class, null and distinct counts, generalized min/max, and N anonymized sample rows, with an explicit truncation notice.
- For huge-data analysis, recommend the 'schema + sample' pattern in the docs: the LLM receives the anonymized profile and writes code, and the code runs on-premise against the original. Throughput: process sheets in a worker pool with a per-process RSS limit, because calamine materializes whole sheets.
- Benchmark before committing, on our target CPU and with realistic French files (xls from public bodies, ods, cp1252 CSV): calamine vs fastexcel vs openpyxl read-only for time and peak RSS; classifier precision and recall on headerless and cryptic-header sheets.

### Risks
- Column misclassification leaks whole columns. Cryptic headers ('Col7', 'Contact', 'Réf'), headerless sheets or multi-row merged headers can hide names. Mitigations: regex sweep over all unique strings, first-name gazetteer hit rate on short-text columns, and conservative defaults (unknown short-text columns with high cardinality get NER).
- Quasi-identifiers survive pseudonymization. Rare combinations of birth date, postal code, sex, job title or salary can single someone out at the LLM provider. Pseudonymised data stays personal data (EDPB 01/2025). After SRB (C-413/23 P), whether data is personal for the recipient depends on its means of re-identification, and quasi-identifiers undermine that argument.
- Memory and DoS: calamine loads whole sheets. XLSX zip bombs, used ranges that reach row 1,048,576, and huge sharedStrings tables can exhaust RAM on CPU servers. Needed: limits on decompressed size and cells, a process RSS cap, and timeouts.
- XML attacks when parsing package parts in Python. openpyxl doesn't guard against billion-laughs attacks without defusedxml. Any custom scan for hidden rows or the inventory must use defusedxml or lxml with entity resolution disabled.
- Hidden rows and columns can't be detected in xls, xlsb and ods through calamine. They will be output, and anonymized, which could surprise users who expect hidden rows to be excluded.
- Formula cells written by libraries without a cached value read as empty, so data is silently lost. Formula text (not output in v1) can contain external paths such as C:\Users\<name>\..., and threaded-comment persons can contain AD SIDs or email addresses.
- Truncating huge sheets can make LLM aggregates wrong without anyone noticing. Always state truncation in the output and prefer profile mode.
- Dependency risk: anjana and pycanon pin exact numpy and pandas versions. ARX adds a JVM. ARXaaS and pyarxaas are dead. openpyxl releases are infrequent (last in 2024).
- Linkage across requests if the token map or HMAC key outlives the session. Keep the key ephemeral, and never derive tokens from an unkeyed hash, which a dictionary attack can reverse for names and phone numbers.
- If users save the anonymized output as CSV and open it in Excel, cells starting with =, +, -, @ or tab can run as formulas (OWASP CSV injection). Quote and prefix such cells in CSV output mode.

### Open questions
- Product decision: by default, should hidden sheets, rows and columns be excluded and reported (proposed), or included and anonymized? And should cell comments ever be output?
- Default caps: maximum cells and tokens per request, and the threshold for switching to profile mode. These depend on the target LLM context sizes and on hosting costs.
- Does fastexcel or calamine stop parsing early when n_rows is set? If so, profiling large sheets could be cheaper. Not verified.
- The source page says GPT-4.1-nano for the format benchmark; secondary coverage says GPT-4.1 mini. Format accuracy is model-dependent, so GDPR Guardian should run its own evaluation with its target LLMs.
- Should v2 write anonymized xlsx back out (openpyxl or rust_xlsxwriter), or stay Markdown-only as constraint 5 implies?
- Not verified because the web-search budget ran out: the defusedxml licence (believed PSF), and the exact licenses of ARX's bundled third-party jars.
- Should the session token map be shared across a multi-turn MCP session, so the same customer keeps the same token in later prompts, and with what TTL?

### Verifier notes
- The 40-bit HMAC collision figure is wrong. For 1M values the probability is about 0.37, not 0.45 (0.45 is the expected number of colliding pairs). The 64-bit recommendation still stands.
- Output is pseudonymised, not anonymised, from the user's (controller's) side. Tokens are consistent across the session and the map exists during it. The EDPB Guidelines 02/2026 (consultation until 30 Oct 2026) test three criteria: no isolation, no linkage, no inference. Per-row tokens that link records across sheets fail 'no linkage' for the controller. The guidelines rely on CJEU C-413/23 P EDPS v SRB (4 Sep 2025): data can be anonymous for a recipient such as the LLM provider without being anonymous for the controller. The docs should say 'pseudonymised' and frame the claim from the recipient's perspective. EDPB Guidelines 01/2025 on pseudonymisation are also relevant. The EDPB published a 'Guidelines at a Glance' summary in Oct 2026.
- The statement that calamine never reads VBA, properties or embedded objects is outdated for the Rust crate. It has vba_project(), the picture feature, defined names, hyperlinks (0.36.0) and workbook_properties() (0.37.0, 2026-10-18). Only the python-calamine 0.9.0 bindings lack them.
- python-calamine 0.9.0 bundles calamine 0.36.x, not 0.37.0. It therefore lacks these 0.37.0 fixes: a 1904-epoch flag reset by <x15:workbookPr> (dates shifted 1,462 days, which matters given the 'respect the 1904 date system' recommendation), XLS embedded-chart cells leaking into worksheet data, _xHHHH_ escapes in formula strings, and a CFB header allocation check (security). Pin carefully and watch for the next python-calamine release. Keep the per-process RSS limit, because earlier calamine releases fixed XLS and ODS out-of-memory issues.
- python-calamine 0.9.0 dropped Python 3.10 and pandas 3.1.0 also requires 3.11 or later, so GDPR Guardian's floor becomes 3.11. anjana 1.2.3 and pycanon 1.3.6 pin numpy==2.0.2. To my knowledge numpy 2.0.x has no CPython 3.13 or 3.14 wheels, which further limits them to an isolated test environment. Also, anjana 1.2.3 pins pycanon==1.3.5, not 1.3.6.
- The hidden-row policy only covers xlsx, but v1 also supports xls, xlsb and ods. For those formats calamine emits hidden rows and columns silently. Either parse visibility there too (ods table:visibility='collapse'/'filter', BIFF ROW/COLINFO flags, xlsb BrtRowHdr/BrtColInfo) or document that hidden rows and columns are included and anonymised for non-xlsx files.
- The xlsx hidden-row scan has edge cases. xsd:boolean allows hidden="true" as well as "1". <sheetFormatPr zeroHeight="1"> hides every row by default. A col can be hidden through width="0". Autofilter and outline-collapsed rows also carry hidden. Cells formatted ';;;' or with a white font look empty but are emitted.
- The ZIP inventory is missing several PII carriers: sheet and table names, which become '## Sheet' headings and must be anonymised; header and footer text (<headerFooter>); drawings with shapes and text boxes (xl/drawings); hyperlinks, including mailto: in sheet rels; defined names with constants; legacy shared-workbook revision logs (xl/revisions/*, userNames.xml); xl/richData for in-cell images; slicerCaches and timelines; queryTables and Power Query (DataMashup in customXml). xls is an OLE2/CFB file, not a ZIP: inventory it with olefile (SummaryInformation holds the author), and note that encrypted xlsx is also CFB.
- Postal code to département is not always the first two digits. Corsica's 20xxx codes map to 2A or 2B, DOM codes (971-976) and 98xxx use three digits, CEDEX codes exist, and some communes have a neighbouring département's postal code. Use the La Poste base (Licence Ouverte 2.0, file updated Sep 2026) to map code to INSEE commune and then to département.
- France checksums: SIRET uses Luhn except La Poste establishments (prefix 356000000, other than head office 35600000000048), where the digit sum must be a multiple of 5. NIR key = 97 - (first 13 digits mod 97), with 2A replaced by 19 and 2B by 18. Corsican NIRs are alphanumeric, so they never come back as floats. python-stdnum, the reference implementation, is LGPL-2.1+, so reimplement these checks rather than depend on it if dependencies must be MIT-compatible.
- Output format: Markdown table and JSON are statistically tied in accuracy (CIs 48.8-55.0 vs 49.2-55.4). All the data come from one small model (gpt-4.1-nano), one synthetic employee table and lookup questions. TOON (21,518 tokens, 47.5%) was benchmarked later and is worth a test. 'Clearly more accurate' is fair only against CSV.
- Document Inspector also only detects Excel Surveys, Scenario Manager scenarios and Filters. It cannot remove hidden rows or columns inside table headers or PivotTables.
- fastexcel 0.21.0 (MIT) is also built on calamine. It exposes sheet visibility, tables and defined names, and returns Arrow or polars directly with n_rows/use_columns/dtypes. That suits the per-column polars pipeline better than python-calamine's list of lists, so it should be a first-class candidate in the benchmark, not an afterthought. polars is now 2.0.0.
- Encrypted legacy xls files protected only with Excel's default 'VelvetSweatshop' password can be decrypted by msoffcrypto-tool without a user password. Consider this so read-only-protected public-body files are not rejected.
- defusedxml (PSF license, permissive) has not been released since 0.7.1 in March 2021. Recent Expat (2.4.1 and later, bundled with current CPython) mitigates billion laughs, and the stdlib does not fetch external entities, so stdlib iterparse plus size limits is an acceptable alternative.
